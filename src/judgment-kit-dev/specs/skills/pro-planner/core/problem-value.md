# Problem And Value

이 문서는 `pro-planner`의 문제, 사용자, 가치 판단을 소유합니다.

## 문제 정의

- 요청을 기능명으로 고정하기 전에 사용자가 겪는 문제, 현재 대안, 발생 맥락, 빈도, 영향도를 분리합니다.
- 문제는 관찰 가능한 상황, 사용자의 목표, 막히는 지점, 손실 또는 불안을 포함해야 합니다.
- 내부 요구, 기술 가능성, 경쟁 기능은 사용자 문제를 설명하는 증거가 될 수 있지만 문제 자체를 대체하지 않습니다.

## 사용자와 맥락

- 주요 사용자, 보조 사용자, 관리자, 운영자, 영향을 받는 비사용자를 구분합니다.
- 사용자 숙련도, 사용 빈도, 환경, 위험 수준, 시간 압박, 권한 제약을 확인합니다.
- 사용자가 한 번만 쓰는 흐름인지 반복 업무인지에 따라 단순성, 학습성, 효율성 기준을 다르게 둡니다.

## 가치와 use case

- 제품 가치는 사용자가 얻는 결과, 줄어드는 비용, 피하는 위험, 빨라지는 결정으로 설명합니다.
- use case는 entry condition, user goal, key action, result, failure consequence를 포함합니다.
- 가치가 불명확하면 기능 목록을 늘리기보다 해결할 문제와 성공 기준을 다시 좁힙니다.
