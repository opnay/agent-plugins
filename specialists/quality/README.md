# Quality

`quality`는 산출물의 목적·특성·위험에 맞는 검증 기준과 절차를 도출하고, 실제 근거로 판단하는 에이전트 행동 패턴입니다. 코드·화면·문서·계획·조사·데이터와 복합 결과물을 포함하며 분야 목록으로 범위를 제한하지 않습니다.

## 사용

핵심 스킬은 `$quality:verify` 하나입니다.

```text
$quality:verify 이 산출물의 목적·요구사항·제약을 확인하고,
필요한 품질 기준과 검증 절차를 도출해 허용된 검증을 수행해 주세요.
기준·근거·판정·미검증 범위와 남은 위험을 반환해 주세요.
```

검증 계획만 필요하면 계획만 요청합니다. 원본 요구·산출물 경로·대상 버전이나 상태·사용 맥락·허용 작업을 제공하면 더 정확한 검증에 도움이 됩니다. 입력 항목을 모두 채우는 고정 양식은 필요하지 않습니다.

스킬은 산출물 이해 → 검증 축 도출 → 기준·근거 설정 → 방법 선택 → 실제 검증 → 판정·재검증을 연결합니다. 매번 모든 분야를 감사하거나 고정 개수의 검사를 수행하지 않습니다.

## 결과 읽기

- `pass`: 확인한 범위와 기준을 충족한다는 충분한 근거가 있습니다.
- `fail`: 실제 기준 위반을 확인했습니다.
- `inconclusive`: 근거·기준·전문 지식이 부족하거나 충돌합니다.
- `not-run`: 검증을 실행하지 않았습니다. 이유와 영향을 함께 제시합니다.

결함·취향·개선 제안, 실제 관찰·추론, 대상 실패·환경 실패를 구분합니다. 중요한 검증이 빠지면 전체 통과로 표시하지 않습니다. 계획·설치·도구 호출이나 작성자의 성공 선언만으로 검증 완료를 판단하지 않습니다.

## 역할군·서브에이전트와 조합

역할 스킬은 필요한 전문 기준을 제공하고, `verify`는 현재 산출물에 적용할 방법을 설계·실행합니다. 특정 역할 플러그인이나 orcat·오케스트레이터는 필수 의존성이 아닙니다.

서브에이전트에 검증을 배정할 때는 대상 버전·원본 요구·목적·제약·허용 작업과 근거 반환 형식을 전달합니다. 작성자의 결론을 정답으로 주지 않습니다. 별도 에이전트 생성만으로 독립성이나 전문성이 보장되는 것은 아닙니다. 검증 과정은 수정·추가 위임·배포 권한을 만들지 않습니다.

## 검증과 역할의 경계

산출물을 직접 조사·실행·대조해 판정 근거를 만들 때는 `$quality:verify`를 사용합니다. 전문 역할·작업 관리·출시 승인은 해당 소유자가 담당합니다. 검증 결과만으로 수정·출시 권한을 얻지 않습니다.

이 플러그인은 전문 지식·도구·접근 권한을 설치하거나 검증 성공·인증·출시 승인을 보장하지 않습니다. 실제 필요한 근거가 없으면 미검증과 다음 확인 사항을 반환합니다.
