# advance-codex-dev v0.1.1 Change Spec

## 변경사항 요약

- disallowed temporary-folder guidance를 제거하고 session artifacts의 기본 위치를 `.agents/sessions/{YYYYMMDD}/`로 정렬한다.
- `.agents/sessions` 폴더의 목적과 `turn-gate` plan/flow record 골격은 호출 가능한 skill이 아니라 docs-only convention으로 유지한다.
- `session-manager` skill, controller, tests, record schema, metadata를 제거하고 `turn-gate`를 active session flow의 소유 표면으로 둔다.
- `workflow-kit` autopilot state guidance도 같은 date-scoped session folder convention으로 맞춘다.
- `subagent-gate` skill을 추가해 subagent 호출 전 종료 시점 계획과 subagent 관점의 최소 context packet을 잠근다.
- empirical test 결과를 반영해 `subagent-gate` handoff packet의 main-thread blocked state와 no-handoff routing note를 명시한다.
- 2차 empirical test 결과를 반영해 no-handoff routing note의 필드 모양을 reason, route, next action, blocked state, re-entry condition으로 고정한다.
- `subagent-gate`를 보존된 사용자 의도 기준으로 재생성해 sibling skill 이름에 기대지 않는 독립 handoff preparation skill로 정리한다.
- `subagent-work` skill을 추가해 reviewable work unit 동안 worker subagent를 spawn, operate, verify, summarize, close/dispose하는 엄격한 lifecycle을 제공한다.
- manifest prompt, README, plugin spec이 plugin 사용 기준을 소유하게 한다.
- `skill-scenario-testing`을 수정 루프가 아니라 분석 중심 empirical evaluation skill로 정리하고, 기본 8개 scenario set, N개 단위 batch dispatch, subagent 한도 시 executor close-and-continue를 추가한다.
- `skill-creator`에 passive skill `description` 끝 plain token 목록 규칙을 추가한다.
- passive skill인 `subagent-work`의 `description` 끝에 `#` 없는 쉼표 구분 plain token 목록을 추가한다.
- `pro-engineering` skill을 추가해 코드 작성과 문제 해결에서 엔지니어링 판단, 원인 분석, 구현 규율, 검증과 리스크 보고 기준을 제공한다.
- `pro-engineering` skill spec을 folder-based 구조로 전환해 사용자 의도, index, 세부 문제 해결 계약을 분리한다.
- `pro-engineering`에 직접 코딩 전에는 넓게 탐색하고 구현 단계에서는 좁게 집중하는 scope-control 계약을 추가한다.
- `optimize-token` skill을 추가해 응답을 간결하게 압축하되 정확성, 검증 상태, 승인 경계, 필수 출력 형식을 보존하는 기준을 제공한다.
- `optimize-token` skill spec을 folder-based 구조로 전환하고, 작업 전 thinking 문장 최적화 intent scenario를 추가한다.
- `optimize-token` runtime에 `references/thinking.md`를 추가해 작업 전 thinking과 진행 보고 문장도 간결하게 유지한다.
- 사용하지 않는 `tool-use-guide` skill과 spec을 제거하고 plugin usage surface에서 관련 노출을 정리한다.

## 사용자 스펙 의도

- 이 저장소의 플러그인들이 더 이상 disallowed temporary folder를 사용하거나 권장하지 않게 하고 싶다.
- `.agents/sessions` 폴더의 기본 규격을 `turn-gate`의 날짜 기반 `000-plan.md`와 `001-*` flow record 골격에 맞추고 싶다.
- 별도 session record schema와 controller를 제공하는 `session-manager`는 기본 session flow와 중복되므로 제거하고 싶다.
- `advance-codex`의 session folder guidance는 `turn-gate`를 대체하지 않고, 폴더 의미와 경계만 설명해야 한다.
- subagent를 준비할 때는 먼저 언제 돌아와야 하는지와 무엇을 넘겨야 하는지를 명확히 잠그고 싶다.
- manifest prompt, README, plugin spec에서 plugin 사용 기준을 분명히 하고 싶다.
- reviewable work unit 동안 worker subagent를 운영하고, 작업 단위가 끝나면 close/dispose해서 메인 에이전트의 context window를 줄이고 싶다.
- passive skill의 `description`은 실제 사용 여부를 결정하는 트리거 조건이므로, 본문을 읽기 전 token matching에 걸리도록 설명 끝에 `#` 없는 쉼표 구분 plain token 목록을 둘 수 있어야 한다.
- `subagent-work`는 사용자가 스킬 이름을 직접 말하지 않아도 worker subagent lifecycle 작업에서 선택되어야 하는 passive skill이다.
- 코드 작성과 문제 해결 과정에서 단순한 스타일 조언이 아니라 실제 증거, 원인 후보, 작은 완전 수정, 검증 기준을 중심으로 엔지니어링 판단을 적용하고 싶다.
- `pro-engineering` 스펙은 폴더화해 문제 해결, 엔지니어링 판단, 코드 작성 규율, 검증/보고의 상세 설명을 각각 분리하고 싶다.
- 자료조사, 구현 범위 조정, 문제 공간 파악처럼 직접 코딩 전 단계에서는 넓은 범위를 탐색하고, 실제 구현 단계에서는 코드를 좁은 범위로 집중해서 봐야 한다.
- 실제 작업 흐름에서 `tool-use-guide`가 선택되지 않았고, `advance-codex`의 핵심 사용 표면으로 유지할 필요가 낮으므로 제거하고 싶다.
- 실제 작업 흐름에서 `agents-sessions`도 거의 선택되지 않았고 `turn-gate`와 역할이 겹쳐 보이므로, runtime skill은 제거하고 session folder convention은 문서로만 남기고 싶다.
- 답변을 짧고 선명하게 다듬는 기준은 특정 외부 플러그인명이나 문체 명칭 없이 `advance-codex`의 `optimize-token` skill로 제공하고 싶다.
- `optimize-token`은 한국어 존대체만 특수하게 고정하기보다, 활성 언어와 말투를 보존하고 이 저장소처럼 한국어 존대체가 요구되는 환경에서는 그 기준을 따르게 하고 싶다.
- `optimize-token`은 단순히 "압축"이라고만 하지 않고, 압축 강도와 문법 보존 기준을 둬서 어색한 문장이 나오지 않게 하고 싶다.
- 20개 시나리오 평가 결과, 일반적인 "짧게" 요청이 과도하게 `dense`로 해석될 수 있어 `light` 기본값과 `dense` 조건을 더 상세히 잠그고 싶다.
- 답변이나 작업을 하기 앞서 생각하는 단계에서도 간결하게 생각하는 방식을 다루고 싶다.

## 변경 목적

`v0.1.1`은 session artifact 기능을 새 controller 중심으로 확장하는 release가 아니라, 기존 guidance를 `turn-gate` 중심의 session folder convention으로 정리하는 patch입니다.
기본 골격은 `.agents/sessions/{YYYYMMDD}/000-plan.md`와 `.agents/sessions/{YYYYMMDD}/{count-pad3}-{eng-lower-slug}.md`입니다.
`advance-codex`는 이 폴더의 목적과 경계를 설명하고, active turn continuity와 flow record 운영은 `loop-kit:turn-gate`가 소유합니다.

## 변경 상세

### Temporary Folder Guidance 제거

- `workflow-kit-dev`와 release `workflow-kit`의 `autopilot` state guidance를 date-scoped `.agents/sessions/{YYYYMMDD}/` 경로로 바꾼다.
- `advance-codex-dev`와 release `advance-codex`에서 legacy scratch-folder guidance를 제거한다.
- 검증 기준은 runtime plugin surfaces에서 disallowed temporary-folder guidance가 남지 않는 것이다.

### `agents-sessions` 문서 축소

- `agents-sessions` runtime skill, agent metadata, skill spec을 제거한다.
- manifest prompt와 plugin spec의 callable skill 목록에서 `agents-sessions`를 제거한다.
- plugin spec과 README에는 `.agents/sessions/{YYYYMMDD}`가 session-scoped operational artifact 위치라는 문서 수준의 참고만 남긴다.

### `session-manager` 제거

- `session-manager` skill, spec, controller, tests, agent metadata, record format reference를 제거한다.
- `session-manager`의 legacy scratch-folder guidance를 제거한다.

### Cross-Plugin Alignment

- `workflow-kit-dev`와 release `workflow-kit`의 `autopilot` skill/spec이 `.agents/sessions/{YYYYMMDD}/` convention을 사용하도록 맞춘다.
- 이 동반 변경은 `advance-codex`의 session folder convention이 `workflow-kit` guidance와 충돌하지 않게 하기 위한 범위다.

### `subagent-gate` 추가

- `subagent-gate` skill을 추가해 subagent 호출 전 handoff gate를 소유하게 한다.
- 종료 시점 계획, stop boundary, output contract, edit permission, close plan을 먼저 작성하도록 한다.
- main-thread blocked state를 handoff packet의 명시 필드로 둔다.
- `subagent-gate` 경계 밖의 요청은 handoff로 억지 변환하지 않고 no-handoff routing note로 돌려보낸다.
- no-handoff routing note에는 reason, right skill or workflow, main-thread next action, main-thread blocked state, re-entry condition을 둔다.
- no-handoff 상태에서는 아직 없는 subagent ownership이나 pass/fail criteria를 억지로 채우지 않는다.
- main agent의 전체 맥락이 아니라 subagent 시점에서 필요한 user goal, verified facts, assigned files, constraints, pass/fail criteria, forbidden actions만 context packet으로 정리하게 한다.
- `subagent-creator`는 custom agent definition을 계속 소유하고, `subagent-gate`는 runtime handoff 준비를 소유한다.
- 보존된 사용자 의도 기준으로 `subagent-gate` spec/runtime을 재작성하고, runtime은 sibling skill 이름이나 숨은 plugin routing table에 의존하지 않는다.

### `subagent-work` 추가

- `subagent-work` skill을 추가해 하나의 reviewable work unit을 worker subagent에게 맡기는 lifecycle을 소유하게 한다.
- 메인 thread는 사용자 대화, 범위 결정, 승인 경계, 통합 판단을 맡고, worker는 준비된 작업 단위의 구현과 1차 검증을 맡는다.
- worker는 작업 단위가 reviewable 상태가 되면 close/dispose하고, 다음 work unit은 compact handoff summary와 새 worker로 시작한다.
- runtime은 독립 완결형으로 기본 worker packet, sync, escalation, close/dispose 기준을 제공한다.

### `skill-scenario-testing` 운영 보강

- `skill-scenario-testing`은 target instruction을 직접 수정하거나 patch를 적용하지 않고, fresh executor evidence 기반 분석과 보고를 소유한다.
- 기본 empirical evaluation은 8개 scenario set을 기준으로 한다.
- smoke check는 2-3개 scenario로 축소할 수 있고, 사용자가 더 큰 scenario 수를 요청하면 N개 단위 batch로 나눠 dispatch한다.
- subagent 한도에 걸리면 완료됐거나 더 이상 쓰지 않는 executor를 닫고 다음 batch를 이어간다.

### Plugin-Level Routing 정리

- plugin usage guidance는 manifest prompt, README, plugin spec에 둔다.
- creator skill의 plugin packaging guidance는 manifest prompt, README, plugin spec 기준으로 정리한다.

### `tool-use-guide` 제거

- `tool-use-guide` runtime skill과 skill spec을 제거한다.
- manifest prompt, README, plugin spec에서 `tool-use-guide` 직접 노출을 제거한다.
- `skill-creator`에는 tool policy가 skill boundary를 흐리지 않게 하라는 일반 기준만 남기고, 제거된 sibling skill로 라우팅하지 않는다.

### `skill-creator` Description Trigger Metadata

- `skill-creator`는 skill frontmatter `description`을 body를 읽기 전 trigger metadata로 다루도록 안내한다.
- passive skill은 사용자가 명시적으로 skill을 요청하지 않아도 선택되어야 하므로, `description` 끝에 token matching을 돕는 plain token 목록을 쉼표로 나열한다.
- token 목록은 literal hashtag가 아니므로 `#`를 붙이지 않는다.
- active/direct-call skill이나 이미 충분히 좁은 trigger를 가진 skill에는 불필요한 token 목록을 강제하지 않는다.

### `subagent-work` Passive Trigger Tokens

- `subagent-work`는 passive skill로 취급한다.
- dev/release `subagent-work` runtime `description` 끝에 worker subagent lifecycle 관련 plain token 목록을 쉼표로 나열한다.
- token 목록에는 literal `#`를 붙이지 않는다.
- 이 변경은 `subagent-work`의 worker lifecycle behavior를 바꾸지 않고 selection metadata만 보강한다.

### `pro-engineering` 추가

- `pro-engineering` skill을 추가해 코드 작성, 버그 수정, 리팩터링, 설계 판단에서 문제 해결 중심의 engineering judgment를 제공한다.
- skill의 핵심 루프는 증상과 기대 동작 분리, 실제 증거 수집, 원인 후보 나열, 가설 검증, 작은 완전 수정, 검증 가능한 결과, residual risk 보고다.
- 이 skill은 특정 언어/프레임워크 레시피, 도구 사용 정책, 커밋 절차, subagent lifecycle을 소유하지 않는다.
- passive skill로 선택될 수 있도록 runtime `description` 끝에 `#` 없는 쉼표 구분 plain token 목록을 둔다.
- spec은 `specs/skills/pro-engineering/intent.md`, `spec.md`, `core/*.md`로 나누어 사용자 의도, index, 세부 계약을 분리한다.
- `core/problem-solving.md`는 증상과 기대 동작 분리, 증거 수집, 원인 후보, 가설 검증, 수정 진입 기준을 소유한다.
- `core/scope-control.md`는 조사/범위 설정 단계의 넓은 탐색과 구현 단계의 좁은 집중 사이 전환 기준을 소유한다.
- `core/engineering-judgment.md`는 기존 패턴 우선, 추상화 판단, 명시적 계약, 리스크 배수, 사용자 입력 필요 조건을 소유한다.
- `core/code-discipline.md`는 작은 완전 변경, 단순 구현 후 개선, 변경 범위, 코드 품질, 금지되는 작성 방식을 소유한다.
- `core/verification-reporting.md`는 검증 선택, 실패 처리, 완료 판정, 보고 형식을 소유한다.

### `optimize-token` 추가

- `optimize-token` skill을 추가해 응답 표면의 토큰 낭비를 줄이는 기준을 제공한다.
- 이 skill은 context/session compaction, prompt rewriting, 코드 축약, 안전 고지 축소를 소유하지 않는다.
- 상세 응답 기준은 runtime reference인 `skills/optimize-token/references/response.md`가 소유한다.
- 응답 압축 중에도 활성 언어, 말투, 저장소별 출력 기대사항을 유지한다.
- 기본 압축 강도는 `light`로 두고, 일반적인 "짧게/간결하게" 요청은 먼저 `light`로 처리한다. 필요할 때 `standard`, `dense`로 올리되 `dense`는 라벨/상태/한 줄/최대 압축처럼 출력 형태가 분명할 때만 사용한다.
- runtime text에는 특정 외부 플러그인명, 캐릭터 프레이밍, novelty style label을 남기지 않는다.
- manifest prompt, README, plugin spec은 `optimize-token`의 역할을 언급한다.
- `optimize-token` skill spec은 folder-based 구조를 사용하고, `intent-scenarios/thinking.md`는 작업 전 thinking 문장 최적화 예시를 소유한다.
- `optimize-token` runtime은 `references/thinking.md`와 `references/response.md`를 함께 사용해 작업 전 판단과 최종 응답 표면을 각각 최적화한다.

## 비목표

- `turn-gate` flow record 생성/갱신 규칙을 `advance-codex` 문서나 다른 sibling skill에 복제하거나 재정의하지 않는다.
- custom agent TOML 정의 규칙을 `subagent-gate`에 흡수하지 않는다.
- worker lifecycle 운영을 일반 프로젝트 실행 workflow 전체로 넓히지 않는다.
- 제거된 `tool-use-guide` 책임을 다른 sibling skill에 그대로 흡수하지 않는다.
- `pro-engineering`을 특정 언어/프레임워크 구현 레시피나 프로젝트별 코딩 컨벤션 대체물로 만들지 않는다.
- `optimize-token`을 일반 context compression, session record 요약, prompt rewriting, 코드 minification 도구로 만들지 않는다.
- `optimize-token` thinking scenario를 내부 추론 공개나 장황한 방법 설명으로 만들지 않는다.
- 별도 `session_record.md`, `change_record.md`, `retrospective_record.md` schema를 유지하지 않는다.
- `.agents/sessions`를 plugin source, release surface, reusable spec의 대체 위치로 만들지 않는다.
- `workflow-kit`의 autopilot loop 자체를 재설계하지 않는다.
- 독립 실행 표면의 이름이나 책임을 바꾸지 않는다.

## 호환성 및 마이그레이션

- `session-manager`를 사용하던 호출자는 더 이상 이 plugin에서 해당 skill이나 controller를 찾을 수 없다.
- active turn continuity와 flow 기록은 `loop-kit:turn-gate`를 사용한다.
- `.agents/sessions`의 폴더 의미는 `advance-codex` README와 plugin spec의 문서 참고를 따른다.
- autopilot state/resume artifacts는 date-scoped `.agents/sessions/{YYYYMMDD}/` 아래에 둔다.
- 사용자는 필요한 구체 skill을 직접 호출한다.

## 검증 기준
