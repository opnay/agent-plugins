# Design Kit Dev

공통 디자인 지식을 바탕으로 프로젝트에 맞는 경험과 시각 표현을 설계하고, 디자인 방향과 재사용 가능한 규칙을 유지하는 플러그인입니다.

## 시작점

| Skill | 사용할 때 | 주요 결과 |
| --- | --- | --- |
| `design-base` | 디자인 원리와 적용 근거가 필요할 때 | 색채·시지각·타이포·공간·상호작용·반복 판단 |
| `web-designer` | 페이지 전달·탐색·반응형 구성이 중심일 때 | 페이지 구조와 웹 표현 규칙 |
| `product-designer` | 과업·흐름·조작·상태가 중심일 때 | 사용자 흐름, 인터랙션, 상태·회복 설계 |
| `visual-content-designer` | 배너·카드뉴스·에디토리얼·소셜 콘텐츠를 다룰 때 | 메시지·이미지·텍스트 구성과 매체별 변형 |
| `art-director` | 시각 콘셉트와 표현 언어를 정할 때 | 이미지·타이포·색·구도·표면의 방향 |
| `creative-director` | 핵심 메시지·아이디어·접점의 연결을 정할 때 | creative brief와 매체 간 전개 원칙 |
| `project-design-rules` | 프로젝트 규칙을 찾거나 정리·기록·갱신할 때 | 디자인 방향·베이스·패턴의 지속 기록 |

기반·전문 설계·디렉션은 판단 범위입니다. 모든 작업이 전체 역할을 순서대로 거치지는 않습니다. 디렉션은 작업 초반부터 사용할 수 있고, 작은 수정에는 관련 역할만 적용합니다.

웹으로 구현된 제품도 과업·상태가 핵심이면 `product-designer`를 선택합니다. UI 라벨·오류 문구는 web/product가 다루며, `visual-content-designer`는 시각 콘텐츠를 다룹니다. creative는 전달할 메시지와 아이디어, art는 이를 구현할 시각 언어를 소유합니다.

## 호출 예시

- `$design-kit-dev:design-base 이 팔레트의 보색 관계와 실제 텍스트 대비를 구분해서 검토해줘.`
- `$design-kit-dev:web-designer 이 소개 페이지의 읽기 순서와 모바일 구성을 설계해줘.`
- `$design-kit-dev:product-designer 저장 실패와 재시도를 포함해 편집 흐름을 검토해줘.`
- `$design-kit-dev:visual-content-designer 카드뉴스의 시리즈 반복과 단독 공유 구성을 잡아줘.`
- `$design-kit-dev:art-director 현재 브랜드를 바탕으로 이미지와 타이포의 시각 언어를 정해줘.`
- `$design-kit-dev:creative-director 출시 메시지와 사이트·소셜 콘텐츠의 연결 아이디어를 정해줘.`
- `$design-kit-dev:project-design-rules 이번에 확정한 색상·목록·상세 패턴을 이 프로젝트의 기존 디자인 문서에 기록해줘.`

## 공통 지식과 프로젝트 규칙

공통 이론은 `$design-kit-dev:design-base/references/`에서 관리합니다. 각 역할은 필요한 reference를 직접 읽으며 다른 skill의 선행 실행을 요구하지 않습니다. 프로젝트 탐색·기록 계약은 `$design-kit-dev:project-design-rules/references/project-context.md`가 소유합니다.

반복은 같은 맥락에서 용어·색·형태·배치·상호작용의 의미를 유지하고, 시각적 연결·리듬과 강조·기억을 만드는 기준입니다. 반복 노출은 맥락에 따라 생략·재제공·강조·변주할 수 있습니다.

실제 프로젝트의 결정값은 해당 프로젝트에 둡니다. 기존 디자인 문서를 우선하고, 기록이 요청 범위이며 소유 위치가 없을 때 `docs/design.md`를 사용합니다. 방향·베이스·패턴을 구분하고, 규칙의 적용 범위·이유·예외·사례·근거와 candidate/adopted/deprecated 상태를 남깁니다. 단일 화면의 관찰을 전역 규칙으로 자동 승격하지 않습니다.

## 범위

이 플러그인은 디자인 판단과 산출물, 프로젝트 규칙 관리를 다룹니다. 제품 범위·사업 정책의 최종 결정, 일반 구현 절차, 출시 승인·게시·배포를 소유하지 않습니다. 시각·브라우저·편집 도구는 작업 환경에서 사용 가능한 도구를 따릅니다.
