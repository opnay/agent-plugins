# quality v0.1.0 Change Spec

## 변경사항 요약

- `agent/quality`에 단일 `verify` 스킬과 두 호스트 manifest를 제공합니다.
- 산출물의 목적·특성·위험에 맞는 기준·방법·실제 근거·판정을 연결합니다.
- 두 marketplace에 기존 순서를 보존해 등록하고 역할군·직접 실행·위임의 사용 안내를 제공합니다.

## 변경 상세

- 목적: 분야를 닫지 않는 공통 산출물 검증 행동 패턴을 제공합니다.
- 범위: runtime·manifest·사용/개발 README·root 안내·등록·검증 계획.
- 입력·출력·권한·종료 계약은 [verify spec](../skills/verify/spec.md)이 소유하며 plugin 경계는 [plugin spec](../plugin.md)이 소유합니다.

## 비목표

- 기존 `pro-quality-manager` 제거·대체, 역할군 재편, 사용자 설치·설정 변경, commit·push·배포.

## 호환성과 마이그레이션

새 호출은 `$quality:verify`입니다. 기존 플러그인과 호출은 유지하며 자동 migration은 없습니다. 특정 역할 plugin·orcat·오케스트레이터를 필수로 설치하지 않습니다.

## 검증 기준

skill 형식·spec/runtime 정합성·실제 리소스·공통 metadata·marketplace 이름/순서/경로·문서 링크·diff 공백을 확인합니다. 실제 native 로딩과 사용/미사용 비교는 [검증 계획](../validation-plan.md)을 따르며 환경 제약과 미실행을 구분합니다.

실제 실행 관찰과 한계는 [검증 결과](../validation-results.md)에 기록했습니다.
