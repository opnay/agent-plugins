# jev-use 스킬 스펙

## 목적

작업 중 작은 선택과 질문 필요성을 Jev로 신속히 평가합니다. 불확실한 근거는 넓은 판단과 구체 주장 검사를 조합하고, 범위가 불명확한 작업은 기본 범위·조사량·실행량을 확인한 뒤 허용된 subagent 모델과 reasoning effort를 선택합니다.

## 경계

- 포함: Jev 호출 가치 판단, 판정 문맥·선택지 구성, 사용자 질문 처리, 불확실한 근거의 다각도 평가, 작업 범위·조사·실행 노동력 평가, 직접 수행·위임 선택, 허용된 모델·effort 라우팅, 결과 사용과 실패 시 진행.
- 제외: Jev CLI 사양·설치·설정 소유, 임의의 전체 코드 검토, 모든 간단한 질문의 자동 전송, 사용자 취향·승인·권한의 대리 결정, 고정된 모델 목록이나 비용 정책, subagent 실행 권한 생성, scenario-testing verdict.

## 처리하려는 작업 형태

- 사용자가 묻거나 에이전트가 작업 중 만난 제한된 선택에 복수의 합리적 후보가 있고, 짧은 허용 문맥으로 평가할 수 있다.
- 출처를 확인한 근거가 있지만 그 관련성, 주장 지지 여부, 빠진 전제 또는 반례가 불확실하여 여러 제한된 판단이 실제 다음 조사·행동을 바꿀 수 있다.
- 작업 범위가 미정이지만 현재 요청·저장소·환경에서 기본 범위와 필요한 조사·실행량을 확인할 수 있으며, 직접 수행과 위임 또는 위임할 모델·effort의 선택이 실제 행동에 영향을 준다.
- 명시적 `$jev:jev-use` 호출뿐 아니라 위 조건에 맞는 일반 작업에도 적용한다. 결정적 규칙이나 충분한 기존 증거가 답을 정하면 Jev를 호출하지 않는다.

## 엔트리포인트 / 대표 표면

- `jev/skills/jev-use/SKILL.md`, `$jev:jev-use`.
- TypeSafe 호출은 설치된 `jev` CLI의 Noul·Choice·Score를 사용한다. 자세한 명령·출력·설정 정보는 `$jev:jev`가 소유하지만, runtime은 필요한 명령과 실패 해석을 자체 설명한다.

## 핵심 처리 계약

1. 요청 목적, 사용자 조건, 현재 규칙, 확인 가능한 증거, 허용된 도구·모델을 먼저 확인한다. 빠른 국소 조사로 해결할 수 있는 불확실성을 Jev에 추정시키지 않는다.
2. 판단이 제한된 이산 선택이면 `jev choice`, 예/아니오 명제면 `jev noul`, 순서형 정도면 `jev score`를 씁니다. 여러 독립 질문이 정확히 같은 state를 공유할 때만 `jev batch`를 씁니다. 판정에 필요한 사실·기준·후보와 `inspect_more`·`ask_user` 같은 유효한 복구 선택지를 포함합니다.
3. 근거가 불확실하면 확인된 출처·발췌·주장·알려진 공백을 최소 공통 state로 구성합니다. 서로 다른 넓은 질문들로 전체 관련성·주장과 근거의 관계·대안 해석을 보고, 좁은 질문들로 결정적인 하위 주장·반증·누락된 전제를 각각 확인합니다. 각 질문은 독립적이고 답이 행동에 영향을 주어야 합니다. 같은 state에서 독립적으로 평가할 수 있으면 폭넓은 질문과 좁은 질문을 한 batch에 섞습니다. 앞선 답이 후속 질문을 결정하거나 근거별 state가 다르면 별도 호출로 처리합니다.
4. 질문 수를 임의의 작은 고정값으로 제한하지 않습니다. 여러 관련 주장과 반례를 한 요청에 담을 수 있지만, 현재 API의 요청·문맥 한도와 전송 비용 안에서 필요한 만큼만 묻습니다. 표현만 바꾼 반복 질문의 다수결을 신뢰도 증거로 쓰지 않습니다. `not_shown`·`insufficient` 같은 선택지로 근거 부재와 반증을 구분하고, 답 사이에 충돌이 있으면 원문을 다시 조사합니다. Jev 결과는 근거의 최종 판정이 아닙니다.
5. 사용자 질문은 제공된 목적과 제약으로 답할 수 있는 작은 선택일 때 Jev를 보조 판단으로 사용합니다. 에이전트가 사용자에게 질문하려는 경우에는 현재 정보로 진행·추가 조사·사용자 질문 중 무엇이 필요한지 평가할 수 있습니다. 사용자만 아는 취향이나 승인·권한을 Jev가 채워 넣지 않습니다.
6. 범위 미정 작업은 먼저 최소 작업 범위, 추가 조사량, 실행 노동력, 병렬성, 실패 영향, 권한 경계를 간결히 정리합니다. Jev로 직접 수행·위임·추가 조사·사용자 확인 중 하나를 고릅니다. 위임이 적절하고 허용되면 사용 가능한 모델 목록에서 모델을 고르고, 선택한 모델이 지원하는 reasoning effort를 별도 질문으로 고릅니다. 사용자가 제한한 모델 계열·effort와 저장소 기본값을 후보 구성에 반영합니다. 모델·effort 선택은 해당 작업의 권고이며 영구 설정이 아닙니다.
7. 질문·문맥·선택지·수준은 TypeSafe 외부 API로 전송됩니다. 사용자와 환경이 허용한 최소 정보만 보냅니다. 비밀, 미허용 파일 내용, 필요 없는 원문은 보내지 않습니다. Jev의 답·확률·confidence는 근거·권한·사용자 의사 또는 품질 증명이 아닙니다. 선택된 행동이 현재 지시·증거·도구 계약에 맞는지 확인한 뒤 실행합니다.
8. Jev CLI 부재, 인증·API 실패, 결과 기준 미달(exit 2), 부적합한 답에서는 설치·설정 변경이나 기준 완화·동일 호출 반복을 자동으로 하지 않습니다. 확인된 기본값과 자체 판단으로 계속할 수 있으면 진행하고, 사용자 결정이 필요하면 묻습니다. 실제 Jev 사용 여부와 실패·대체 판단은 결과에 구분해 보고합니다.

## 대표 유즈케이스

- 사용자의 A/B 질문: 제공된 목표·제약으로 `option_a`, `option_b`, `need_user_input` 중 선택해 짧은 추천을 만든다.
- 사용자에게 되묻기 전: `proceed_with_known_default`, `inspect_more`, `ask_user` 중 선택해 불필요한 질문을 줄인다.
- 근거가 불확실한 완료 주장: 공통 근거에 전체 지지 여부와 개별 검증·배포·사용 가능성 주장을 함께 묻고, 답이 갈리면 원문과 실제 실행 결과를 조사합니다.
- 범위 미정 작업: 최소 범위·조사량·실행량을 확인한 뒤 `direct`, `delegate`, `inspect_more`, `ask_user`를 평가하고, 위임 시 허용 모델과 effort를 순서대로 선택한다.
- 동일 문맥의 독립 소판단: 공통 state를 보존한 batch로 평가한다. 서로 다른 state를 호출 수 감소만을 위해 합치지 않는다.

## 검토 질문

- Jev 호출이 현재 결정에 실질적인 도움을 주는가? 결정적 규칙·기존 증거·사용자 취향을 외부 판정으로 대체하지 않았는가?
- 전송 문맥은 충분하면서도 허용된 최소 범위인가? 선택지에 실제 복구 행동이 포함되는가?
- 넓은 질문과 좁은 질문이 서로 다른 판단을 담당하고, 공통 state·독립성·현재 요청 한도에 맞는가? 누락된 근거와 반증을 구분하고 답의 충돌을 조사했는가?
- 범위·조사량·실행량을 먼저 확인하고, 위임 여부·모델·effort를 허용 후보에서 선택했는가?
- Jev 결과를 권고로 취급하고 실행 권한·결과 검증·실패 대체 경로를 별도로 처리했는가?

## 독립성 원칙

- 독립 실행 가능성을 강제한다. runtime 본문만으로 사용 시점, 단건 CLI 호출, 모델·effort 라우팅, 실패 처리를 수행할 수 있어야 한다.
- `$jev:jev`는 상세 CLI 안내를 위한 선택적 sibling이며 숨은 필수 문맥이 아니다. `scenario-testing`의 평가·verdict 계약을 가져오지 않는다.

## 확장 원칙

- 반복되는 업무별 예시는 runtime reference로 분리할 수 있지만, 이 스킬은 Jev로 제한된 작업 판단을 실제 행동에 연결하는 공통 계약만 소유한다.
- 모델·effort 이름과 비용·성능 가정은 시점과 환경에 따라 확인한다. 특정 계열을 영구 기본값으로 내장하지 않는다.
