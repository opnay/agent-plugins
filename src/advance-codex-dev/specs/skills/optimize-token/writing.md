# Writing Axis

## 소유

`writing`은 에이전트 토큰 최적화 중 파일, 문서, spec, README, release note, handoff record처럼 저장되는 작성물에 필요한 추가 보존 계약만 소유합니다.
저장되지 않는 상황에는 별도 축을 만들지 않고 `levels/`를 바로 적용합니다.
저장되는 작성물은 전역 `levels/`의 기본 적용 대상이 아니라 이 파일 기준으로 별도 관리합니다.

## 보존

- 현재 상태만 기록합니다. 이전 방향, 폐기된 결정, 작업 중 임시 맥락을 결과물에 남기지 않습니다.
- 지속 계약, 사용자 의도, 승인 경계, 검증 상태, 남은 위험을 필요한 위치에 보존합니다.
- 저장 후 다시 읽는 사람의 판단이나 실행이 달라질 수 있는 의미 맥락을 보존합니다.
- 실행 순서, 의존성, 적용 조건, 제외 범위, rollback 조건, source of truth, evidence 출처, 확인/미확인 범위는 저장물의 실행 가능성을 좌우하면 줄이지 않습니다.
- 경로, 명령어, 식별자, 날짜, 버전, 수치, public API 이름은 임의로 줄이지 않습니다.
- 저장 후 다시 읽는 사람이 실행할 수 있어야 하므로, 지시 대상과 적용 조건을 명확히 둡니다.

## 축소

- 작성 과정 설명, 이전 설계와의 비교, 대화 중 폐기된 후보
- 결과물 사용에 필요 없는 배경
- 같은 계약을 여러 파일에 반복하는 문장

## 실패

- 현재 결과물에 이전 맥락이 섞임
- 저장된 문서만 보고 실행할 수 없음
- 검증 실패, 미실행, 승인 경계가 삭제됨
- 짧아졌지만 계약 범위가 더 넓거나 좁게 오해됨
- 순서, 의존성, source of truth, 확인 범위가 사라져 실행 또는 판단이 달라짐
