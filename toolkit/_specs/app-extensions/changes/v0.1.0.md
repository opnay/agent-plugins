# app-extensions-dev v0.1.0 Change Spec

## 변경사항 요약

- 외부 app plugin에 delta guidance를 제공하는 `app-extensions-dev`를 정의합니다.
- 첫 skill로 `figma-ext`의 target, coordinates, viewport, layout translation 계약을 제공합니다.
- 초기 surface를 skills-only companion plugin으로 제한합니다.
- repository marketplace에 `app-extensions`를 등록하고 local Codex에 설치합니다.

## 변경 목적

Figma처럼 이미 capability와 tool-use contract를 제공하는 외부 plugin을 복제하지 않고, 사용자·팀이 지속적으로 적용할 추가 판단과 workflow 규칙을 독립 plugin에서 관리합니다.

## 릴리즈 노트 기준

- 독자에게 보이는 변화: `$app-extensions:figma-ext`로 Figma layout과 handoff 작업에 추가 구조·좌표·responsive·implementation 기준을 적용할 수 있습니다.
- 호환성 영향: 기존 plugin과 skill 호출에는 영향이 없습니다.
- migration 필요 여부: 신규 plugin이므로 없습니다.
- 운영자/사용자가 알아야 할 검증 결과: skills-only plugin이며 외부 app connection이나 MCP server를 번들하지 않습니다. local install 후 새 thread에서 skill을 불러와야 합니다.

## 기록 근거

- 관련 커밋: 미정
- 관련 세션 기록: 현재 사용자 요청

## 변경 상세

### App Extensions Plugin 경계

- 목적: 외부 app capability에 대한 로컬 extension guidance를 upstream plugin과 분리합니다.
- 범위: manifest, README, plugin spec.
- 관련 표면: `src/app-extensions-dev/`.
- 검증: manifest와 usage surface가 companion·delta-only 경계를 설명하고 실제 `figma-ext`만 노출해야 합니다.

### Figma Extension Skill

- 목적: Figma target, hierarchy, coordinates, viewport와 code layout translation을 일관되게 해석합니다.
- 범위: `figma-ext` spec과 runtime `SKILL.md`.
- 관련 표면: `src/app-extensions-dev/specs/skills/figma-ext.md`, `src/app-extensions-dev/skills/figma-ext/`.
- 검증: runtime이 target-first, absolute·relative coordinates, viewport·responsive, flow-first와 position priority를 포함해야 합니다.

### Skills-Only Packaging

- 목적: upstream app plugin이 소유하는 connection과 tool definition을 중복하지 않습니다.
- 범위: plugin manifest와 release build.
- 관련 표면: `.codex-plugin/plugin.json`, generated release root.
- 검증: `apps`, `mcpServers`, `.app.json`, `.mcp.json`, hooks, scripts가 없어야 합니다.

### Marketplace 및 Local Install

- 목적: generated release plugin을 repository marketplace에서 발견하고 Codex가 local cache에 설치하도록 합니다.
- 범위: `.agents/plugins/marketplace.json`, configured `opnay-plugins` marketplace, local plugin cache.
- 관련 표면: `./app-extensions`, repository marketplace, Codex plugin install state.
- 검증: marketplace entry의 path·policy·category와 installed·enabled 상태를 확인하고 새 thread pickup 필요성을 보고해야 합니다.

## 비목표

- upstream Figma plugin이나 manifest를 수정·상속·병합하지 않습니다.
- Figma connection, 인증, MCP tool, UI를 새로 제공하지 않습니다.
- generic design judgment나 frontend implementation workflow를 흡수하지 않습니다.
- 기존 marketplace 항목을 재정렬하지 않습니다.

## 호환성 및 마이그레이션

- 신규 plugin이므로 기존 호출자 migration은 없습니다.
- dev manifest는 `app-extensions-dev`, build output manifest는 `app-extensions` 이름을 사용합니다.
- upstream Figma capability가 없으면 `figma-ext`는 mutation을 수행하지 않고 unavailable 상태를 보고합니다.

## 검증 기준

- dev와 release `figma-ext`가 canonical `quick_validate.py`를 통과해야 합니다.
- `pnpm build:plugin app-extensions --force`가 통과해야 합니다.
- dev와 release manifest JSON이 파싱되고 name 변환과 version `0.1.0`이 일치해야 합니다.
- dev와 release runtime skill이 동일해야 합니다.
- release root에 `specs/`와 `changes/`가 없어야 합니다.
- dev와 release에 `.app.json`, `.mcp.json`, hooks, scripts가 없어야 합니다.
- manifest, README, plugin spec이 실제 `figma-ext` surface만 노출해야 합니다.
- runtime은 dev-only spec path나 upstream tool schema를 실행 지시로 포함하지 않아야 합니다.
- repository marketplace는 기존 순서를 유지한 채 마지막에 `app-extensions`를 등록하고 `source.path=./app-extensions`, `AVAILABLE`, `ON_INSTALL`, `Developer Tools`를 사용해야 합니다.
- `opnay-plugins` marketplace가 Codex에 configured 상태여야 합니다.
- `app-extensions@opnay-plugins`가 installed·enabled 상태여야 합니다.
- 설치 후 새 thread에서 `$app-extensions:figma-ext` pickup이 필요함을 보고해야 합니다.
- `git diff --check`가 통과해야 합니다.

## 정식 규칙 승격 여부

- normative spec 또는 runtime 문서로 승격할 지속 규칙: companion·delta-only plugin 경계와 `figma-ext` 처리 계약
- change spec에만 남길 release/migration 이력: 신규 `0.1.0` 생성과 초기 skills-only surface
