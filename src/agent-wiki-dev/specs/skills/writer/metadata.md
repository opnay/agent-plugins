# 문서 속성과 태그

## 역할과 적용 범위

- writer는 일반 지식 문서와 프로젝트 작업 기록을 작성·갱신할 때 문서 맨 위의 YAML frontmatter에 `type`과 `tags`를 관리합니다. `index.md`는 하향 탐색을 소유하며 이 속성의 필수 대상은 아닙니다. 첨부 파일은 대상이 아닙니다.
- `type`은 문서의 주된 성격, `tags`는 함께 찾을 주제·기술 키워드, 폴더는 소유 위치, 본문 링크는 개념·근거·판단 관계를 담당합니다. 메타데이터와 본문의 역할은 구분합니다.
- 현재 승인된 작성·갱신 문서에 적용합니다. 전체 위키 정규화·기존 문서 일괄 태깅·이동·설정 변경은 별도 작업입니다. 정확한 본문 범위·원문 보존·읽기 전용 지시를 우선하고 허용된 본문 작업은 독립적으로 수행합니다.

## type

- `type`은 비어 있지 않은 문자열 하나입니다. 본문 목적을 확인해 가장 적합한 유형 하나를 선택하고 같은 의미의 기존 값을 재사용합니다.
- 예시: `reference`는 설명·참고, `comparison`은 후보 비교, `design`은 설계, `record`는 작업 조건·결과 기록, `diagnosis`는 원인 진단, `benchmark`는 성능 측정, `guide`는 실행 안내입니다. 예시는 폐쇄된 enum이 아니며 필요한 새 유형은 기존 어휘와 중복을 확인하고 정합니다.
- 문서 유형은 작업의 성공·완료 상태나 근거 수준을 뜻하지 않습니다. 프로젝트 기록 경로에 있다는 이유만으로 모든 문서를 같은 유형으로 만들지 않고 주된 내용을 봅니다.

## tags

- `tags`는 문자열 목록입니다. 현재 본문을 대표하며 여러 문서에서 함께 검색할 주제·기술을 평면 키워드로 고릅니다. 적합한 키워드가 없으면 `tags: []`를 사용합니다.
- 허용된 관련 영역의 기존 태그를 먼저 확인해 같은 개념의 표기를 재사용합니다. 근거가 충분하면 새 키워드를 만들며 고정 태그 목록·태그 수·도구별 분류표를 강제하지 않습니다. 태그 선택을 위해 관련 없는 root나 전체 위키를 탐색하지 않습니다.
- 새 영문 태그는 소문자와 필요한 하이픈을 사용합니다. 기존 한국어·고유 용어는 의미와 표기를 보존합니다. 목록 값에는 `#`나 카테고리 접두사를 붙이지 않습니다. 공백·슬래시가 없는 키워드이며 숫자만으로 구성하지 않습니다. 대소문자만 다른 값과 같은 의미의 중복은 늘리지 않습니다.
- 문서에 단순히 언급된 모든 명사·버전·작업 상태를 태그로 만들지 않습니다. 프로젝트명도 소유 폴더를 반복하기 위해 자동 부여하지 않고 실제 본문의 검색 주제로 판단합니다.

## 갱신과 실패

- 기존 frontmatter를 읽고 하나의 mapping 안에서 대상 속성을 병합합니다. 알 수 없는 속성·값과 본문·기존 참조를 보존하며 중복 YAML 블록·중복 키를 만들지 않습니다. 유효하고 내용에 맞는 기존 type·tags는 재사용합니다.
- 기존 계층 태그나 다른 사용자 관례의 변환은 승인 범위를 확인합니다. 의미를 확정할 수 없거나 YAML이 손상됐거나 기존 속성의 자료형이 충돌하면 조용히 덮어쓰지 않습니다. 허용된 본문 작업과 미반영 메타데이터를 구분해 보고합니다.
- 저장 후 YAML mapping과 키 중복, `type` 문자열, `tags` 문자열 목록, 태그 형식·중복·본문 적합성, 기존 속성·본문·근거 보존을 확인합니다. 문자열이 다른 YAML 자료형으로 해석될 수 있으면 인용합니다. 기존 분류·하향 탐색·권한 검증도 유지합니다.

## 예시

```yaml
---
type: benchmark
tags:
  - llm
  - uzu
  - performance
---
```

예시는 uzu 성능 측정 문서의 메타데이터이며 고정 어휘나 본문 템플릿이 아닙니다. 실행 계약은 runtime 본문이 자체 포함합니다.
