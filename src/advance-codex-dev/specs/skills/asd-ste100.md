# asd-ste100 스킬 스펙

## 목적

`asd-ste100`은 ASD-STE100의 명확한 기술 지시 작성 원칙을 Codex 지침, skill 본문, 기술 문서와 운영 절차의 작성·검토에 적용합니다.
언어 공통 원칙과 영어 전용 규칙을 구분하고, 의미 보존과 독자의 정확한 행동을 우선합니다.

## 경계

- 포함:
  - 구체적인 행동, 명확한 대상, 조건·순서·결과를 갖춘 지시 작성
  - 기술 문서·agent instruction의 작성, 재작성, 검토
  - 영어 일반 어휘의 승인 의미·품사 확인과 기술 명사·동사 구분
  - 원칙 적용과 공식 규격 준수 검토의 구분
- 제외:
  - 기술 사실, 누락된 판단 기준, 실행 권한의 임의 확정
  - 자동 번역, 일반 대화·문학·마케팅 문체의 일괄 변환
  - 공식 사전 전체 복제, 자체 어휘 목록을 공식 사전으로 취급
  - 인증, 실행 결과 검증, 도구 설치, 외부 양식 제출

## 처리하려는 작업 형태

- 명시적 ASD-STE100·STE 요청
- 기술 지시, skill·agent instruction, 운영 절차의 모호함을 줄이는 작성·검토
- 공식 규격 준수 요구가 있는 영어 기술 문서 검토

## 엔트리포인트 / 대표 표면

- runtime: `advance-codex/skills/asd-ste100/SKILL.md`
- 영어 전용 어휘·용법: `advance-codex/skills/asd-ste100/references/english-vocabulary.md`
- 출처·판본·준수 검토: `advance-codex/skills/asd-ste100/references/standard-scope.md`
- 호출: `$advance-codex:asd-ste100`
- description은 작성·검토 대상과 발동 조건을 설명하고 좁은 passive matching token을 포함합니다.

## 핵심 처리 계약

1. 요청 산출물, 독자, 언어·말투, 기술 근거, 보호할 literal, 작성·검토 범위를 확인합니다.
2. 절차와 설명문을 구분하고, 일반 원칙 적용을 기본으로 합니다. 사용자의 공식 준수 요구를 일반 원칙 적용으로 낮추지 않습니다.
3. 핵심 작성 원칙을 적용합니다. 영어 산문은 영어 reference를 읽고 어휘·용법을 검토합니다. 혼합 언어에서는 영어 산문 부분에만 적용합니다.
4. 원문·기술 근거와 대조하여 행동, 조건, 순서, 논리, 의무 강도, 예외, 수치·단위, 경고, 권한, exact literal을 보존합니다.
5. 작성·재작성은 완성 문서를, 검토는 위치·문제·근거·제안으로 응답합니다. 검토 요청만으로 원본을 변경하지 않습니다.
6. 공식 준수 요구, 규격 설명, 준수 주장의 근거 검사에서는 standard-scope reference를 읽습니다. 공식 준수 검토는 대상 판본, 전체 규칙·사전 접근, 프로젝트 용어 근거, 검토 범위와 미검증 사항을 확인합니다.

## 언어 공통 작성 원칙

- 한 문장에는 하나의 주제 또는 주된 지시를 둡니다. 여러 순차 작업은 순서를 유지한 별도 단계로 씁니다.
- 누가 무엇을 하는지 명확히 하고 구체적인 동사를 사용합니다. 절차는 직접 지시하며 설명문은 사실을 서술합니다.
- 실행 전에 알아야 하는 조건·전제·경고를 해당 행동 앞에 둡니다. 원인과 결과, 선택과 순차 행동을 구분합니다.
- 같은 대상에는 같은 용어를 사용하고, 지시 대상이 모호한 대명사는 명시적인 명사로 바꿉니다.
- 문장을 짧게 유지하되 필수 조건·예외·논리를 삭제하지 않습니다. 영어 단어 수 기준을 한국어에 강제하지 않습니다.
- 필요한 복구·중단 조건과 관찰 가능한 완료 기준을 근거에 따라 제시합니다. 원문에 없는 사실·조건을 창작하지 않습니다.
- `필요시` 같은 표현의 판단 기준이 없으면 확인된 기준만 사용합니다. 남은 불명확성은 표시하고, 결과에 중요한 경우에만 질문합니다.
- 사용자 언어·말투, 코드·명령·경로·API·식별자·UI label·인용문·승인된 안전 문구를 보존합니다. 변경 제한이 있는 문구는 충돌을 보고합니다.
- `must`, `should`, `may`, 부정, 수치, 논리 결합의 의미를 유지합니다.

## 영어 Reference 계약

- 승인 어휘, 의미·품사, 기술 명사·동사, 철자, 영어 문법 제한과 영어 예시는 영어 reference가 소유합니다.
- 본문에는 읽기 조건과 의미 보존 계약만 둡니다. 영어 단어 목록·치환표를 본문에 반복하지 않습니다.
- 공식 FAQ의 소수 예시는 출처가 있는 참고 사례이며 완전한 사전이나 무조건 치환 규칙이 아닙니다.
- 프로젝트 용어는 기술 근거와 적용 범위를 확인합니다. 사전에 없는 일반 단어를 기술 용어로 임의 분류하지 않습니다.
- 영어 전용 규칙을 한국어 등 다른 언어의 문법·어휘에 그대로 적용하지 않습니다.

## 준수·출처 경계

- 일반 원칙 적용은 ASD-STE100을 참고한 명확성 개선이며 공식 준수 확인이 아닙니다.
- 비영어 문서에는 공식 STE 준수를 주장하지 않습니다.
- 공식 준수 검토는 요청 판본의 전체 writing rules와 dictionary, 적용 가능한 프로젝트 용어 근거가 필요합니다.
- 원문·공식 자료가 부족하면 가능한 개선은 수행하고 준수 상태를 미검증으로 보고합니다. 요약 reference나 checker 출력만으로 준수를 확정하지 않습니다.
- 출처 확인일·판본·확인 범위와 공식 문서 미확보 한계를 reference에 남깁니다. 공개 웹 안내를 규격 전문으로 취급하지 않습니다.
- 필요한 판본·규칙·사전 항목을 확인할 수 없으면 규칙 번호·단어 승인·인증을 추정하지 않습니다.

## 검토 질문

- 독자가 대상, 행동, 적용 조건, 순서와 완료 기준을 정확히 알 수 있습니까?
- 조건·예외·의무 강도·논리·literal이 보존됐습니까?
- 영어 단어·문법 관련 세부가 references에만 있으며 읽기 조건이 명확합니까?
- 영어 규칙이 한국어와 exact literal까지 잘못 적용되지 않습니까?
- 근거가 없는 교체·중단·성공 기준을 추가하지 않았습니까?
- 준수 검토 범위와 미검증 사항을 실제 근거대로 보고합니까?
- 본문·references만으로 독립 실행되며 plugin 사용 표면이 실제 skill과 일치합니까?

## 독립성 원칙

- 독립 실행을 강제합니다. 본문과 번들 references만으로 작성·검토·미검증 보고가 가능해야 합니다.
- sibling skill과 개발용 spec은 runtime 필수 입력이 아닙니다. 공식 준수 검토에 필요한 외부 규격은 입력·증거이며 숨은 skill 의존성이 아닙니다.
- `optimize-token`은 표현 길이와 반복을, `asd-ste100`은 지시 명확성과 영어 통제를 소유합니다. 선택 기준은 plugin 사용 표면이 소유합니다.

## 확장 원칙

- 일반 대화의 기본 문체나 번역 skill로 확장하지 않습니다.
- 상세 영어 규칙·예시는 references에서 유지하고 새로운 공식 정보는 판본·출처와 함께 확인합니다.
- 다른 skill의 작성 workflow나 실행 권한을 흡수하지 않습니다.
