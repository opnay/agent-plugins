# Compression Intent Scenarios

각 입력에는 하나의 가장 짧고 안전한 기대 출력만 둡니다.

| 시나리오 | 입력 | 기대 출력 | 핵심 보존 기준 |
| --- | --- | --- | --- |
| 기본 간결화 | `설정 경로를 확인한 결과, 설정 경로가 잘못되어 있음을 확인했습니다.` | `설정 경로가 잘못됐습니다.` | 직접 결론, 자연스러운 문법 |
| 원인·증거 | `원인은 아직 확정되지 않았지만 로그에는 권한 오류가 있습니다.` | `원인: 미확정. 증거: 권한 오류 로그.` | 추정 원인과 관측 증거 분리 |
| 순서·의존성 | `spec을 먼저 고친 뒤 runtime을 다시 쓰고, 그 결과를 build해야 합니다.` | `순서: spec > runtime > build.` | 선행 순서와 의존성 |
| 범위·비목표 | `A는 변경하지만 B는 이번 작업 범위가 아닙니다.` | `변경: A. 제외: B.` | 포함 범위와 비목표 분리 |
| source 구분 | `원본은 dev source이고 release surface는 build가 만든 생성물입니다.` | `Source: dev source. 생성물: release surface.` | source of truth와 생성물 구분 |
| 미실행 검증·위험 | `핵심 테스트는 아직 실행하지 않았고 회귀 위험이 남아 있습니다.` | `검증: 미실행. 위험: 회귀 가능.` | 미실행 상태와 남은 위험 |
| 승인 경계 | `커밋은 실행하지 않았고 push와 PR도 승인되지 않았습니다.` | `커밋: 미실행. push/PR: 미승인.` | 실행 상태와 외부 변경 승인 분리 |
| 저장 문서·결측값 | `운영 문서에는 pnpm build:plugin advance-codex --force를 실행하는 현재 계약만 남겨야 하며 담당자는 아직 없습니다. 이전에는 npm도 고려했습니다.` | `명령: pnpm build:plugin advance-codex --force. 담당자: -.` | 현재 지속 계약, 정확한 명령, 필드 결측값 |
