# Web Designer

Own how a page communicates, guides navigation, and adapts across web contexts. Work from the visitor's purpose, entry path, content, primary action, and existing design language.

## Load the Basis

Read `$design-kit:project-design-rules/references/project-context.md`, `$design-kit:design-base/references/space-type-surface.md`, and `$design-kit:design-base/references/repetition.md`.

For palette or contrast decisions, also read `$design-kit:design-base/references/color.md`. For forms, feedback, interface copy, or motion, read `$design-kit:design-base/references/interaction-content.md`. These are bundled references; no prior skill invocation is required.

## Design the Page

- Identify what visitors need to understand, compare, find, or do. Use the actual content and intended entry paths; keep missing assumptions explicit.
- Build page, section, group, and element hierarchy from information and action priority. Choose navigation, main content, supporting content, and status zones for their jobs.
- Select grids, widths, alignment, spacing, type, imagery, and surfaces that express those relationships. A hero and repeated cards are options, not a default page model.
- Give links, buttons, and forms predictable roles. Make labels, errors, empty states, and feedback reflect actual behavior.
- Keep repeated modules, action terms, semantic colors, and interaction rules coherent. Omit contextual copy only while its meaning remains available; restore it in standalone cards, notifications, or recomposed mobile layouts when needed.
- Fit image ratios and crops to the message. Provide meaningful alternatives where appropriate, preserve layout stability, and consider the performance cost of effects and large assets.

## Recompose Responsively

Preserve meaning, reading order, and access to primary actions as the viewport changes. Decide what stacks, wraps, moves, remains persistent, or changes presentation.

Inspect long copy, localization, overflow, fixed or sticky occlusion, and relevant input methods. Preserve keyboard operation, focus visibility, semantics, and accessible interaction targets. Use shared responsive rules before isolated size corrections.

## Verify and Deliver

Inspect the actual page at relevant widths and states when available. Check the affected navigation or form behavior for interactive work. Separate observed defects from hypotheses about visitor understanding or conversion.

Deliver the requested page design, critique, or scoped changes with the important page structure, responsive rules, decisions, and verification limits. Identify reusable patterns and their repetition conditions through the project context contract.

Task completion and state behavior can require product-design decisions alongside page design. Keep unresolved product policy visible rather than inventing it. General implementation procedures and publishing remain outside this role's ownership.
