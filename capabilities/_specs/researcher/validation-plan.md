# Research 0.1.0 검증 계획

## 대상과 분리

단일 research의 형식·spec/runtime·리소스·선택 기준, 좁은 조사/심층 조사/계획/배정 worker 경계와 비례성을 확인합니다. 이동만 하는 다른 skill은 이전 소스의 명시적 이름·경로 변환 결과와 대조합니다. 실제 설치와 metadata 발견, 본문/reference 읽기, 답의 품질은 별도 관찰입니다.

## 고정 사례

각 사례의 동일 요청·초기 파일·권한·관찰 기준을 실행 전에 고정합니다. 기대 결과와 실패 가설은 작업 폴더 밖에 둡니다. 사례별 사용·미사용을 새 HOME/CODEX_HOME·동일 모델 요청/도구/한도에서 실행합니다. 사용 조건만 현재 skill 폴더를 임시 native 경로에 연결하고 본문을 주입하지 않습니다. 미사용에는 대상이 없어야 합니다. 실제 선택하지 않은 결과도 보존합니다.

## 검증과 해석

- JSON·두 manifest metadata·현재 11 plugin/26 skill·실제 skill/spec/intent·호출·상대 링크·scoped 리소스·순서를 확인합니다.
- 독립 read-only verifier가 연구 계약, 패키징, 조합/실행 경계를 좁게 검토하고 주 실행자가 근거를 대조합니다.
- 별도 HOME의 native plugin 등록·설치·목록·cache 일치와 설치된 namespace 호출을 검사합니다. 직업 숙련도 asset의 명시 읽기와 orcat adapter 부재 보고는 별도 smoke입니다.
- 실제 답·도구 출력·변경 상태로 각 조건을 먼저 판정한 뒤 쌍을 해석합니다. 양쪽 성공은 추가 효과 미확인이며 미사용 성공/사용 실패는 회귀 후보입니다. 본문 비선택은 로딩 후 효과 증거가 아닙니다.
- 원본 인증 내용은 읽거나 복사하지 않고 임시 링크만 사용·제거합니다. source와 사용자 설치는 보존합니다. 환경 오류·fixture 오류·무관한 tool 실패와 산출물 계약 위반을 구분합니다.
- 한 번의 합성 사례·요청 모델 설정에 한정합니다. 서버 실행 모델 ID·실제 외부 원자료 수집·orcat/app 통합·Claude host 실행이 미확인이면 그대로 보고합니다.
