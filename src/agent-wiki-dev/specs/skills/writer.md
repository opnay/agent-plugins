## 사용자 스펙 의도

- writer는 조사 자료·사용자 정보·작업 기록을 자주 반영하고 문서 연결과 정리를 소유합니다.
- 폴더 트리가 상위 위치를 제공하고 index.md는 top-down 하위 안내를 담당합니다. 일반 문서에는 의미 있는 관련 참조만 두며 위치 복귀용 상위·root 링크와 왕복 의무는 두지 않습니다.
- 고정 폴더·템플릿 없이 기존 위키를 따르며, 빈 위키는 첫 작성 시 최소 index.md부터 만듭니다.
- 폴더당 직접 파일 25개·루트 0 기준 깊이 4를 지키며, 복합명은 `<상위>_<하위>`까지만 사용합니다.
- 웹 조사 후에는 항상 기록 여부를 판단하되 탐색 자체나 중복을 매번 기록하지 않습니다.
- root는 물리적 공개·백업 경계이고 폴더는 의미 분류입니다. 기록마다 하나의 named root를 명확히 선택합니다.

- 작성 빈도를 높여 결과뿐 아니라 당시 활용한 지식·판단·주요 실패와 전환을 복원할 수 있어야 합니다.
- 작업 기록 > 판단별 근거 목록 > 자료 출처·요약을 연결하되 모든 단계를 별도 문서로 만들지는 않습니다.
- 서브에이전트가 조사한 URL 자료를 위키에 정리하고 메인 에이전트가 필요한 부분만 읽을 수 있어야 합니다.
- 위키는 판단에 필요한 지식·관찰 결과·조건·한계를 남기며 모든 작업의 재실행을 요구하지 않습니다. 임시 폴더를 지속적인 근거처럼 남기지 않습니다.
- 작성·정리 시 문서의 주제 소속과 개요·버전 전환·패턴·사례 역할을 먼저 판단합니다. 파일 수 상한에 이르기 전에도 실제 내용에 맞는 주제 폴더를 구성하고 의미상 배치를 완료 기준으로 확인합니다.

# Writer 스킬 스펙

## 목적·경계

승인된 위키에 새 지식·사용자 정보·결정·작업 결과를 반영하고 탐색 가능한 연결을 유지합니다.
외부 재조사, 제품 구현, 임의의 다른 위키 선택, 전체 구조의 상시 재편은 소유하지 않습니다.

## 기록 시점

- 조사 질문의 답·근거를 확보했을 때, 사용자가 사실·선호·규칙을 알려줬을 때, 실패 원인·해결 조건을 확인했을 때, 결정·작업 결과가 확정됐을 때 기록합니다. 웹 조사 결과는 아래 기록 기준을 적용합니다.
- 먼 미래의 재사용 가능성이 높아야만 기록하는 필터를 두지 않습니다. 긴 작업에서는 확정된 중간 결과마다 반영합니다.
- 동일 정보는 중복 기록하지 않고 기존 문서로 연결합니다. 검색·도구 호출별 원시 로그, 비공개 추론 과정, 불필요한 비밀값은 기록하지 않습니다.
- 가설·계획은 사실이나 완료 결과로 쓰지 않습니다. 사용자가 기록 금지·읽기 전용을 지정하면 반영하지 않습니다.

## 웹 조사 기록 기준

- 웹 조사 후 항상 기존 위키와 비교해 기록·갱신·생략을 판단합니다. 웹검색 외의 사용자 정보·작업 기록 조건은 유지합니다.
- 새 사실·방법·제약, 비교·선택·배제의 결정 근거, 기존 위키의 오류·누락·오래된 정보 정정이면 기록합니다. 실제 근거를 확인한 결과만 사실로 쓰고 나머지는 미확인으로 구분합니다.
- 페이지 위치 찾기·실패한 검색·내용 없는 탐색만 했거나, 기존 위키와 같은 정보에 추가할 근거·조건도 없으면 생략합니다.
- 검색 과정에서 불확실성이 생겼다는 사실만으로 기록하지 않습니다. 알려진 제약이나 실패 원인이 작업에 영향을 준다는 근거를 확보했다면 새 지식으로 평가합니다.
- 날씨·가격·일정 등 일시적 정보는 작업 결정의 근거일 때만 날짜·적용 범위와 함께 기록합니다.
- 기존 설명을 재확인한 경우 확인 시점·근거의 갱신이 현재 판단에 도움이 될 때만 해당 부분을 갱신하고 중복 문서를 만들지 않습니다.
- 검색어·방문 페이지가 아닌 해결한 질문과 결과를 단위로 묶고 출처·범위·확인 시점을 보존합니다. 같은 질문을 위한 여러 조회를 개별 기록으로 늘리지 않습니다.
- 충분한 기존 조사 결과를 받아 바로 판단할 수 있으며 researcher 선행 실행이나 재검색은 요구하지 않습니다. 기록 판정은 쓰기 권한을 확대하지 않습니다.

## 작업 기록과 근거 연결

- 탐색 관계는 `작업 기록 > 판단별 근거 목록 > 자료 출처·요약`입니다. 판단별 목록은 작업 문서 안에 두고, 재사용할 자료 요약은 별도 문서로 연결할 수 있습니다. 세 파일이나 고정 디렉터리를 강제하지 않습니다.
- 작업 기록은 문제·목표·배경·사용자 제약, 활용한 지식과 출처, 검토한 대안과 채택·배제 이유, 주요 시도·실패·전환, 결과·검증·미해결 한계를 포함합니다. 해당하지 않는 항목을 억지로 채우지 않으며 필요한 정보가 없으면 공백을 명시합니다.
- 판단별 근거에는 확인하려던 질문, 관련 자료 링크, 실제 판단에 어떻게 쓰였는지, 미확인 항목을 남깁니다. 자료 문서는 질문 관련 핵심 내용·원문 URL 또는 코드/실행 위치·확인 날짜·버전·적용 조건·불확실성을 보존합니다.
- 원인 확인, 대안 채택·배제, 가설 기각, 의미 있는 실패·방향 전환, 검증 결과 확정 시 같은 작업 기록에 누적합니다. 종료 때만 작성하지 않습니다. 완료 시 기록할 사건과 저장 내용을 대조해 누락된 판단·근거·결과를 확인합니다.
- 당시 알려진 사실과 후속 정정을 구분합니다. 기존 기록 보완은 확인 가능한 출처에 한정하며 기록되지 않은 당시 판단은 추측하지 않습니다. 의사결정 요약과 관찰 가능한 근거를 남기고 비공개 추론이나 도구 원시 로그는 저장하지 않습니다.
- 작업 문서는 프로젝트 인덱스에서 문제·증상·해결 방식으로 찾을 수 있게 연결합니다. 일반화한 지식은 적용 조건과 원래 작업 기록을 연결하고, 공유 자료 요약은 작업마다 복제하지 않습니다.
- 위임된 자료 정리는 제공된 질문·자료·기록 권한을 사용합니다. 실제 채택·배제 이유는 작업 담당자가 제공한 근거가 있을 때만 기록합니다. 동일 문서 동시 쓰기는 담당 지정 또는 직렬화로 피하고 저장 직전에 재확인합니다.
- 위임 결과는 저장 문서 경로·핵심 발견·미해결 항목·저장 상태로 간결히 반환합니다. 상세 요약은 저장 문서에 두되 저장 실패를 경로만으로 숨기지 않습니다.
- 완료 기준: 새 맥락의 독자가 기록과 연결된 출처만으로 과거 문제·선택 이유·시행착오·검증·교훈을 글 작성에 활용할 수 있어야 합니다. 출처 없는 판단은 추정으로 채우지 않고 공백으로 전달합니다.

## 근거의 지속성과 재현 범위

- 기록 자체에 확인한 사실·관찰 결과, 판단 이유, 중요한 조건·시점·버전, 한계가 있어야 합니다. 링크나 실행 경로만으로 내용을 대신하지 않습니다.
- 위키의 기본 완료 기준은 지식과 판단 맥락의 이해입니다. 모든 실험의 재실행·원시 로그·재현 스크립트·전체 산출물 보존을 요구하지 않습니다. 사용자가 재현을 요청했거나 결과를 활용하려면 재실행이 필요한 경우에만 필요한 자료의 범위와 보존 권한을 확인합니다.
- `/tmp`, `/private/tmp`, 임시 worktree·scratchpad 같은 소멸 가능한 작업 위치는 지속적인 근거 출처로 사용하지 않습니다. 필요한 관찰과 결론은 본문에 요약하고, 원본 추적이 필요하면 실제로 확인한 원문 URL·저장소 커밋과 파일 위치·같은 root의 보존 자료를 사용합니다. 안정적인 원본이 없으면 관찰 당시 결과와 독립 재확인 한계를 명시합니다.
- 임시 경로는 단기 복구·인계에 필요한 경우에만 작업 위치로 구분하고 임시성·용도를 밝힙니다. 영구 보존·현재 접근 가능·원시 자료 독립 검증을 암시하지 않습니다. 근거 경로로 남기기 위해 원시 로그·산출물을 자동 복제하거나 다른 root로 옮기지 않습니다.
- 기존 기록의 임시 경로를 고칠 때 확인된 요약·조건·한계는 보존합니다. 확인하지 않은 영구 경로를 만들거나 자료를 읽지 않고 근거를 검증했다고 쓰지 않습니다.

## 쓰기 계약

1. 경로·쓰기 범위를 확인하고 정확히 하나의 root를 고릅니다. 우선순위는 사용자 지정 root, 명확한 현재 작업 root, 이름·설명의 정확한 일치, 비민감하고 모호하지 않은 default입니다. 위치 지정은 권한 부여가 아닙니다.
2. 개인정보·서로 다른 공개 경계가 섞였거나 root가 모호하면 사용자에게 확인합니다. 더 엄격한 root에 둘지 문서를 나눌지는 추측하지 않으며, 자동 링크·복제·이동·병합하지 않습니다. root 사이 이동은 사용자가 출발 root·대상 root·범위를 명시한 경우에만 수행하고 cross-root Markdown 의존성을 만들지 않습니다.
3. 기존 인덱스·대상 문서·주변 연결을 선택 root 안에서 읽습니다. 충분한 제공 자료는 재조회하지 않고 정확한 문서 경로를 알면 직접 읽습니다. 기존 자료를 찾아야 하면 root·하위 인덱스로 영역을 고른 뒤 관련 링크·영역 내 검색을 사용합니다. 인덱스 누락·불완전·선택 영역 미발견 때만 필요한 범위로 넓힙니다. 입력이 충분하면 reader나 researcher를 재호출하지 않습니다. 명시적 전역 정리·감사는 승인된 범위에서 검사합니다.
4. 아래 주제·문서 역할 기준으로 위치를 판단합니다. 같은 주제·범위면 갱신하고, 별도 주제·버전·사례로 참조할 이유가 있으면 새 문서를 만듭니다. 고정된 Project/Knowledge 구조나 문서 템플릿을 강제하지 않습니다.
5. 첫 작성 시 선택 root의 index.md가 없으면 기존 파일을 살핀 뒤 최소 인덱스를 생성합니다. 빈 위키에는 불필요한 하위 폴더를 미리 만들지 않습니다.
6. 제목·적용 범위·출처 또는 사용자 제공 맥락·필요한 확인 시점·불확실성을 식별 가능하게 기록합니다. YAML이나 표를 일괄 강제하지 않습니다.
7. 현재 지식은 근거에 맞게 정정하며, 과거 결정·작업 기록은 당시의 의미를 보존합니다. 중요한 상충은 해소 근거 또는 미해결 상태를 남깁니다.
8. 선택 root 안의 연결 계약을 적용하고 저장 후 실제 내용과 링크를 확인합니다. 다른 root로 향하는 상대 Markdown 링크는 만들지 않습니다.

## 주제 소속과 문서 역할

- 승인된 작성·정리마다 소유 주제와 개요·버전 전환·재사용 패턴·개별 사례·작업 기록 역할을 먼저 판단합니다. 관련 기존 내용에서 지식의 분산·역할 혼재를 확인합니다. 파일 수·깊이 상한 미만이어도 이 판단을 수행하며 제한 준수만으로 배치 적합성을 인정하지 않습니다.
- 내용이 독립적으로 활용할 지식 영역을 이루고 버전·패턴·사례를 별도로 참조할 필요가 있으면 해당 주제 폴더를 사용하거나 구성합니다. 구체적인 버전 문서 하나가 첫 하위 문서여도 되며 두 번째 파일이나 상한 초과까지 기다리지 않습니다. 예를 들어 Zod가 재사용 검증 지식을 소유한다면 버전 전환은 `frontend/zod/migration-4-5.md`처럼 주제 아래 둡니다. 경로·이름은 위키 관례에 맞춥니다.
- 릴리스 전용 변경과 일반 패턴은 질문·적용 범위가 다를 때 구분합니다. API·절마다 기계적으로 문서를 나누지 않습니다. 단일 메모에 독립 주제 경계가 유용하지 않으면 적절한 기존 영역에 유지합니다. 모든 문서별 폴더, 빈 미래 분류·개요 placeholder, 내용 중복을 만들지 않습니다. 주제 index는 목적·실제 하위 문서 역할을 설명하며 실제 자식 하나로도 충분할 수 있습니다.
- 유용한 기존 관례·내용을 보존하되 기존 평면 배치라는 이유만으로 주제 소속 재판단을 생략하지 않습니다. 필요한 로컬 분류·참조 갱신은 기존 승인 범위에서 수행하며 통상 작업에 재확인을 요구하지 않습니다. 정확한 파일만 수정하라는 요청은 다른 문서 이동 권한이 아닙니다. 범위 밖 재편이나 root 경계 변경이 필요하면 허용된 부분을 완료하고 남은 구조 문제를 알리며 자발적인 전체 재편으로 넓히지 않습니다.
- 저장 후 각 문서의 주제 소속·역할·적용 범위, 관련 지식의 불필요한 분산, index의 실제 하위 안내, 빈 구조·중복 생성 여부를 확인합니다. 하향 링크·파일 수·깊이 검사는 의미상 분류 검증을 대신하지 않습니다. 범위 밖에 남은 배치 문제를 알리고 부분 검사로 위키 전체 정상이라고 보고하지 않습니다.

## 연결·정리

- 생성·이동 전에 결과 구조를 확인합니다. 폴더당 직접 파일은 index.md·첨부·숨김 파일을 포함해 최대 25개입니다. 하위 폴더와 ZIP 내부 항목은 합산하지 않습니다.
- 루트 깊이는 0이며 폴더 깊이는 최대 4입니다. 단순 이름·서브 카테고리는 자유롭게 정하되 밑줄 복합명은 비어 있지 않은 두 부분 `<상위>_<하위>`까지만 허용합니다. 세 부분 이상은 실제 하위 폴더로 표현하며 파일명은 이 규칙의 대상이 아닙니다.
- 26번째 파일이나 깊이 5가 필요하면 먼저 기존 문서 갱신, 의미 있는 하위 분류, 깊이 4에서 기존 형제 영역 활용·해당 영역 재편을 검토합니다. 새 index.md도 결과 파일 수에 포함합니다. 무관한 문서 병합·내용 삭제·번호만 다른 폴더로 제한을 맞추지 않습니다.
- 허용 범위 안에서 의미와 근거를 보존하며 재구성할 수 없으면 상한을 넘겨 쓰지 않고 미반영 내용과 필요한 결정을 알립니다. 기존 위반의 최초 정리는 명시된 정리 범위로 수행하고, 이후 일반 작업은 영향받는 영역만 점검합니다.
- index.md는 영역의 목적·범위와 하위 주제·문서의 역할을 설명하고 다음 읽을 대상을 top-down으로 안내합니다. 파일 목록을 계속 덧붙이는 문서로 만들지 않습니다. 일반 문서는 본문 이해에 필요한 관련 개념·근거를 연결합니다.
- 루트 인덱스에서 하위 주제와 각 문서로 실제 링크를 따라 도달할 수 있어야 합니다. 검증은 하향 도달성과 링크 대상 유효성을 확인하며 문서→루트 복귀는 요구하지 않습니다. 일반 문서끼리만 순환하며 루트에서 찾을 수 없는 집합은 충분하지 않습니다.
- 상위 위치는 폴더 트리로 확인합니다. 인덱스·일반 문서에 위치 복귀만을 위한 상위·root 링크나 기계적인 상호 링크를 넣지 않습니다. 기존 링크 삭제는 사용자가 탐색 정리를 승인한 범위에서만 수행하며 일반 내용 수정에 덧붙이지 않습니다. 대상이 상위 index라는 이유만으로 삭제하지 않고 문맥상 위치 복귀용인지 판단해 관련 개념·근거·개요 참조를 보존합니다. 기존 위키 전체를 일괄 수정하지 않습니다.
- 작성할 때 주변 중복·참조를 정리하고 작업 종료 시 변경한 문서와 그 연결 범위를 점검합니다. 상한 초과·중복·탐색 곤란·상이한 적용 범위가 드러나면 해당 영역만 병합·분리·인덱싱합니다.
- 이동·병합은 선택 root 안에서만 기존 내용을 보존한 목적지를 먼저 준비하고 들어오는 링크와 상대 링크를 갱신한 뒤 이전 문서를 제거합니다. root 사이 이동은 위의 명시적 사용자 지시가 있을 때만 별도 작업으로 수행하며 root를 가로지르는 Markdown 링크·복제·병합을 만들지 않습니다. 관련 참조 탐색은 위키 전체에서 할 수 있지만 수정은 영향 범위로 한정합니다.
- 여러 작업이 같은 파일을 갱신할 수 있으면 쓰기 직전 다시 확인하고 충돌 시 병합합니다. 진행 중인 변경을 덮어쓰지 않습니다.
- 기존의 무관한 고립 문서는 위치·문제를 알리고 현재 작업을 전체 재정리로 확대하지 않습니다. 전체 연결 검증을 하지 않았다면 전체 정상이라고 보고하지 않습니다.

## 완료·실패

- 변경 경로, 반영 내용, 연결 확인 범위, 남은 문제를 간결히 전달합니다. 기존 내용이 충분해 변경이 없으면 그대로 알립니다.
- 쓰기·검증이 실패하면 확인된 부분만 반영 완료로 구분합니다. 연결이 깨진 상태에서 이전 문서를 삭제하거나 정리 완료로 보고하지 않습니다.
- 설정·권한이 없으면 다른 폴더에 임의로 저장하지 않습니다. 가능한 본 작업은 계속하며 위키 미반영을 알립니다.
