# v0.1.0

## 변경사항 요약

- `code-quality-dev` 플러그인을 추가했습니다.
- `code-quality` instruction-only skill을 추가했습니다.
- production code 구현, 리팩터링, 테스트, 의존성 판단, 코드 리뷰 기준을 runtime references로 분리했습니다.
- 호출/비호출 검증용 prompt fixture를 추가했습니다.
- 시나리오 테스트 결과에 따라 generated/vendor, formatting-only, style-only, naming-only 경계를 명확히 했습니다.

## 변경 상세

### 새 플러그인

- 목적: production code 작업에서 정확성, 변경 안전성, 검증 가능성, 적절한 재사용, 단순한 설계를 지원합니다.
- 범위: 구현, 버그 수정, 리팩터링, 테스트, 의존성 판단, 코드 리뷰입니다.
- 비목표: prose-only 작업, 번역, 단순 포맷·스타일·이름 변경, code-quality 위험 검토 없는 generated/vendor code 직접 수정입니다.

### 새 skill

- `skills/code-quality/SKILL.md`는 짧은 실행 절차와 priority order만 소유합니다.
- 상세 품질 기준, 재사용과 의존성 기준, decision guide, review rubric, examples는 `references/`로 분리했습니다.
- `formatting-only`, `style-only`, `naming-only` 작업은 기본 비호출로 두고, 예외는 `$code-quality` 명시 호출이나 correctness/security/compatibility/operational-risk 검토 명시 요청으로 좁혔습니다.

### 검증 기준

- skill validator가 통과해야 합니다.
- plugin build가 release surface를 생성해야 합니다.
- release surface에는 `specs/`와 `changes/`가 포함되지 않아야 합니다.
- JSON/YAML/CSV가 파싱 가능해야 합니다.
