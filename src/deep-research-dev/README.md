# Deep Research Dev

여러 출처를 체계적으로 수집·대조하여 주장별 근거, 반대 근거, 불확실성, 출처를 추적하는 의사결정용 조사 보고서를 만듭니다.

## 목적

`deep-research-dev`는 조사 자체가 산출물인 작업을 위한 단일 스킬 플러그인입니다. 시장 조사, 문헌 조사, 기술·정책 조사, 팩트체크, 실사처럼 결론의 근거를 나중에 검토할 수 있어야 하는 질문을 다룹니다.

`judgment-kit:pro-researcher`가 이후 제품·디자인·엔지니어링·품질 판단을 위한 불확실성 감소와 decision input을 소유한다면, 이 플러그인은 여러 출처를 직접 조사·대조해 독립적인 조사 보고서를 완성하는 실행 워크플로를 소유합니다.

## 적합한 상황

- 특정 시장의 규모·성장·경쟁 구도를 기준 시점과 지역별로 비교해야 할 때
- 논문, 표준, 공식 문서, 원 데이터를 대조해 기술 또는 정책 주장을 검증해야 할 때
- 제품, 회사, 정책, 기술의 사실관계를 출처와 함께 확인해야 할 때
- 실사에서 주장별 근거, 반대 근거, 적용 범위, 남은 불확실성을 남겨야 할 때

## 부적합한 상황

- 날씨·현재가·단순 정의처럼 한 번의 조회로 답할 수 있는 질문
- 사용자가 제공한 한 문서만 요약하는 작업
- 근거 없는 아이디어 발산, 코드 구현, 외부 시스템 변경, 지속 모니터링
- OpenAI의 독점 기능 또는 제품 모드인 `Deep Research`와 같다고 주장해야 하는 작업

## 사용 방법

명시 호출:

```text
$deep-research-dev:deep-research 한국의 2025년 생성형 AI 규제 변화를 조사해 기업 도입 판단 보고서로 정리해 주세요.
```

자동 트리거가 적합한 요청 예시:

- “서로 다른 국가의 데이터 이전 규제를 2026년 7월 기준으로 비교하고 출처를 붙여 주세요.”
- “이 기술 주장이 사실인지 원 논문과 독립 검증 자료를 대조해 주세요.”
- “인수 후보 회사의 공개 보안 사고 이력을 반대 근거까지 포함해 실사 보고서로 작성해 주세요.”

질문의 의사결정 목적, 범위, 기준 시점, 지역, 비교축, 보고서 형식이 결론을 크게 바꾸지 않는 한, 스킬은 가정을 공개하고 조사를 진행합니다. 그 정보가 결론을 실질적으로 바꿀 때만 먼저 확인을 요청합니다.

## 산출물

보고서는 질문에 직접 답하면서 다음을 함께 제공합니다.

- 조사 범위와 기준 시점, 핵심 판단
- 주장별 사실·해석·추론·권고 구분
- 근거와 반대 근거, 적용 범위, 신뢰도, 남은 불확실성
- 정확한 출처 URL, 발행일 또는 기준일, 접근일
- 상충 근거와 최신성 위험, 결론을 바꿀 수 있는 추가 정보

검색 결과의 스니펫은 탐색에만 사용하며 인용하지 않습니다. 핵심 주장은 가능한 한 원문 또는 1차 자료로 확인합니다.

## 모델 역할 예시

모델 이름이 아니라 역할과 검증 책임으로 배치합니다. 현재 제품군의 예시는 다음과 같지만, 특정 모델에 기능을 고정하지 않습니다.

| 역할 | 책임 | 현재 예시 |
| --- | --- | --- |
| 조사 설계·상충 판단·최종 종합 | 범위, 증거 강도, 결론과 인용을 최종 검토합니다. | 가장 강한 추론 모델(예: Sol) |
| 독립 출처 스트림 조사 | 분리된 하위 질문을 읽기 전용으로 조사합니다. | 균형형 작업 모델(예: Terra) |
| 고정 스키마 대량 추출 | 반복 추출을 수행하고 원문 근거를 보존합니다. | 빠르고 저렴한 모델(예: Luna) |

위임은 서로 겹치지 않는 읽기 전용 조사 스트림이 세 개 이상이고, 각 질문·범위·출력 스키마가 분명할 때만 사용합니다. 최종 책임자는 중요한 주장과 인용을 직접 다시 확인합니다.
