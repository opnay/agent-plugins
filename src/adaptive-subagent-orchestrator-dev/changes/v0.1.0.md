# adaptive-subagent-orchestrator-dev 0.1.0 Change Spec

## 변경사항 요약

- orchestration을 경량 진입, 위임·생성, 결과 검증·통합의 세 skill로 제공합니다.
- `orchestrate-subagents`만 implicit invocation을 허용합니다.
- 기존 `adaptive-subagent-orchestrator` skill identifier는 shim 없이 대체합니다.

## 변경 목적

DIRECT 또는 false-positive 요청이 단일 대형 skill 본문을 로드하지 않도록 entry 비용을 제한하면서, delegation gate와 evidence integration 계약은 focused skill에 보존합니다.

## 릴리즈 노트 기준

- 독자에게 보이는 변화: `$adaptive-subagent-orchestrator:orchestrate-subagents`, `$adaptive-subagent-orchestrator:dispatch-subagents`, `$adaptive-subagent-orchestrator:integrate-subagent-results`를 제공합니다.
- 호환성 영향: 기존 `$adaptive-subagent-orchestrator:adaptive-subagent-orchestrator` 호출은 더 이상 유효하지 않습니다.
- migration 필요 여부: 기존 explicit call을 새 entry identifier로 변경해야 합니다. compatibility shim은 제공하지 않습니다.
- 운영자/사용자가 알아야 할 검증 결과: entry context budget, invocation policy, lifecycle handoff, skill/plugin validation, release build, forward test를 통과해야 합니다.

## 기록 근거

- 관련 커밋: 미정.
- 관련 세션 기록: 2026-07-20 skill decomposition session.

## 변경 상세

### 3단 skill composition

- 목적: false-positive activation 비용과 단일 skill 책임 과밀을 줄입니다.
- 범위: plugin spec, 세 skill spec, 세 runtime skill folder, README, manifest.
- 관련 표면: `src/adaptive-subagent-orchestrator-dev`.
- 검증: spec/runtime alignment와 plugin usage surface 검토.

### 경량 implicit entry

- 목적: 정밀도 우선으로 `DIRECT` 또는 `DISPATCH`만 판정합니다.
- 범위: `orchestrate-subagents` description, body, invocation metadata.
- 관련 표면: `skills/orchestrate-subagents/`.
- 검증: body 200단어 이하, description 80단어 이하, references 부재, positive/negative trigger forward test.

### Dispatch와 integration

- 목적: 실제 spawn과 evidence-backed integration을 명시적 artifact로 연결합니다.
- 범위: delegation rubric, task contract, DispatchManifest, result contract, integration workflow.
- 관련 표면: `skills/dispatch-subagents/`, `skills/integrate-subagent-results/`.
- 검증: DIRECT, PARALLEL_READ, PARALLEL_WRITE, input gate, conflict, failure, read-to-write 시나리오.

## 비목표

- 별도 planner 또는 mode별 skill 추가.
- 외부 Codex 설정 변경.
- user-level skill folder 생성.
- scripts, assets, MCP, app integration 추가.
- 모델명, reasoning effort, custom agent configuration 하드코딩.

## 호환성 및 마이그레이션

- 플러그인 이름과 version `0.1.0`은 유지합니다.
- 기존 skill folder와 identifier는 release surface에서도 제거합니다.
- README, manifest, prompt 예시는 새 entry identifier로 교체합니다.
- root release surface는 build command로만 갱신합니다.

## 검증 기준

- 세 skill folder에 canonical `quick_validate.py`를 실행합니다.
- dev와 release plugin에 `validate_plugin.py`를 실행합니다.
- entry body·description word count, references 부재, 진입만 implicit임을 검사합니다.
- runtime에 dev-only spec path와 기존 skill identifier가 남지 않았는지 검사합니다.
- `pnpm build:plugin adaptive-subagent-orchestrator --force`로 release surface를 갱신합니다.
- marketplace JSON과 모든 `agents/openai.yaml`을 파싱합니다.
- clean-context verifier와 fresh forward-test scenario를 통과합니다.

## 정식 규칙 승격 여부

- normative spec 또는 runtime 문서로 승격할 지속 규칙: 3단 lifecycle, precision-first entry, delegation gate, DispatchManifest, result evidence validation, no nested subagents.
- change spec에만 남길 release/migration 이력: 기존 identifier 제거와 0.1.0 내부 구조 전환.
