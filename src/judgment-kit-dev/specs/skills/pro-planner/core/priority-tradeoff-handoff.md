# Priority, Tradeoff, And Handoff

이 문서는 `pro-planner`의 우선순위, tradeoff, handoff 계약을 소유합니다.

## Priority

- 우선순위는 사용자 가치, 위험 감소, 의존성, 구현/운영 비용, 학습 효과, 되돌리기 쉬움을 함께 봅니다.
- 제품 방식 선택을 막는 질문이나 기능 영역 간 강한 의존성은 우선순위를 높입니다.
- 중요하지만 검증 불가능한 항목은 먼저 검증 가능한 질문이나 작은 release slice로 바꿉니다.
- 높은 빈도, 높은 위험, 강한 의존성, 주요 사용자의 막힘은 우선순위를 올리는 신호입니다.

## Tradeoff

- 빠른 출시와 완성도, 자동화와 사용자 통제, 단순함과 확장성, 개인화와 일관성 사이의 선택을 명시합니다.
- tradeoff는 선택, 포기한 대안, 선택 이유, 남은 위험, 재검토 조건을 포함합니다.
- 불확실성이 크면 큰 결정보다 학습 가능한 작은 실험을 우선합니다.

## Handoff

- designer handoff는 제품 방식, 사용자 목표, 기능 영역 map, 정보 구조, 화면 inventory, 디자인 시스템 브리프, 주요 흐름, 정보 우선순위, 상태, 오류, UX 위험을 전달합니다.
- engineer handoff는 기능 영역별 요구사항, 데이터와 상태, 정책, 예외, acceptance criteria, non-goal을 전달합니다.
- handoff는 해결책을 과도하게 고정하지 않고, 다음 역할이 판단해야 할 여지를 남깁니다.
