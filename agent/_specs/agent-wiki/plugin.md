## 사용자 스펙 의도

- Agent Wiki는 작업 중 얻은 조사 자료와 작업 기록을 지정 폴더에 축적하는 위키입니다.
- 폴더 구조는 사용하는 에이전트가 정하고, 문서는 루트 index.md와 관련 지식에 연결합니다.
- 이번 범위는 기본 구조와 저장 위치 설정 CLI입니다. 설정은 `~/.agents/config.wiki.toml`에 저장하고, CLI는 `~/.local/bin/agent-wiki`에 설치할 수 있어야 합니다.
- 실행 시 Python이 필요하지 않은 Rust 단일 바이너리로 설치합니다.
- reader, researcher, writer로 기존 지식 활용·근거 확보·문서 반영 책임을 분리합니다.
- 폴더 트리는 상위 위치를, index.md는 top-down 하위 주제·문서 안내를, 일반 문서는 본문과 의미 있는 관련 참조를 담당합니다. 복귀 링크나 문서→루트 왕복은 요구하지 않습니다.
- 기존 지식 탐색, 사건 기반의 잦은 기록, 작성 시 주변 정리와 작업 종료 시 변경 범위 점검을 적용합니다.
- 위키 루트를 0으로 계산해 폴더 깊이는 최대 4입니다.
- 복합 폴더명은 `<상위>_<하위>`까지만 허용하고 `<상위>_<하위>_<하위2>`는 사용하지 않습니다. 추가 세분화는 실제 하위 폴더로 표현합니다.
- 웹 조사 후 기록 필요성을 항상 판단하되, 실제 기록은 writer의 기준에 따라 새 지식·결정 근거·정정에 한정합니다.
- 지식 분류와 개인정보·작업 기록 같은 공개·백업 경계를 혼동하지 않도록 사용자 정의 named root를 지원합니다.

- 사용자가 과거 작업에 활용한 지식과 판단 근거를 복원해 블로그 작성 등에 활용할 수 있어야 합니다.
- 작업 기록 > 판단별 근거 목록 > 자료 출처·요약을 링크로 연결하며 근거 목록은 작업 기록 안에 둘 수 있습니다.

# Agent Wiki 플러그인 스펙

## 목적과 현재 범위

작업 중 얻은 지식과 경험을 지정된 위키에 연결된 문서로 축적하고 다음 작업에 재사용합니다.
CLI는 named root 저장 위치와 설치를, manager는 조건·진행·완료와 역할 연결을, reader·researcher·writer는 탐색·조사·기억 반영을 소유합니다.
제품 구현, 위키 외부의 임의 기록, 작업 기록의 프로젝트 소유·조건 체크리스트 계약 외 고정 폴더 템플릿, 상시 백그라운드 실행, 백업·공개·동기화 명령, 개인정보 자동 분류, cross-root resolver는 소유하지 않습니다.

## 내장 skill과 사용 기준

- `manager`: 작업과 위키 활용의 기본 진입점입니다. 구체 충족 조건·선행·검증·후속 변경·진행·완료 판단과 임시 작업 기록을 소유하고 필요한 전문 역할만 연결합니다. 제품 구현·범용 실행기·위키 직접 편집은 소유하지 않습니다.
- `reader`: 현재 작업에 필요한 기존 기억·이력·규칙을 읽고 Obsidian CLI의 type·tags 검색으로 후보를 좁혀 본문·적용 범위·근거 공백을 확인합니다. 위키를 수정하지 않습니다.
- `researcher`: 현재 질문의 지식 공백·모순·최신성을 조사하고 CLI로 관련 기존 조사·비교·진단을 재사용하며 출처·적용 조건·불확실성을 반환합니다. 위키를 수정하지 않습니다.
- `writer`: 제공된 지식·사용자 정보·결정·작업 상태를 기억에 반영합니다. 기록 여부·소유 주제·중복·근거 보존·프로젝트 소유 기록·지식 문서 저장, `type`·`tags` 작성·보존과 저장 검증을 소유합니다. 작업 조건 도출·조건 변경·충족 재판정은 소유하지 않습니다.
- manager를 기본 진입점으로 제공하며 각 전문 skill의 직접 호출도 유지합니다. 기존 근거가 충분하면 reader·researcher를 생략하고 writer로 바로 기록할 수 있습니다. 역할의 고정 순서·전체 호출·서브에이전트 실행은 요구하지 않습니다.
- manager는 일반 작업 조건 관리·임시 기록을 단독 수행할 수 있습니다. 위키 읽기·조사·저장이 필요할 때 해당 bundled skill의 runtime을 사용하며, 이 sibling context 의존은 상세 계약 중복과 기억 쓰기 권한 혼합을 피하기 위한 것입니다. 위키 역할이 불가하면 한계를 알리고 독립 작업을 계속합니다.
- reader·researcher·writer는 manager의 사전 로딩이나 작업 기록을 요구하지 않고 단독 실행합니다. 각 runtime은 자체 소유 계약을 dev-only spec 없이 실행 가능하게 포함합니다.
- 세부 계약은 아래 스펙 지도의 소유 문서를 따릅니다. 별도 workflow skill은 두지 않습니다.

## 역할 간 전달과 완료

- manager는 조건·진행·완료와 임시 초안을, writer는 제공 상태 보존·분류·기억 저장·저장 검증을 소유합니다. 작업 완료와 위키 저장 완료를 나누어 보고합니다.
- 작업 기록은 프로젝트가 소유하며 `records/YYYY-MM/000-<slug>.md`로 저장합니다. 의도·조건·상태·근거의 연속성과 과거 판단의 복원 가능성을 유지합니다. 상세 명명·general 분류·재개·이관은 [writer 기록 계약](skills/writer/records.md)을 따릅니다.
- 위키와 제공 근거가 충분하면 반복 조회를 생략하며 필요한 공백만 조사합니다. 과거 설명을 현재 정보로 덮어쓰지 않습니다.
- URL 조사를 독립적으로 분리할 수 있고 위임이 허용된 경우 질문·목적·자료·필요 정보·관련 root·허용 읽기/쓰기 범위·스킬 식별자·반환 계약을 전달합니다. 작은 조사나 충분한 자료에 위임을 강제하지 않으며 총 토큰 절감을 보장하지 않습니다.
- researcher는 읽기 전용으로 근거를 확보합니다. 승인된 저장은 writer 역할에서 수행하고 같은 파일의 쓰기는 직렬화합니다. 반환은 저장 경로·핵심 발견·미해결·저장 상태를 구분하며 상세 근거는 기록에 둡니다. 메인은 필요한 출처를 확인하고 실제 채택·배제 이유를 제공합니다. 자료 담당자가 이를 추측하지 않습니다.

## 스펙 지도

| 소유 문서 | 계약 |
| --- | --- |
| [공통 위키](wiki.md) | root 경계·접근·탐색·구조·연결·권한 |
| [CLI](cli.md) | agent-wiki 설치·설정·조회·실패·빌드·검증 |
| [Obsidian 조회](obsidian.md) | vault/root 매핑·type/tags 검색·출력 판정·역할별 활용 |
| [manager](skills/manager/spec.md) | 구체 조건·진행·완료·임시 기록·역할 전달 |
| [reader](skills/reader/spec.md) | 기존 지식·과거 작업 탐색과 해석 |
| [researcher](skills/researcher/spec.md) | 질문별 근거 확보·상충·최신성 확인 |
| [writer](skills/writer/spec.md) | 기억 선택·분류·문서 속성·상태 보존·기록 저장·검증 |

공통 계약은 각 skill spec의 작성 기준이며 설치 runtime은 필요한 계약을 자체 포함합니다. runtime에서 개발 spec을 요구하지 않습니다.

## 대표 표면

아래 파일 경로는 저장소 루트 기준이며 CLI 명령은 `agent/agent-wiki/`에서 실행합니다.

- `agent/agent-wiki/scripts/src/main.rs`: 설치·저장 위치 설정·조회 CLI 원본입니다.
- `agent/agent-wiki/scripts/build.sh`: Cargo.lock 기준으로 네이티브 바이너리 `agent/agent-wiki/scripts/agent-wiki`를 빌드합니다.
- `agent/agent-wiki/README.md`: 설치 방법, 명령, 설정 형식을 설명합니다.
- `agent/agent-wiki/skills/<manager|reader|researcher|writer>/SKILL.md`: 각 역할의 실행 지침입니다.
- `agent/agent-wiki/.codex-plugin/plugin.json`: CLI와 네 스킬의 선택 기준을 설명합니다.
