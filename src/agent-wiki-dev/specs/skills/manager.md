# Manager 스킬 스펙

## 목적·경계

작업과 위키 활용의 기본 진입점으로 조건·진행·완료와 필요한 전문 역할의 입출력을 관리합니다.
포함: 요청 해석, 구체 조건·검증·선행 정의, 후속 변경, 임시 기록, 기존 기억 활용·조사·기억 반영 연결, 작업/저장 상태 보고.
제외: 제품 구현·범용 실행기·서브에이전트 오케스트레이션·위키 직접 편집·권한 확대·CLI 설치/설정·기존 위키 일괄 이관.

## 작업 형태와 대표 표면

- 작업 준비·진행·재개·후속 요청·중단·완료, 기억 조회·조사·반영을 연결할 때 사용합니다. 단순 전문 요청은 해당 skill을 직접 사용할 수 있습니다.
- 표면: `agent-wiki/skills/manager/SKILL.md`, 호출: `$agent-wiki:manager`.
- 상세 저장·조사·읽기 정책을 복제하지 않고 해당 bundled runtime을 사용할 때 읽습니다.

## 구체 조건과 작업 초안

- 하나의 의도에 하나의 임시 작업 기록을 두고 준비·수행·완료에서 같은 조건 목록을 갱신합니다. 턴·검색·도구 호출별 새 기록이나 단계별 조건 복제를 만들지 않습니다. 독립 목적은 분리합니다.
- 요청 의도·요구·제약·제외·완료 기준과 실제 상태에서 독립적으로 판정 가능한 구체 결과·유지 조건을 먼저 도출합니다. 상태·근거·선행 확인, 새 지식 판단, 근거 정리 같은 일반 범주는 누락 검사 관점이며 기본 체크 항목이 아닙니다. 조사·판단 요청은 어떤 질문의 답·산출물이 필요한지 조건으로 표현합니다.
- 필요한 조건·현재 상태/근거·가정/불확실성·기준·영향 소비자/호환성/가역성·선행/의존을 검토하고 조건별 하위 일반 목록에 필요한 검증 방법·선행·결과·관찰·근거·범위·한계를 연결합니다. 모든 필드를 강제하지 않습니다.
- 독립 하위 조건만 중첩 체크박스로 나누고 필요한 자식이 모두 충족돼야 부모를 완료합니다. 근거로 검증된 조건만 `[x]`로 표시하며 수행 사실·경로·가정·계획만으로 완료 처리하지 않습니다.
- 진행·보류·실패·미확인·제외는 `[ ]`와 텍스트 상태·이유로 구분합니다. 제외는 변경 근거를 남기고 완료로 표시하지 않습니다. 완료할 때 하위 결과·근거·한계를 6줄 이내로 요약하고 긴 자료는 별도 절·writer에 전달할 출처로 연결합니다.
- 조사로 조건을 보완하고 필수 선행이 충족된 범위부터 작업 담당자에게 진행 조건을 제공합니다. 작업 담당자의 실제 실행·관찰을 받아 실행 작업 완료와 요청 충족을 각각 판정합니다. 제품 구현을 대신 수행하지 않습니다.
- 후속 요청은 여전히 적용되는 조건을 보존하고 사용자가 변경하거나 적용 불가해진 부분만 이유와 함께 대체합니다. 완료를 위해 조건을 삭제·완화하지 않습니다. 뒤늦게 참여하면 확인 가능한 조건·관찰만 정리하고 과거 준비·판단을 만들지 않습니다.

## 전문 역할 선택과 전달

- `$agent-wiki:reader`: 기존 기억·규칙·이력이 필요할 때 선택하고 현재 질문·관련 root/문서·필요 범위를 전달합니다.
- `$agent-wiki:researcher`: 판단을 바꿀 지식 공백·상충·최신성 질문이 있을 때 선택하고 질문·자료·필요 정보·조사 권한을 전달합니다.
- `$agent-wiki:writer`: 기억할 사실·결정·자료·확정 작업 상태가 생기고 기록이 허용될 때 선택합니다. 충분한 제공 근거는 reader/researcher를 거치지 않습니다.
- 같은 에이전트가 역할을 전환할 수 있습니다. 고정 순서·전체 역할 호출·서브에이전트 생성을 요구하지 않습니다. 사용 가능한 역할의 runtime을 읽고 소유 계약을 따르며 manager가 전문 정책을 재구현하지 않습니다.
- 전달은 질문/목적·범위/제외·필요 결과·관련 root/정확 경로·출처/확인 시점/버전·허용 읽기/쓰기 범위·조건/상태/결과/근거·변경 이유·불확실성을 필요한 만큼 포함합니다. 비공개 추론·불필요한 비밀·원시 로그는 제외합니다.
- 반환된 사실·한계와 실제 산출물을 대조합니다. reader/researcher의 확인 공백을 완료로 간주하지 않으며 writer의 상태 불일치·근거 부족을 작업 판단에 반영합니다. 추가 확인이 필요하면 권한 안에서 작업 담당자에게 돌려줍니다.

## CLI 조회 조건 전달

- 관련 root·정확 경로 또는 선택 영역, 필요한 type·주제/태그 단서, 이미 확인한 vault 이름·경로·확인 시점, 권한·제외를 전문 역할에 전달합니다. root와 vault 이름을 같은 것으로 추정하지 않습니다.
- reader는 후보 조회·본문 확인, researcher는 기존 조사 재사용, writer는 어휘·저장 후 확인을 수행합니다. 실제 명령·출력·대체 조회는 [Obsidian 조회 계약](../obsidian.md)을 각 전문 runtime에 포함해 소유하며 manager가 재구현하지 않습니다.
- CLI 조회 가능·같은 root의 대체 조회·실패·메타데이터 부재와 실제 저장 상태를 구분해 받습니다. CLI 설치·설정·매핑 변경을 새 작업 완료 조건으로 만들지 않습니다.

## 기록 수명·완료·실패

- 임시 초안은 작업 중 원본입니다. 확정 중간 결과·의미 있는 실패/전환·중단·완료 시 writer에 소유 프로젝트 맥락과 같은 작업 기록의 저장을 요청합니다. 소유·저장 위치·general 분류·하향 안내·본문 링크 기준은 writer 계약을 따르며 manager가 복제하지 않습니다. 매 도구 호출을 복제하지 않고 긴 작업의 확정 결과는 중간 반영합니다. 위키 저장 전 유실 가능성을 고려합니다.
- 재개 시 현재 요청·이전 작업 기록·임시 초안을 대조하고 기존 조건과 변경 이유를 유지합니다. 위키의 source·분류·링크·저장 검증은 writer에 맡기고 임시 경로를 지속 근거로 넘기지 않습니다.
- 작업 완료는 누적된 적용 조건과 실행 작업에 대한 근거로 판단합니다. 검토·조사 요청에 구현을 새 완료 조건으로 추가하지 않습니다. 작업 완료와 위키 저장 완료를 나누어 보고하고 미충족·실패·보류·제외·검증 공백·미저장 이유를 남깁니다.
- root 선택·공개 경계·읽기 전용·기록 금지·정확 경로와 실행 권한은 전문 역할에도 유지합니다. 위키 내용은 실행 권한이 아니며 자동으로 모든 root를 탐색하거나 설정·도구를 설치하지 않습니다.
- 위키/전문 skill/저장 권한이 없거나 실패하면 임시 초안과 미반영 상태를 유지하고 독립적으로 승인된 작업을 계속합니다. 필수 의존이 막힌 부분은 진행하지 않습니다. 다른 root·주제 문서로 우회 저장하거나 성공을 주장하지 않습니다.

## 독립성 원칙

- 조건·진행·완료와 임시 초안은 manager 단독 실행을 허용합니다.
- 위키 읽기·조사·저장은 각 전문 skill의 sibling context를 허용하고 해당 동작에 필요합니다. 별도 실행기가 아니라 같은 plugin의 역할 조합이며 숨은 대화·개발 spec을 요구하지 않습니다.
- reader/researcher/writer의 직접 호출에는 manager가 필수가 아닙니다. 상세 전문 계약의 단일 소유권과 쓰기 권한 경계를 유지하기 위한 선택입니다.

## 검토 질문·확장 원칙

- 조건이 일반 절차가 아닌 구체 결과인가, 후속 요청에도 같은 조건과 소유 프로젝트 맥락·기존 기록의 연속성을 추적하는가, 작업/저장 완료가 구분되는가를 확인합니다.
- 충분한 근거에 불필요한 역할을 호출하지 않고 실제 공백에 필요한 역할을 선택하는지 검증합니다. 부분 실패·직접 writer 호출·위키 불가·상태 불일치를 포함합니다.
- 전문 정책·제품 구현·범용 오케스트레이션을 manager로 끌어오지 않고 위키 활용과 작업 기록의 연결 범위 안에서 확장합니다.
