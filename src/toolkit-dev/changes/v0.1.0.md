# toolkit-dev v0.1.0 Change Spec

## 변경사항 요약

- 로컬 개발 CLI 운용을 소유하는 `toolkit-dev` plugin을 정의합니다.
- 첫 skill로 Apple `container` CLI cheatsheet와 안전·호환성 계약을 제공합니다.
- 설치, 제거, containerization 개념을 조건부 runtime reference로 분리합니다.
- experimental `container k8s` plugin의 local cluster lifecycle과 third-party Kubernetes CLI 비목표를 추가합니다.
- 신규 `git` skill로 task-scoped commit, risk-proportional supporting check, message 위생, commit granularity, 120자 미만 subject·commit type·post-commit full-message 검증, branch, `git switch -C` force-create, push workflow와 조건부 branch convention·recovery reference를 제공합니다.
- repository marketplace에 `toolkit`을 등록하고 local development install로 노출을 확인합니다.

## 변경 목적

Codex가 Apple `container`와 Git처럼 작업 대상이 분명한 로컬 개발 CLI를 도구별 계약으로 운용하도록 독립적인 plugin 경계를 제공합니다.
각 skill은 고빈도 정상 흐름을 즉시 제공하고 조건부 호환성·정책·복구 세부사항만 runtime reference로 라우팅합니다.

## 릴리즈 노트 기준

- 독자에게 보이는 변화: `$toolkit:apple-container`로 Apple `container` workflow를, `$toolkit:git`으로 task-scoped commit·branch·push workflow를 사용할 수 있습니다.
- 호환성 영향: 기존 plugin과 skill 호출에는 영향이 없습니다.
- migration 필요 여부: 없습니다.
- 운영자/사용자가 알아야 할 검증 결과: release surface에는 runtime skill과 references만 포함되며 repository marketplace의 `toolkit` 항목이 `./toolkit`을 가리킵니다.

## 기록 근거

- 관련 커밋: 미정
- 관련 세션 기록: 현재 사용자 요청

## 변경 상세

### Toolkit Plugin 경계

- 목적: CLI 자체가 작업 대상인 reusable guidance를 `advance-codex`와 분리합니다.
- 범위: manifest, README, plugin spec.
- 관련 표면: `src/toolkit-dev/`.
- 검증: manifest, README, plugin spec이 실제 `apple-container`, `git` surface와 각 선택 기준만 노출해야 합니다.

### Apple Container Runtime Surface

- 목적: 직접 실행 명령과 조건부 상세 문서를 progressive disclosure로 제공합니다.
- 범위: `SKILL.md`, `references/installation.md`, `references/uninstallation.md`, `references/concepts.md`.
- 관련 표면: `src/toolkit-dev/skills/apple-container/`.
- 검증: runtime routing link가 모두 존재하고 서로 책임을 중복하지 않아야 합니다.

### Kubernetes Plugin Surface

- 목적: bundled `container k8s` plugin을 local development cluster lifecycle로 설명하고 Kubernetes client workflow와 분리합니다.
- 범위: `SKILL.md`, `references/kubernetes.md`, skill spec, README, manifest usage guidance.
- 관련 표면: `src/toolkit-dev/skills/apple-container/`.
- 검증: plugin availability와 plugin 전용 help syntax를 확인하고, `kubectl` 등 third-party CLI를 설치·실행 계약으로 포함하지 않아야 합니다.

### Git Runtime Surface

- 목적: commit, branch, push를 분리된 skill이 아니라 선택적으로 조합 가능한 하나의 Git workflow로 제공합니다.
- 범위: `SKILL.md`, `references/branch-conventions.md`, `references/recovery.md`, skill spec, README, manifest usage guidance.
- 관련 표면: `src/toolkit-dev/skills/git/`, `src/toolkit-dev/specs/skills/git.md`.
- 검증: 정상 workflow와 치트시트는 `SKILL.md`가 소유하고 prefix policy와 실패·중단 복구만 조건부 reference로 라우팅해야 합니다. commit은 risk에 맞는 supporting check, skip·unavailable reporting, message 위생, related change unit 단위 granularity를 적용해야 합니다. subject는 120자 미만이며 staged scope에 맞는 지원 type을 사용하고, commit 후 실제 full message를 expected message·applicable convention과 대조해야 합니다. `git switch -C`는 exact branch·start point·기존 ref·worktree 확인과 명시적 force-create 권한을 요구해야 합니다.

### Marketplace 및 개발 설치

- 목적: 생성된 release surface를 repository marketplace에서 발견하고 local Codex 설치로 검증합니다.
- 범위: `.agents/plugins/marketplace.json`, local marketplace 등록, `toolkit@opnay-plugins` install.
- 관련 표면: `.agents/plugins/marketplace.json`, `toolkit/`.
- 검증: 기존 marketplace 순서를 유지하고 `toolkit`을 마지막에 추가하며 path·policy·category와 설치 상태를 확인해야 합니다.

## 비목표

- Docker Desktop, Podman, Compose compatibility shim을 설치하거나 번들하지 않습니다.
- `kubectl`, Helm, Kustomize 등 third-party Kubernetes CLI를 설치·실행하거나 workload management를 소유하지 않습니다.
- CLI 전체 manual을 저장소에 복제하지 않습니다.
- 기존 plugin의 skill을 이번 version에서 이동하지 않습니다.
- 기존 `advance-codex:git-committer`를 수정·제거하거나 신규 `git` skill의 runtime dependency로 만들지 않습니다.
- 기존 compact message-file gate, 기존 post-operation 확인, recovery의 부분 성공·남은 상태 보고는 유지합니다. post-commit full-message 검증은 포함하되, allocator의 nonzero·경로 유무·unexpected output별 상세 분기, cleanup의 exit-only 판정·추가 file test 금지, main post-commit의 unrelated-state 확인 강화는 포함하지 않습니다.
- 기존 marketplace 항목을 재정렬하지 않습니다.

## 호환성 및 마이그레이션

- 신규 plugin surface 안의 skill 추가이므로 기존 호출자 migration은 없습니다.
- dev manifest는 `toolkit-dev`, build output manifest는 `toolkit` 이름을 사용합니다.

## 검증 기준

- dev와 release `apple-container` skill이 canonical `quick_validate.py`를 통과해야 합니다.
- dev와 release `git` skill이 canonical `quick_validate.py`를 통과해야 합니다.
- `pnpm build:plugin toolkit [--force]`가 통과해야 합니다.
- dev와 release manifest JSON이 파싱되고 name 변환과 version `0.1.0`이 일치해야 합니다.
- release root에 `specs/`와 `changes/`가 없어야 합니다.
- `SKILL.md` 하단 routing link가 `kubernetes.md`를 포함한 네 runtime reference를 정확히 가리켜야 합니다.
- `git/SKILL.md`가 commit·branch·push 치트시트와 `branch-conventions.md`, `recovery.md` routing을 포함해야 합니다.
- `git` runtime은 120자 미만 subject와 `feat`, `fix`, `refactor`, `docs`, `test`, `perf`, `style`, `build`, `ci`, `chore` type 선택 기준을 포함해야 합니다.
- `git` runtime은 docs·code supporting check 선택, failed·skipped·unavailable 구분, skip 근거·residual risk, message hygiene, one-related-change-unit granularity를 포함해야 합니다.
- `git` runtime은 commit 성공·cleanup 뒤 actual hash·full message를 읽고 expected message·applicable convention과 대조하며, mismatch를 자동 amend·reset·rollback하지 않아야 합니다.
- 기존 compact allocation·exact-path cleanup과 message hygiene을 위한 pre-commit readback, 기존 `status`·branch 확인, recovery의 partial-success remaining-state reporting은 유지돼야 합니다. allocator output별 상세 실패 분기, cleanup 판정 강화, main post-commit unrelated-state reporting은 추가되지 않아야 합니다.
- `git switch -C <branch> <start-point>`는 일반 `-c`와 구분되고 `--force`, `--discard-changes`, branch 삭제 권한으로 확장되지 않아야 합니다.
- `git` runtime은 refspec source·destination을 구분하고 일반 push 요청에서 `wip:main` mapping을 추론하지 않아야 합니다.
- 신규 `git` dev·release runtime이 일치하고 기존 `advance-codex` dev·release surface는 변경되지 않아야 합니다.
- installation과 uninstallation은 공식 signed package와 bundled script 경로를 사용해야 합니다.
- `container k8s` 예시는 설치된 1.2.2 plugin help와 일치하고 experimental status, kubeconfig mutation, third-party CLI 제외를 보존해야 합니다.
- marketplace JSON이 파싱되고 `toolkit.source.path=./toolkit`, `AVAILABLE`, `ON_INSTALL`, `Developer Tools`가 유지되어야 합니다.
- local `opnay-plugins` marketplace와 `toolkit@opnay-plugins` 설치 상태를 확인해야 합니다.
- `git diff --check`가 통과해야 합니다.

## 정식 규칙 승격 여부

- normative spec으로 승격할 지속 규칙: plugin 경계, skill 실행·호환성·routing 계약
- change spec에만 남길 release/migration 이력: 신규 `0.1.0` 생성과 초기 surface 구성
