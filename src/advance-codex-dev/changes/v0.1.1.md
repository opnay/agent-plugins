# advance-codex-dev v0.1.1 Change Spec

## 변경사항 요약

- session artifact guidance를 date-scoped `.agents/sessions/{YYYYMMDD}/` convention으로 정리한다.
- `session-manager`, `agents-sessions`, subagent runtime skill, `tool-use-guide`처럼 중복되거나 선택성이 낮은 runtime surface를 제거한다.
- `skill-scenario-testing`, `skill-creator`, `git-committer`, `plugin-creator`, `optimize-token`의 역할과 사용 표면을 정리한다.
- `git-committer`의 메시지 전달을 임시 파일 생성 > `git commit -F <file>` > 파일 정리 gate로 고정한다.
- `git-committer`의 별도 commit 승인 gate를 제거하고, PR 같은 상위 작업 요청에 포함된 commit을 재승인 없이 실행한다.
- `git-committer` 메시지 파일 gate에서 allocator 직후와 cleanup 직전의 반복 file type 검사를 제거한다.
- `notion-memory` spec, runtime, reference, script, usage surface를 최종 bundle에서 제외하며 그 책임을 sibling skill로 이전하지 않는다.
- `optimize-token`은 추가 설정 없이 가장 짧고 안전한 표현을 쓰는 단일 압축 계약과 `의미 맥락 보존` 기준을 둔다.
- `pro-*` role judgment skill은 `judgment-kit`으로 분리하고 `advance-codex`에서는 제공하지 않는다.

## 변경 목적

`v0.1.1`은 `advance-codex`를 Codex surface 제작, 평가, 커밋, 토큰 최적화 중심 플러그인으로 좁히는 변경입니다.
role-based judgment는 `judgment-kit`이 소유하며, agent work memory 책임은 이 bundle에서 제공하지 않습니다.

## 릴리즈 노트 기준

- 독자에게 보이는 변화: `advance-codex`는 creator, scenario testing, commit, optimize-token 중심으로 노출된다.
- 호환성 영향: 기존 `$advance-codex:pro-*` 호출자는 `$judgment-kit:pro-*`로 옮겨야 한다. 개발 채널의 `notion-memory` 호출은 대체 없이 제거된다.
- migration 필요 여부: pro 계열 skill 호출 prefix 변경이 필요하다. `notion-memory`는 `main`에 배포되지 않았으므로 공개 migration은 없다.
- 운영자/사용자 참고: release surface에는 `specs/`, `changes/`가 없어야 하며 manifest prompt는 실제 제공 skill만 언급해야 한다. plugin build나 upgrade는 사용자 설정, 설치 cache, Notion 데이터·페이지를 자동 삭제하지 않는다.

## 변경 상세

### Session Surface 정리

- 목적: `advance-codex`에는 session artifact 위치에 대한 문서 수준 convention만 남긴다.
- 범위: README, plugin spec, manifest prompt.
- 관련 표면: `.agents/sessions/{YYYYMMDD}/` 설명.
- 검증: runtime skill source와 release surface에 `session-manager`와 `agents-sessions` runtime skill이 없어야 한다.

### Runtime Skill 제거

- 목적: `advance-codex`의 범위를 Codex surface 제작과 운영 품질 도구로 좁힌다.
- 범위: `session-manager`, `agents-sessions`, subagent runtime skill, `tool-use-guide` 제거.
- 관련 표면: `skills/`, `specs/skills/`, README, plugin spec, manifest prompt.
- 검증: dev/release surface와 manifest prompt에 제거된 skill 노출이 없어야 한다.

### Creator/Testing/Commit/Token Surface 정리

- 목적: 남는 skill의 시작 기준과 책임을 manifest, README, plugin spec에 맞춘다.
- 범위: `skill-creator`, `plugin-creator`, `skill-scenario-testing`, `git-committer`, `optimize-token`.
- 관련 표면: runtime skill, skill spec, plugin usage surface.
- 검증: 각 skill이 자기 spec과 runtime surface에 존재하고, dev-only spec 경로를 runtime 실행 지시로 남기지 않아야 한다.

### Git Commit Message File Gate

- 목적: Bash heredoc/EOF와 stdin 조합에서 생길 수 있는 shell 해석 오류와 예기치 않은 script 실행을 막는다.
- 범위: `git-committer` intent, workflow, message, verification spec과 runtime skill, command reference.
- 관련 표면: `src/advance-codex-dev/specs/skills/git-committer/`, `src/advance-codex-dev/skills/git-committer/`.
- 계약: 신뢰된 allocator의 전용 임시 파일 생성, non-shell 파일 쓰기, readback, final staged diff, `git commit -F <file>`, exact path cleanup과 부재 확인을 순서대로 수행한다. allocator 직후와 cleanup 직전에는 file type을 반복 확인하지 않는다.
- 검증: runtime과 reference에 heredoc/EOF, here-string, command substitution, `git commit -F -`, 여러 `-m`을 허용하는 경로가 없어야 한다.

### Git Commit 실행 진입 단순화

- 목적: commit을 포함하는 상위 작업 요청에서 불필요한 commit-specific 재승인을 요구하지 않는다.
- 범위: `git-committer` intent, workflow, runtime skill, README, plugin spec, manifest prompt.
- 계약: 직접 commit 요청이나 `PR 올려놔`처럼 완료에 commit이 필요한 상위 요청은 별도 commit 승인 gate 없이 task-scoped commit finalization으로 이어진다. commit 포함 여부를 결정하는 상위 요청 해석과 push, PR, release, publish, version bump 실행은 이 skill이 소유하지 않는다.
- 검증: dev/release runtime에 explicit commit approval 또는 commit execution authority 단계가 없어야 하며, 상위 PR workflow의 commit 단계에 사용할 수 있어야 한다.

### Notion Memory 최종 Bundle 제외

- 목적: `notion-memory`를 최종 `advance-codex` bundle에서 제외하고 관련 책임을 sibling skill에 이전하지 않는다.
- 범위: `notion-memory` skill spec과 runtime 폴더 전체, README, plugin spec, manifest 설명·keyword·prompt.
- 배포 상태: 해당 skill은 `main`에 배포되지 않았으므로 공개 사용자 migration은 없다.
- 개발 채널: `$advance-codex-dev:notion-memory`와 개발 채널의 `$advance-codex:notion-memory` 호출은 대체 없이 제거한다.
- 보존: plugin 변경은 사용자 설정 원본, 설치된 Codex cache, Notion DB·페이지·데이터를 자동 삭제하지 않는다. 기존 설치 cache에서는 다음 plugin upgrade 전까지 stale skill이 보일 수 있다.
- 검증: dev/release에 관련 spec·runtime 경로가 없어야 하며, 이 철거 기록을 제외한 활성 README, manifest, plugin spec, runtime에서 관련 호출, Notion, `ntn` 계약이 없어야 한다.

### Optimize Token 단일 압축 계약

- 목적: `optimize-token`이 추가 설정 없이 의미와 문법이 허용하는 가장 짧고 안전한 표현을 사용하게 한다.
- 범위: `optimize-token` spec, runtime skill, 고정 압축 시나리오, AGENTS 호출 규격.
- 관련 표면: `src/advance-codex-dev/specs/skills/optimize-token/`, `src/advance-codex-dev/skills/optimize-token/`.
- 압축 계약: 필드형, 한 줄, 압축 표, 목록 묶음 중 가장 짧고 명확한 형태를 우선하되 원인/증거, 순서/의존성, 범위/비목표, 확인/미확인, source/evidence 구분, 검증 한계, 승인 경계, 위험, 정확한 식별자를 보존한다.
- 저장 작성물: 별도 축을 두지 않고 동일 계약을 적용하며 현재 상태, 실행 가능성, 지속 계약을 보존한다.
- 호환성: `$advance-codex:optimize-token extreme` 호출은 `$advance-codex:optimize-token`으로 바꾼다. 강도 인자, 선택 질문, 강도별 reference는 지원하지 않는다.
- 검증: 고정 시나리오와 fresh executor가 의미 맥락 보존, 단일 출력, 저장 작성물 계약을 충족해야 한다.

### Role Judgment 분리

- 목적: product planning, engineering, design judgment를 `judgment-kit`의 coherent bundle로 분리한다.
- 범위: `pro-planner`, `pro-engineering`, `pro-designer` runtime skill과 folder-based spec을 `judgment-kit-dev`로 이동한다.
- 관련 표면: `src/judgment-kit-dev`, root `judgment-kit`, marketplace entry.
- 검증: `advance-codex` dev/release surface에 `pro-*` skill과 spec이 없어야 한다.

## 비목표

- flow record 생성/갱신 규칙을 복제하거나 재정의하지 않는다.
- 제거된 runtime skill 책임을 다른 sibling skill에 그대로 흡수하지 않는다.
- `advance-codex`를 일반 제품 구현 workflow나 역할 기반 판단 플러그인으로 넓히지 않는다.
- 사용자 설정 원본, 설치된 Codex cache, Notion DB·페이지·데이터를 plugin 철거 과정에서 자동 삭제하지 않는다.
- `judgment-kit`의 `pro-*` runtime 판단 계약을 이번 change spec에서 새로 설계하지 않는다.

## 호환성 및 마이그레이션

- `$advance-codex:optimize-token extreme` 대신 `$advance-codex:optimize-token`을 사용한다.
- 이번 변경은 기존 `v0.1.1` 승격 주기의 후속 변경이므로 version을 추가로 올리지 않는다.
- `$advance-codex:pro-planner` 대신 `$judgment-kit:pro-planner`를 사용한다.
- `$advance-codex:pro-engineering` 대신 `$judgment-kit:pro-engineering`을 사용한다.
- `$advance-codex:pro-designer` 대신 `$judgment-kit:pro-designer`를 사용한다.
- 개발 채널의 `$advance-codex-dev:notion-memory`와 `$advance-codex:notion-memory`는 대체 없이 제거한다.
- `notion-memory`는 `main`에 배포되지 않았으므로 공개 호출 migration은 없다.

## 검증 기준

- `src/advance-codex-dev/skills/`와 `src/advance-codex-dev/specs/skills/` 아래에 `pro-*`와 `notion-memory`가 없어야 한다.
- `advance-codex/skills/` 아래에 `notion-memory`가 없어야 한다.
- 철거 기록인 이 파일을 제외한 dev/release README, manifest, plugin spec, runtime에서 `notion-memory`, Notion, `ntn` 계약이 없어야 한다.
- dev/release의 남은 skill은 `git-committer`, `optimize-token`, `plugin-creator`, `skill-creator`, `skill-scenario-testing`이며 manifest prompt와 일치해야 한다.
- 남은 dev/release skill 전체가 canonical `quick_validate.py`를 통과해야 한다.
- `optimize-token` dev/release skill에 legacy mode 이름·설정 문구와 제거된 reference가 없어야 한다.
- `pnpm build:plugin advance-codex --force`가 통과해야 한다.
- dev/release manifest와 marketplace JSON이 파싱되고, manifest name과 version `0.1.1`, marketplace path·policy·순서가 유지되어야 한다.
- `advance-codex/specs`와 `advance-codex/changes`가 없어야 한다.
- `git diff --check`가 통과해야 한다.
- dev/release `git-committer`가 메시지 파일 생성 > readback > `git commit -F <file>` > cleanup gate를 동일하게 포함해야 한다.
- dev/release command reference에는 allocator 직후나 cleanup 직전의 file type 검사 명령이 없어야 하며, `unlink` 후 `test ! -e`와 `test ! -L`만 실행해야 한다.
- dev/release `git-committer`에 heredoc/EOF, here-string, command substitution, `git commit -F -`, 여러 `-m`을 허용하는 예시가 없어야 한다.
- dev/release `git-committer`에 별도 commit-specific 승인 gate가 없어야 하며, PR 같은 상위 workflow에 포함된 commit을 처리한다고 명시해야 한다.

## 정식 규칙 승격 여부

- normative spec으로 승격할 지속 규칙: `advance-codex-dev/specs/plugin.md`는 Codex surface 제작, 평가, 커밋, 토큰 최적화 중심 경계를 소유한다. `optimize-token` skill spec은 추가 설정 없는 최대 안전 압축과 저장 작성물을 포함한 단일 보존 계약을 소유한다. `git-committer` skill spec은 별도 commit-specific 승인 gate 없는 요청 범위 진입과 commit message의 파일 생성 > `git commit -F <file>` > cleanup gate를 소유한다.
- change spec에만 남길 release/migration 이력: `pro-*` skill을 `judgment-kit`으로 분리한 호출 prefix 변경과 미배포 `notion-memory`의 최종 bundle 제외.
