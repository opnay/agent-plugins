# optimize-token 스킬 스펙

## 목적

`optimize-token`은 응답, 진행·상태·검증·승인 문구, 판단 문구, 저장 작성물을 정확성과 의미 맥락이 허용하는 가장 짧고 안전한 형태로 압축하는 skill입니다.

## 경계

- 포함: 에이전트가 생성하는 문구와 저장 작성물의 압축, 의미 맥락·검증 상태·승인 경계·지속 계약 보존
- 제외: context/session 압축, prompt rewriting, 코드 minification, 오류·API·식별자·경로·명령어·안전 고지의 임의 축약

## 대표 표면

- runtime: `advance-codex-dev/skills/optimize-token/SKILL.md`
- 사용자 의도: `intent.md`
- 고정 예시 검증: `intent-scenarios/compression.md`

## 핵심 계약

- 호출 시 추가 설정 없이 가장 짧고 안전한 결과를 적용합니다.
- 삭제 가능한 인사말·요청 재진술·반복·약한 추측·결정에 영향 없는 과정 설명부터 줄입니다.
- 결과 또는 행동을 먼저 두고, 필요한 증거와 다음 행동 또는 위험을 이어 둡니다.
- 의미와 문법을 보존하는 후보가 여럿이면 토큰이 가장 적은 결과를 선택합니다.
- 자연문을 유지하기 전에 표준 문법 축약과 필드형·한 줄 형식을 먼저 검토합니다. 반복 행은 압축 표, 반복 라벨은 목록 묶음으로 줄입니다.
- 자연문이 더 짧거나 관계를 더 명확히 보존하면 라벨화를 강제하지 않습니다.
- 필드값·표 셀·목록 속성값의 결측값은 `-`로 쓸 수 있습니다. 자연문 중간의 대체 표현으로는 쓰지 않습니다.
- 압축이 관계나 판단 기준을 숨기면 필요한 구절만 자연스럽게 확장하고 메타 설명은 덧붙이지 않습니다.

## 의미 맥락 보존

`의미 맥락`은 제거하거나 합쳤을 때 사용자의 판단, 다음 행동, 승인 여부, 위험 이해, 검증 해석이 달라질 수 있는 정보입니다.

- 원인과 증거, 순서와 의존성, 범위와 비목표를 필요한 만큼 분리합니다.
- source of truth와 생성물, 외부·위임 증거와 주 실행자의 판단을 혼동하지 않습니다.
- 확인·미확인 범위, 실패·건너뜀·미실행·불충분 검증, 불확실성, 막힘, 승인 상태와 경계, 남은 위험, 다음 행동을 보존합니다.
- 요청된 섹션과 형식, 경로, 명령어, 식별자, 날짜, 버전, 수치, public API 이름, 활성 언어와 말투를 정확히 보존합니다.
- 보안·개인정보·법률·의료·금융처럼 안전 판단에 필요한 조건과 예외를 줄이지 않습니다.

## 저장 작성물

- 현재 상태와 지속 계약만 남기고 작성 과정, 폐기된 후보, 불필요한 배경, 중복 계약은 줄입니다.
- 대화 없이도 실행·검증·승인·판단할 수 있도록 적용 조건, 순서, 의존성, 제외 범위, rollback 조건, source of truth, 증거 출처, 확인 범위와 한계를 보존합니다.
- 저장물의 요청 형식과 정확한 리터럴을 유지합니다.

## 실패 조건

- 짧아진 결과가 더 모호하거나 비문입니다.
- 원인·증거, 순서·의존성, 범위·비목표, source·생성물 관계가 합쳐져 다른 판단을 유도합니다.
- 실패, 미실행, 검증 한계, 승인 경계, 위험 또는 다음 행동이 숨겨집니다.
- 정확한 식별자나 필수 형식이 바뀝니다.
- 저장 작성물이 현재 상태와 다르거나 단독으로 실행할 수 없습니다.

- 제거된 정보가 판단, 행동, 승인, 위험 이해, 검증 해석을 바꿉니까?
- 압축 형식이 필요한 관계나 출처 구분을 숨깁니까?
- 저장 작성물만 읽어도 현재 계약을 실행하고 검증할 수 있습니까?

## 독립성 및 확장 원칙

- runtime은 sibling skill, 외부 plugin, dev-only spec에 의존하지 않고 독립 실행됩니다.

- 회귀 예시는 `intent-scenarios/compression.md`에 단일 기대 출력과 보존 기준으로 추가합니다.
