# 0.1.0 변경 기록

## 변경사항 요약

- manager가 작업 조건·진행·완료를 관리하고 reader·researcher·writer가 기억 조회·조사·저장을 담당합니다.
- 작업 기록은 `Projects/<project>/records/`에 저장하며, 특정 프로젝트가 없는 일반 작업은 `Projects/general/records/`에 둡니다.
- 설정은 named root 형식을, root 등록은 `set <name> <directory>`를 사용합니다. 이전 기록 배치·단일 `root` 설정·`set <directory>` 하위호환은 제공하지 않습니다.
- 문서의 주제 소속·역할을 판단하고 인덱스의 하향 안내와 개념·근거·판단 중심 본문 참조를 유지합니다.
- writer가 문서 유형 `type`과 평면 키워드 `tags`를 작성·갱신하고 기존 속성·본문을 보존합니다.
- 본문 PR 참조는 종류·번호가 붙은 식별자를 인라인 코드로 표시하고 실제 링크에서도 같은 표시명을 사용합니다.
- 등록된 Obsidian vault의 CLI를 reader·researcher의 유형/태그 조회와 writer의 어휘·저장 확인에 연결하고 manager가 대상·조건을 전달합니다.

## 변경 상세

작업 조건 관리와 기억 저장의 책임을 구분하고, 기록 위치·설정 형식을 하나의 계약으로 유지해 탐색·갱신 경로를 일관되게 합니다.

### 역할과 작업 기록

manager는 구체 충족 조건·변경 이유·결과·검증 한계를 관리합니다. writer는 전달된 상태와 근거를 보존하고 분류·실제 저장을 검증하며 작업 완료를 재판정하지 않습니다. 전문 스킬을 직접 사용할 수 있고 고정 호출 순서나 서브에이전트 실행은 필요하지 않습니다.

새 기록과 후속 기록 모두 프로젝트 소유 위치를 사용합니다. 같은 의도는 같은 기록으로 이어가며 소유가 불분명한 작업을 general에 임의 분류하지 않습니다. 미지원 위치의 기록은 이관 필요를 알리고, 이관 권한 없이 이전 위치 갱신·이동·복제하지 않습니다.

### 지식 분류와 연결

writer는 개요·버전·패턴·사례·작업 기록의 역할과 주제 소속을 먼저 판단합니다. 실제 내용에 맞는 주제 폴더를 구성하며 빈 구조·중복 요약·기계적인 세분화를 만들지 않습니다.

인덱스는 하위 영역과 문서를 안내합니다. 본문 링크는 개념 이해·주장의 근거·선택과 적용 조건의 판단에 필요할 때 사용합니다. 같은 작업이나 프로젝트에 속한다는 이유만으로 연결하지 않으며 복귀 링크·기계적 상호 링크·고정 근거 문서 사슬은 요구하지 않습니다.

과거 기록은 당시 조건·판단·주요 시도·실패·결과·한계를 근거와 함께 복원할 수 있어야 합니다. 근거 요약은 같은 문서에 둘 수 있고 임시 경로는 지속적인 근거로 사용하지 않습니다. 웹 조사 후 새 지식·결정 근거·정정은 반영하고 단순 탐색·중복은 생략합니다.

### 문서 속성

일반 문서·작업 기록은 YAML frontmatter의 `type` 문자열과 `tags` 문자열 목록으로 문서 성격과 검색 키워드를 표현합니다. 폴더의 소유 위치·본문 링크의 의미 관계는 유지합니다. 기존 문서는 승인된 갱신 범위에서 보완하며 전체 위키 정규화는 별도 작업입니다.

### Obsidian 조회 연계

reader·researcher는 root와 경로가 일치하는 등록 vault에서 type·tags 후보 검색 후 본문 근거를 확인합니다. writer는 관련 어휘와 저장 후 속성을 조회하고 manager는 대상·조건을 전달합니다. 출력 의미·자료형·실패와 메타데이터 부재를 구분하며 같은 root의 파일 대체 조회를 유지합니다. 기존 유형·태그 작성과 코드로 표시한 PR 참조 계약도 유지합니다.

### 설정과 CLI

- 설정 위치: `~/.agents/config.wiki.toml`. 형식은 `default`, named `roots`의 `path`와 선택 `description`입니다.
- 명령: `set <name> <directory>`, `default <name>`, `list`, `path [name]`, `install [--force]`입니다.
- root는 백업·공개·동기화 경계입니다. 경로 중복·상하 중첩과 root 간 Markdown 의존성을 허용하지 않습니다.
- 설정 파일이 심볼릭 링크이면 링크는 유지하며 실제 대상 파일을 조회·갱신합니다. 끊어진 링크와 미지원 설정은 변경하지 않고 실패합니다.

## 호환성·적용 범위

구형 단일 `root` 설정과 `set <directory>`는 거부하며 기존 설정 바이트를 보존합니다. 프로젝트 기록 영역 밖의 배치도 지원하지 않습니다. 구형 설정·배치의 위키에는 설정 갱신과 기록 이관이 필요하며 자동 변환·이동은 수행하지 않습니다.

작업 기록 외 지식 배치는 소유 주제의 관례를 따릅니다. 루트 0 기준 폴더 깊이 4·밑줄 복합 폴더명 두 부분 제한과 기존 읽기/쓰기 권한 경계를 유지합니다. 위키 이관·실제 환경 설치·Git 발행은 플러그인 변경과 별도 작업입니다.

## 검증

- Rust CLI 테스트 13개, 로컬 debug build, skill validator 3개, JSON 파싱·변경 Markdown 링크·서식 검사를 통과했습니다.
- 독립 read-only 검토로 spec·runtime·README·CLI 정합성을 확인했습니다.
- 일반 기록 갱신·미지원 기록 배치의 고정 모의 사례 2개에서 스킬 포함 실행이 계약을 충족했습니다. 단일 읽기 전용 모의 실행이며 실제 저장·행동 안정성·자동 선택 효과는 검증하지 않았습니다.
