- 프로젝트 특성에 맞는 패턴과 맥락에 따른 용어·색·패턴의 반복을 유지한다.

# web-designer 스킬 스펙

## 목적과 경계

- 페이지의 정보 전달, 탐색, 웹 레이아웃·반응형 표현을 소유한다.
- 소개 사이트·랜딩·콘텐츠 페이지·웹 화면 구성에 적용한다. 반복 과업·상태 설계가 중심이면 product 관점과 구분한다.
- 일반 코드 구현, 제품 범위 결정, 배포·게시를 소유하지 않는다.
- 대표 표면: `design-kit/skills/web-designer/SKILL.md`.

## 핵심 처리 계약

- 사용자·방문 목적·진입 경로·콘텐츠·주요 행동·기존 디자인 시스템을 확인한다.
- 정보와 행동 우선순위에서 페이지 구조를 정한다. 모든 페이지를 hero와 카드 모음으로 고정하지 않는다.
- 페이지, 섹션, 그룹, 요소 위계와 navigation·본문·보조·상태 영역을 설계한다.
- 그리드·정렬·폭·간격·타이포·이미지를 실제 콘텐츠와 읽기 순서에 맞춘다.
- viewport가 바뀌면 의미·읽기 순서·주요 행동을 유지하며 재배치한다. 고정 요소의 가림, overflow, 긴 문구·지역화를 확인한다.
- 링크·버튼·폼의 의미, 라벨·오류·빈 상태·피드백, keyboard·focus·조작 목표를 확인한다.
- 웹 표현에서 이미지 비율·crop·대체 텍스트·레이아웃 안정성·과한 효과의 성능을 고려한다.
- 같은 용어·행동·색·반복 모듈의 규칙을 유지한다. 섹션 맥락으로 생략한 문구는 독립 카드·알림·모바일 재배치에서 필요하면 복원한다.
- 표현 선택은 메시지·사용성·브랜드 목표의 근거를 갖는다. 전환율 개선은 검증 전 가설이다.

## 출력과 검토 질문

- 페이지 구조·반응형 규칙·중요 표현 결정·필요 상태·검증 범위를 제공한다.
- 재사용할 프로젝트 패턴은 적용 조건·반복 규칙과 함께 제안한다. 기록은 공통 프로젝트 계약을 따른다.
- 방문자가 위치·메시지·다음 행동을 이해하는가? 화면 크기·내용 길이·입력 방식이 바뀌어도 가능한가?

## 독립성·확장

- bundle 내 직접 실행 가능. 프로젝트 맥락 reference와 design-base의 공간·타이포·표면, 반복 reference를 명시적으로 읽는다.
- 색·상호작용 이론은 해당 결정이 있을 때 추가로 읽는다. base skill 선행 호출은 필요 없다.
- 새 기준은 웹 페이지의 전달·탐색·적응 문제에 연결한다.
