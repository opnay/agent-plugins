# Color Criteria

## 정의

Color는 색상 시스템과 색감이 사용자 이해, 상태 의미, 접근성을 돕는지 판단하는 별도 표현 기준입니다.

## 기준

- 색상 역할: primary, secondary, accent, neutral, background, surface, border, text, destructive 같은 역할이 분명해야 합니다.
- 의미 색상: success, warning, error, info, selected, disabled 같은 상태색은 제품 전체에서 같은 의미로 쓰여야 합니다.
- 위계와 강조: 강조색은 핵심 행동과 중요한 정보에 우선 배정하고, 여러 강조색이 서로 경쟁하지 않아야 합니다.
- 대비와 접근성: 텍스트, 아이콘, focus, 상태 표시는 배경과 충분히 구분되어야 하며 색만으로 의미를 전달하지 않아야 합니다.
- 색감: pastel, vivid, muted, neutral, warm, cool 같은 색감은 화면 목적, 대상 사용자, 목표 톤과 맞아야 합니다.
- 색상 무게: 특정 색이나 어두운 팔레트가 화면 전체를 과하게 지배해 정보 위계가 흐려지면 background, surface, action, status 역할을 분리해야 합니다.
- 테마 적응성: light, dark, high contrast, 사용자 설정에서도 의미와 위계가 유지되어야 합니다.
- 데이터 색상: 축, 격자, 라벨, series, threshold, 선택, 범례, 비교, 위험 구간은 구분 가능해야 하며 색각 다양성과 보조 표식을 함께 고려해야 합니다.
- 색상 표현: 단색, 그라데이션, 투명도, 패턴은 정보 의미, 표면 역할, 목표 톤을 분명하게 해야 합니다.
- 감정 전환: 성공, 경고, 오류, 빈 상태의 색감과 톤은 갑자기 튀지 않고 같은 제품처럼 이어져야 합니다.
- 문화와 도메인 맥락: 색의 의미가 지역, 산업, 사용자 집단에 따라 달라질 수 있음을 고려해야 합니다.
- 확장성: 새 상태, 다국어, 장기 사용에도 팔레트와 토큰 구조가 쉽게 깨지지 않아야 합니다.
