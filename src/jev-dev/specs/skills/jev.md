# jev 스킬 스펙

## 목적

사용자가 지정한 질문과 선택지를 Jev CLI에 전달하고, 출력·실패를 원래 작업에 맞게 사용한다.

## 경계

- 포함: 필요한 문맥과 선택지 구성, 옵션 선택, CLI 결과 해석, 요청된 설정·설치·제거·진단.
- 제외: CLI 기계적 동작 재구현, 모든 문서를 자동 검증하는 정책, 맥락이 필요한 판단의 무조건적인 파일별 분할, 로컬 모델이라는 설명.

## 처리하려는 작업 형태

- Jev 또는 TypeSafe를 사용한 선택지 판정, `config`, `install`, `uninstall`, `doctor` 사용 요청.
- 일반 질문이나 코드 검토 전체를 자동으로 외부 API에 넘기는 trigger는 아니다.

## 엔트리포인트 / 대표 표면

- `jev/skills/jev/SKILL.md`, `$jev:jev`.
- 실행 파일 `jev`는 PATH에 설치되어 있어야 한다. 실행 실패가 설치나 인증 문제를 나타내면 해당 설정을 안내하며 일반 호출 전에 별도 doctor·연결 확인을 요구하지 않는다.

## 핵심 처리 계약

- `--if`에 질문과 판정에 필요한 문맥을 함께 담고, `--conditions`에 고유 선택지를 전달한다. 쉼표를 포함하는 선택지 이름은 지원하지 않는다.
- 입력이 여러 문서의 관계에 의존하면 문맥을 함께 보존한다. 입력에 없는 사실을 보충한 판정으로 보고하지 않는다.
- 선택지만 필요하면 기본 출력, 확률 등이 필요하면 JSON과 필요한 pick 필드를 사용한다.
- threshold는 최대 선택 확률의 최소값이며 confidence와 다르다. 점수는 정답 보장이 아니다.
- CLI 성공 결과로 작업을 진행한다. 별도 API 재호출이나 연결 검사로 같은 결과를 중복 검증하지 않는다.
- 종료 코드 2는 임계값 미달이며 stdout 결과가 아니다. 기준을 조용히 낮춰 재시도하지 않는다. 종료 코드 1은 실행 오류로 보고한다.
- config 경로·기본값·우선순위·토큰 stdin 저장과 마스킹을 설명한다. 실제 토큰을 대화나 명령 인자에 요청하지 않는다.
- 유지보수 요청에는 `install [--force] [--dir <directory>]`, `uninstall [--dir <directory>]`, `doctor [--dir <directory>]`를 사용한다. 기본 대상은 `~/.local/bin/jev`다.
- install은 실행 중인 바이너리를 복사하며, 최신 소스를 빌드하거나 다운로드하지 않는다. 최초 설치는 플러그인의 `scripts/`에서 `go run . install`, 소스 갱신은 `go run . install --force`를 사용한다. 다른 설치 위치는 `--dir <directory>`로 지정한다.
- uninstall은 Jev로 식별되는 일반 파일만 제거하며 설정·토큰·설치 디렉터리·셸 설정을 보존한다. 없는 대상은 성공이다.
- doctor는 설치·PATH·설정·토큰 유무만 읽는다. API 인증 유효성이나 모델 정확성을 확인하지 않으며, 자동 수정을 하지 않는다. 문제는 stderr와 종료 코드 1로 보고한다.
- 질문과 선택지가 TypeSafe 외부 API로 전송됨을 밝힌다. 승인 범위 밖의 파일이나 비밀정보를 입력으로 수집하지 않는다.

## 검토 질문

- 선택에 필요한 문맥과 선택지 의미가 보존되는가?
- 선택 확률과 confidence, 판정 결과와 실행 실패를 구분하는가?
- 설정·설치·외부 전송 권한을 요청 범위 안에 유지하는가?

## 독립성 원칙

- 독립 실행 가능성을 강제한다. 스킬 본문만으로 지원 CLI 호출과 결과 사용을 이해할 수 있어야 한다.
- sibling skill이나 개발 spec을 runtime 필수 문맥으로 요구하지 않는다. 플러그인 번들 목적과 설치 안내는 README·manifest가 소유한다.

## 확장 원칙

- 실제 지원 명령만 안내한다. 새 업무별 판정 정책이나 primitive를 암묵적으로 추가하지 않는다.
