# 모델 및 작업 라우팅

이 문서는 여러 조사 스트림을 위임할 가치가 있을 때 역할, 작업 패킷, 검증 책임을 나누는 기준입니다.

## 이름보다 역할을 먼저 선택하기

모델 제품명은 바뀔 수 있으므로 다음 역할 계약을 먼저 정하세요.

| 역할 | 적합한 작업 | 필요한 특성 | 현재 제품군 예시 |
| --- | --- | --- | --- |
| 조사 설계자·종합 책임자 | 범위 설정, 상충 판단, 민감한 추론, 최종 보고서 | 가장 강한 추론과 긴 맥락 종합 | Sol |
| 출처 스트림 조사자 | 독립 하위 질문의 원문 탐색·정독·요약 | 균형 잡힌 추론, 도구 사용, 읽기 처리량 | Terra |
| 구조화 추출자 | 많은 문서에서 고정 필드를 반복 추출 | 빠른 처리, 낮은 비용, 엄격한 스키마 준수 | Luna |

위 이름은 예시입니다. 실제 실행 환경에서 이용 가능한 모델과 성능 특성을 확인하고 같은 역할 계약에 맞춰 대체하세요.

## 위임 여부 결정

다음을 모두 만족할 때만 위임하세요.

- 서로 겹치지 않는 읽기 전용 조사 스트림이 3개 이상입니다.
- 각 스트림을 다른 작업의 결과 없이 시작할 수 있습니다.
- 질문, 범위, 기준 시점, 필요한 출처 유형과 출력 스키마를 고정할 수 있습니다.
- 병렬 처리로 얻는 시간·커버리지 이득이 종합 비용보다 큽니다.
- 최종 책임자가 중요한 주장과 인용을 재확인할 수 있습니다.

다음에는 위임하지 마세요.

- 한두 번의 조회로 끝나는 질문
- 하위 질문이 같은 정의나 증거에 강하게 의존하는 경우
- 작업자에게 외부 쓰기, 메시지 전송, 구매, 변경 권한이 필요한 경우
- 결론 자체를 다수결로 정하려는 경우

## 작업 패킷

각 조사자에게 다음만 전달하세요.

- 독립적인 하위 질문
- 조사 목적과 결정 맥락
- 포함·제외 범위
- 기준 시점, 지역, 핵심 정의
- 우선할 출처 유형
- 읽기 전용 경계
- 완료 조건
- 아래 출력 스키마

이전 조사자의 결론, 종합 책임자의 의심, 원하는 결론을 전달하지 마세요. 탐색을 편향시킬 수 있는 서사를 제외하세요.

## 조사자 출력 스키마

각 작업자는 최소한 다음을 반환해야 합니다.

1. 하위 질문에 대한 잠정 답
2. 핵심 발견사항
3. 정확한 원문 URL과 문서 내 위치
4. 발행일 또는 기준일과 접근일
5. 주장을 직접 뒷받침하는 근거
6. 반대 근거 또는 대안 설명
7. 적용 범위와 방법론 한계
8. 신뢰도와 남은 불확실성
9. 답하지 못한 항목과 이유

URL 없는 주장 목록이나 검색 결과 요약만 반환하면 완료로 보지 마세요.

## 역할별 주의점

### 조사 설계자·종합 책임자

- 질문의 정의와 성공 기준을 소유합니다.
- 작업 스트림 간 중복과 증거 공백을 관리합니다.
- 서로 다른 작업자의 결론을 단순 합산하지 않습니다.
- 중요한 원문과 인용을 직접 다시 엽니다.
- 상충, 표현 강도, 최종 불확실성을 책임집니다.

### 출처 스트림 조사자

- 하나의 명확한 하위 질문과 출처군에 집중합니다.
- 검색 스니펫이 아니라 원문을 엽니다.
- 발견사항과 반대 근거를 같은 스키마로 반환합니다.
- 다른 스트림을 종합하거나 최종 권고를 만들지 않습니다.

### 구조화 추출자

- 필드 정의와 누락값 표현이 고정된 작업에만 사용합니다.
- 해석이 필요한 모호한 문장은 원문 구절과 함께 검토 대상으로 표시합니다.
- 법률 해석, 인과 판단, 상충 해소, 최종 신뢰도 결정은 맡기지 않습니다.
- 표본 검사를 통과하지 못하면 추출을 중단하고 상위 역할로 올립니다.

## 실행 순서

1. 종합 책임자가 조사 지도와 공통 정의를 고정합니다.
2. 독립 스트림을 조사자에게 배정합니다.
3. 필요하면 각 스트림 안의 반복 추출만 구조화 추출자에게 맡깁니다.
4. 작업자 결과의 URL, 날짜, 범위, 반대 근거를 형식 검사합니다.
5. 종합 책임자가 중요한 원문을 다시 열고 주장-근거 원장에 병합합니다.
6. 상충과 빈틈을 대상으로 필요한 추가 조사만 수행합니다.
7. 종합 책임자가 최종 보고서와 인용 감사를 완료합니다.

## 단일 모델 대체 경로

하위 작업 도구가 없거나 위임 기준을 충족하지 않으면 하나의 모델이 같은 단계를 순차적으로 수행하세요. 조사 지도를 먼저 고정하고, 스트림별 메모를 분리한 뒤 마지막에 종합하면 역할 분리의 이점을 상당 부분 유지할 수 있습니다.
