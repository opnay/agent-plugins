## 사용자 스펙 의도

- 엔지니어링 가이드를 단순한 코딩 스타일 목록이 아니라 문제 해결 논리 중심으로 제공하고 싶다.
- 코드 작성 시 엔지니어가 알아야 할 논리, 기술 판단, 코드 작성 방법, 원인 분석, 검증 방법을 다루고 싶다.
- 구체 언어/프레임워크 레시피보다 실제 작업 중 판단 기준으로 사용할 수 있는 원칙을 원한다.
- `pro-engineering` 스펙은 단일 파일에 모든 내용을 압축하지 않고, 폴더 기반 구조에서 각 세부 책임을 자세히 설명해야 한다.
- 자료조사, 구현 범위 조정, 문제 공간 파악처럼 직접 코딩 전 단계에서는 넓은 범위를 탐색하고, 실제 구현 단계에서는 코드를 좁은 범위로 집중해서 봐야 한다.
