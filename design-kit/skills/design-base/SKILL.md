# Design Base

Connect design principles to choices users can perceive and use. Account for the audience, purpose, medium, frequency, risk, existing design language, and actual artifact.

## Establish the Basis

Read `$design-kit:project-design-rules/references/project-context.md` before applying project-specific conventions. Use supplied context and inspect relevant artifacts; keep missing context explicit.

Distinguish a general principle from a project's chosen palette, token, layout, or pattern. Existing adopted rules are inputs, not proof that every observed implementation is intentional.

Frame each material decision through **principle, applicability, choice, and verification**. Use only the detail needed for the request. Distinguish observed behavior, inferred user impact, proposed changes, and verified results.

## Select Knowledge

Read only the references needed for the decision:

- Color, complementary relationships, palette, contrast, semantic or data colors: [color](references/color.md).
- Grouping, hierarchy, typography, density, space, layout, depth, cards or materials: [space, type, and surface](references/space-type-surface.md).
- Affordance, states, flow, interface copy, feedback or motion: [interaction and content](references/interaction-content.md).
- Consistency, recurring terms, colors or patterns, omission, reinforcement, series or rhythm: [repetition](references/repetition.md).

These references also support other roles in this bundle. A role can read them directly without running this skill first.

## Make the Decision

- Start with meaning, relationships, and action priority; choose expression that makes them perceptible.
- Preserve essential readability, state meaning, accessible operation, and truthful claims. Within those constraints, consider emotional response, attraction, pleasure, and memorability when they serve the brief.
- Resolve competing goals through use context. Dense comparison tools and occasional high-risk tasks can require different spacing, information exposure, and interaction choices.
- Prefer repeatable rules to isolated visual fixes. Reconsider grouping or ownership when a child needs greater persistent importance than its group implies.
- Explain alternatives only when they resolve a real choice. Do not prescribe a fixed number of concepts or a full audit for a small request.

## Verify and Report

Inspect the actual artifact at the relevant size and state when available. Check the affected content lengths, themes, input methods, and responsive conditions. A static image can support visual observations; it does not prove navigation, accessibility, or task completion.

Report the decision, its basis and tradeoff, what was inspected or measured, and consequential uncertainty. If an artifact or behavior cannot be checked, state that limit. Route reusable project decisions through the project context contract; do not imply that a proposal was saved.
