# pro-designer Skill Spec

## 목적

`pro-designer`는 Codex가 화면, 제품 UI, 시각 산출물을 다룰 때 디자이너 관점의 지식 기준을 적용하게 하는 guidance skill입니다.
핵심 초점은 `UI`, `UX`, `Content`, `Quality` 4축으로 디자인 판단 기준을 제공하는 것입니다.

## 경계

- UI: 사용자가 정보를 읽고, 구조를 이해하고, 가능한 행동을 판단하는 인터페이스 표면 기준
- UX: 사용자가 목표까지 가는 과정에서 헷갈림, 불안, 실수, 반복 부담을 줄이는 경험 기준
- Content: 화면 안의 언어가 이해, 판단, 행동을 돕는지 보는 기준
- Quality: UI, UX, Content가 접근성, 일관성, 적응성, 맥락 적합성을 유지하는지 보는 기준

## 처리하려는 작업 형태

- 새 화면, 웹사이트, 앱, 대시보드, 폼, 설정 패널, 랜딩 페이지를 만들 때 디자인 판단이 필요한 작업
- 기존 UI가 어색하거나 복잡하거나 사용하기 어려운 이유를 찾아 개선하는 작업
- 사용자가 어떤 흐름으로 목표에 도달해야 하는지 정리해야 하는 작업
- 화면 밀도, 정보 구조, 시각 위계, 문구, 상태 설계를 함께 판단해야 하는 작업
- 디자인 방향, 품질 기준, 개선 판단의 근거가 필요한 작업

## 1차 기준 축

- UI는 정보 구조, 시각 위계, 상태 표현, affordance, feedback을 다룹니다.
- UX는 user flow, 인지 부하, 오류 예방과 회복, 신뢰, 학습성을 다룹니다.
- Content는 라벨, CTA, 안내, 오류 문구, 빈 상태, 용어 일관성을 다룹니다.
- Quality는 접근성, 일관성, 적응성, 맥락 적합성, 감정과 톤을 다룹니다.

## 핵심 처리 계약

- `pro-designer`는 미감 평가 문서가 아니라 디자인 판단에 필요한 지식 기준입니다.
- 디자인 판단은 대상 사용자, 작업 목적, 화면 유형, 정보 우선순위를 기준으로 합니다.
- UI는 사용자가 화면의 정보를 읽고, 구조를 이해하고, 가능한 행동을 자연스럽게 판단할 수 있는지 봅니다.
- UX는 사용자가 목표까지 가는 흐름에서 헷갈림, 불안, 실수, 반복 부담이 줄어드는지 봅니다.
- Content는 문구가 사용자의 이해와 결정을 돕고 다음 행동을 분명히 하는지 봅니다.
- Quality는 접근성, 일관성, 적응성, 맥락 적합성, 톤이 유지되는지 봅니다.
- 기존 디자인 시스템이나 제품 패턴이 있으면 먼저 따르고, 새 패턴은 명시적 이유가 있을 때만 도입합니다.

## 사용 기준

- 사용자가 UI 생성, UI 개선, 디자인 검토, 화면 어색함, 대시보드, 랜딩 페이지, 설정 패널, 폼, 앱 화면을 요청할 때 적용합니다.
- 사용자가 UX 개선, 사용 흐름, 온보딩, 전환율, 이탈, 헷갈림, 피로감, 신뢰 문제를 언급할 때 적용합니다.
- 사용자가 문구, 라벨, 오류 메시지, CTA, 빈 상태의 이해 가능성을 묻는 경우에도 적용합니다.
- 단순 코드 스타일, 빌드 오류, 데이터 모델, API 계약처럼 디자인 판단이 핵심이 아닌 작업에는 적용하지 않습니다.
- 디자인 시스템이 있으면 먼저 따르고, 새 패턴은 사용자 문제를 더 잘 해결한다는 이유가 있을 때만 도입합니다.
- 미감 취향보다 사용자가 무엇을 이해하고 어떤 행동을 할 수 있는지를 기준으로 판단합니다.
