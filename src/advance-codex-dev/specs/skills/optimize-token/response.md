# Response Optimization Spec

## 보존 규칙

- 압축은 언어 변경이 아닙니다. 활성 언어, 말투, 존대, 지역 표현을 유지합니다.
- 의미, 안전 경계, 검증 상태, 승인 경계, 형식, 경로, 명령어, 날짜, 버전, 수치는 줄이지 않습니다.
- 문법을 깨서 줄이지 않습니다. 중복 제거와 문장 병합을 우선합니다.

## 단계 규칙

- 읽는 순서: `` `light` > `standard` > `extreme` ``
- 뒤 단계는 앞 단계 규칙을 상속하고 자기 덮어쓰기 규칙만 적용합니다.
- `light`: 일반 "짧게/간결하게" 요청의 기본값입니다. 자연문을 유지합니다.
- `standard`: "핵심만/요약/더 짧게" 또는 긴 보고에 씁니다. 핵심 판단, 근거, 다음 행동, 중요한 위험을 남깁니다.
- `extreme`: "상태만/라벨만/한 줄로/최대한 압축" 또는 구조화된 원문에만 씁니다.
- 고위험, 미검증, 실패, 승인, commit/push/PR/publish/release/version bump는 필요한 부분을 `standard` 또는 `light`로 강등합니다.
- 단계나 흐름 순서 설명은 `standard` 단계 규칙으로 다루며, `>` 체인을 사용합니다. 예: `` `light` > `standard` > `extreme` 순으로 읽어야 합니다. ``

## 판단 규칙

- 줄여도 되는 것: 인사말, 자기 설명, 반복 조건, 완충 표현, 공유된 배경
- 줄이면 실패하는 것: 승인 필요 조건, 실패/미실행 검증, 변경 파일과 경로, 날짜/버전/수치/명령어, 안전상 중요한 예외 조건
- 선택 강도가 맞아도 필수 정보가 빠지거나 더 모호해지면 실패입니다.
- `>`는 진행 방향이나 읽는 순서만 나타내며, 우열이나 실행 권한을 뜻하지 않습니다.
