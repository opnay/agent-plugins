# Response Optimization Spec

## 언어와 말투 보존 규칙

- 응답 압축은 언어를 바꾸는 작업이 아닙니다.
- 사용자 또는 상위 지침이 특정 언어와 말투를 요구하면 그대로 유지합니다.
- 이 저장소처럼 한국어 존대체가 요구되는 환경에서는 한국어 존대체를 유지합니다.
- 한국어 외 언어에서는 해당 언어의 자연스러운 전문 문체를 유지하고, 사용자가 격식/비격식, 존칭, 지역 표현을 지정했다면 그 기준을 따릅니다.
- 언어별로 짧게 만들기 어렵더라도 의미, 안전 경계, 검증 상태를 줄이지 않습니다.

## 압축 범위와 문법 규칙

- 기본 압축 범위는 `light`입니다. 사용자가 단순히 "짧게", "간결하게", "군더더기 없이"처럼 말한 경우에는 먼저 `light`를 선택합니다. 불필요한 인사말, 반복, 완충 표현을 줄이되 완전한 문장을 유지합니다.
- `standard` 압축은 원문이 길거나 사용자가 "핵심만", "더 짧게", "요약해서"처럼 내용 선별을 요구할 때 사용합니다. 세부 배경을 줄이고 핵심 판단, 근거, 다음 행동, material risk를 남깁니다.
- `dense` 압축은 사용자가 "상태만", "라벨만", "최대한 압축", "한 줄로"처럼 매우 짧은 출력 형태를 직접 요구하거나, 원문이 상태표/숫자 목록/정해진 헤딩처럼 구조가 명확할 때만 사용합니다. 이 경우에도 승인 경계, 검증 상태, 수치, 경로는 유지합니다.
- 고위험 작업, 검증 실패, 승인 요청, 보안/법률/금융 등에서는 사용자가 짧게 요청해도 `dense`로 바로 가지 말고 `light` 또는 `standard` 안에서 필요한 세부 정보를 보존합니다.
- 조사, 관사, 전치사, 동사, 존칭처럼 해당 언어에서 문장을 자연스럽게 만드는 요소를 임의로 삭제하지 않습니다.
- 제목, 목록, 상태값은 짧게 쓸 수 있지만 설명 문장은 자연스러운 문법을 유지합니다.
- 문법을 줄여 토큰을 아끼는 것보다 문장을 합치거나 중복을 제거하는 방식을 우선합니다.

## 필요한 판단 규칙

- 압축해도 되는 것:
  - 인사말
  - 자기 설명
  - 반복되는 조건 설명
  - 확신 없는 완충 표현
  - 이미 사용자와 공유된 배경
- 압축 강도 선택 기준:
  - `짧게`, `간결하게`, `군더더기 없이`: 기본 `light`
  - `핵심만`, `요약해서`, 긴 보고 축약: 보통 `standard`
  - `상태만`, `라벨만`, `한 줄로`, 구조화된 상태 목록: 조건부 `dense`
- 압축하면 안 되는 것:
  - 승인 필요 조건
  - 검증 실패 또는 미실행 사실
  - 변경 파일과 경로
  - 날짜, 버전, 수치, 명령어
  - 안전상 중요한 예외 조건
  - 해당 언어의 자연스러운 문법과 말투
