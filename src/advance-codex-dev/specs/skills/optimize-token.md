# optimize-token 스킬 스펙

## 목적

`optimize-token`은 Codex 응답을 짧고 선명하게 만들되 정확성, 안전 경계, 검증 보고, 사용자가 요구한 형식을 약화하지 않는 응답 최적화 skill입니다.
목표는 특정 외부 플러그인이나 문체 이름을 재현하는 것이 아니라, 토큰 낭비를 줄이는 실용적인 응답 작성 기준을 제공하는 것입니다.

## 경계

- 포함:
  - 불필요한 인사말, 완충 표현, 반복 설명, 과도한 배경 설명 줄이기
  - 답변 순서를 결론, 근거, 다음 행동 중심으로 정리하기
  - 짧게 쓰더라도 승인 경계, 검증 결과, residual risk, 파일 경로 같은 필수 정보를 유지하기
  - 활성 언어, 말투, 저장소별 출력 기대사항을 유지하며 응답 압축하기
- 제외:
  - 모델 context compression, 세션 요약, session record 압축
  - 코드, 오류 메시지, API 이름, 파일 경로의 임의 축약
  - 안전 경고, 법률/의료/금융 고지, approval-sensitive 설명의 축소
  - 특정 외부 플러그인명, 밈, 말투, 캐릭터화된 표현 사용

## 처리하려는 작업 형태

- 사용자가 "짧게", "간결하게", "토큰 아끼게", "불필요한 말 빼고"처럼 응답 형식 최적화를 요청하는 경우
- 문서, 보고, 리뷰 결과, 구현 완료 보고처럼 내용은 유지하되 표현 밀도를 높여야 하는 경우
- 다른 skill이 만든 결과물을 사용자에게 전달하기 전에 응답 표면만 다듬어야 하는 경우

## 엔트리포인트 / 대표 표면

- 대표 표면: `advance-codex-dev/skills/optimize-token/SKILL.md`
- 호출 방식: 사용자가 짧고 선명한 응답, 토큰 절약, 불필요한 말 제거, 응답 압축을 요청할 때 호출한다. 상세 응답 기준은 `advance-codex-dev/skills/optimize-token/references/response.md`가 소유한다.

## 핵심 처리 계약

- `SKILL.md`는 언제 이 skill을 쓰는지와 어떤 reference를 읽을지 안내합니다.
- 자세한 응답 작성 규칙은 `references/response.md`가 소유합니다.
- 응답 최적화는 의미 보존을 전제로 합니다. 짧아진 답변이 더 모호해지면 실패입니다.
- 응답 최적화는 문법을 깨는 압축이 아니라, 자연스러운 문장 안에서 불필요한 표현을 줄이는 작업입니다.
- 다른 상위 지침이 요구하는 보고 항목은 삭제하지 않고 더 촘촘하게 씁니다.
- 사용자가 명시한 출력 형식은 유지합니다.

## 언어와 말투 보존 규칙

- 응답 압축은 언어를 바꾸는 작업이 아닙니다.
- 사용자 또는 상위 지침이 특정 언어와 말투를 요구하면 그대로 유지합니다.
- 이 저장소처럼 한국어 존대체가 요구되는 환경에서는 한국어 존대체를 유지합니다.
- 한국어 외 언어에서는 해당 언어의 자연스러운 전문 문체를 유지하고, 사용자가 격식/비격식, 존칭, 지역 표현을 지정했다면 그 기준을 따릅니다.
- 언어별로 짧게 만들기 어렵더라도 의미, 안전 경계, 검증 상태를 줄이지 않습니다.

## 압축 범위와 문법 규칙

- 기본 압축 범위는 `light`입니다. 사용자가 단순히 "짧게", "간결하게", "군더더기 없이"처럼 말한 경우에는 먼저 `light`를 선택합니다. 불필요한 인사말, 반복, 완충 표현을 줄이되 완전한 문장을 유지합니다.
- `standard` 압축은 원문이 길거나 사용자가 "핵심만", "더 짧게", "요약해서"처럼 내용 선별을 요구할 때 사용합니다. 세부 배경을 줄이고 핵심 판단, 근거, 다음 행동, material risk를 남깁니다.
- `dense` 압축은 사용자가 "상태만", "라벨만", "최대한 압축", "한 줄로"처럼 매우 짧은 출력 형태를 직접 요구하거나, 원문이 상태표/숫자 목록/정해진 헤딩처럼 구조가 명확할 때만 사용합니다. 이 경우에도 승인 경계, 검증 상태, 수치, 경로는 유지합니다.
- 고위험 작업, 검증 실패, 승인 요청, 보안/법률/금융 등에서는 사용자가 짧게 요청해도 `dense`로 바로 가지 말고 `light` 또는 `standard` 안에서 필요한 세부 정보를 보존합니다.
- 조사, 관사, 전치사, 동사, 존칭처럼 해당 언어에서 문장을 자연스럽게 만드는 요소를 임의로 삭제하지 않습니다.
- 제목, 목록, 상태값은 짧게 쓸 수 있지만 설명 문장은 자연스러운 문법을 유지합니다.
- 문법을 줄여 토큰을 아끼는 것보다 문장을 합치거나 중복을 제거하는 방식을 우선합니다.

- 참고 출처: https://github.com/JuliusBrussee/caveman/blob/main/plugins/caveman/skills/caveman/SKILL.md

- runtime skill에는 출처, 외부 플러그인명, 캐릭터화된 style label을 넣지 않습니다.

## 필요한 판단 규칙

- 압축해도 되는 것:
  - 인사말
  - 자기 설명
  - 반복되는 조건 설명
  - 확신 없는 완충 표현
  - 이미 사용자와 공유된 배경
- 압축 강도 선택 기준:
  - `짧게`, `간결하게`, `군더더기 없이`: 기본 `light`
  - `핵심만`, `요약해서`, 긴 보고 축약: 보통 `standard`
  - `상태만`, `라벨만`, `한 줄로`, 구조화된 상태 목록: 조건부 `dense`
- 압축하면 안 되는 것:
  - 승인 필요 조건
  - 검증 실패 또는 미실행 사실
  - 변경 파일과 경로
  - 날짜, 버전, 수치, 명령어
  - 안전상 중요한 예외 조건
  - 해당 언어의 자연스러운 문법과 말투

## 검토 질문

- 이 skill이 응답 표면만 다루고 있는가?
- 짧게 만들면서 정확성이나 검증 상태가 흐려지지 않았는가?
- 상위 지침의 언어, 말투, 보고 형식을 유지했는가?
- 압축 강도가 요청과 상황에 맞고, 문장이 어색해지지 않았는가?
- 단순한 "짧게" 요청을 과도하게 `dense`로 해석하지 않았는가?
- 외부 플러그인명이나 불필요한 출처 설명이 runtime에 남지 않았는가?

## 독립성 원칙

- 이 skill이 독립 실행 가능성을 spec으로 강제해야 하는가: 예.

## 확장 원칙

- 더 많은 응답 유형이 필요하면 `references/response.md`에 추가합니다.
- session record, prompt compression, subagent handoff 압축 같은 별도 책임은 이 skill에 흡수하지 않습니다.
- 출력 형식별 예시는 간결하게 유지하고, 반복되는 문체 예시를 과도하게 늘리지 않습니다.
