## 사용자 스펙 의도

- 신규 플러그인 추가. 폴더 위치를 지정하면, 해당 위치에 지식 저장소 문서 폴더를 만들어 관리합니다. 스킬은 항상 사용되도록 passive 셋팅이 필요합니다. 폴더의 AGENTS.md를 만들고 관리하는 규칙을 추가합니다.
  - 새 플러그인 이름을 무엇으로 할까요?
    - `memory-vault`[직접 입력]
- 정정: 사용자는 직접 관리하는 폴더를 제공합니다. 해당 폴더 그 자체를 관리하는 스킬입니다.
- skill 이름은 플러그인 이름과 같은 `memory-vault`를 사용합니다.
- 지식 저장하는 스킬은 만들었는데, 전략을 뭘로 가져가야될까? 이 플러그인을 설치한 에이전트에게 뭔가를 시키면 자연스레 습득하는 지식들을 모아 관리하는 방식을 생각하고있거든.
- 이건 프로젝트 타겟이 아니야. 어떤 상황에서든 에이전트를 사용하다보면 기억해야되는 내용들과 지식들을 저장하는 스킬이야.
- `INDEX.md`는 정보를 나열하는 인덱싱 파일로 유지합니다. 예를 들어 `Programming/001-some-knowledge.md`, `Programming/React/001-hook-rules.md` 같은 지식 문서를 폴더별 `INDEX.md`에서 나열합니다. 지식 문서 파일명은 `<index>-<slug|lowercase|hyphen-case>.md` 형식입니다.
- memory-vault 또 잘못 설계됐어. 에이전트가 작업하면서 나오는 실수, 웹검색을 통해 얻게된 지식, 사용자의 지시를 통해 얻게된 지식 등을 저장하는 공간이야. 프로젝트 스코프 같은게 아니고, 사용자가 지시해야 저장하는 공간이 아니야. 예: `pnpm install` -> 권한 부족 실패 -> pnpm은 권한 상승 필요 요청.
  - 다음으로 어떤 흐름을 진행할까요?
    - `작업 지시`[선택], 추가 메시지: memory-vault 설계 수정 요청
  - `memory-vault-dev`의 첫 수정으로 version bump를 어떻게 할까요?
    - `patch (Recommended)`[선택 후 중단], 이후 사용자가 `next` 신규 플러그인 범위이므로 추가 patch 여부를 재확인함

# memory-vault 스킬 스펙

## 목적

`memory-vault`는 에이전트 사용 전반에서 오래 유지할 개인/작업 지식을 vault root에 저장하고, 다음 작업에서 다시 읽어 적용하도록 돕습니다.
이 skill은 사용자가 명시적으로 "기억해", "저장해", "앞으로 이렇게 해"라고 요청할 때뿐 아니라, 작업 중 나온 실수, 명령 실패, 웹검색 지식, 코드 확인 결과, 사용자 지시처럼 장기적으로 재사용 가능한 기억 후보가 생길 때 passive로 선택될 수 있어야 합니다.

## 경계

- 포함:
  - 대상 vault root 확인 또는 기본 개인 vault root 사용
  - 대상 폴더의 `README.md`, `INDEX.md`, `preferences.md`, `decisions.md`, `environment.md`, `workflows.md`, `glossary.md`, `open-questions.md` 생성
  - 1-2 depth 카테고리 폴더의 `INDEX.md` 생성
  - 1-2 depth 카테고리 폴더 아래 지식 문서 생성
  - 카테고리 `INDEX.md`에 지식 문서와 하위 카테고리 링크 나열
  - `AGENTS.md`의 `Memory Vault` 표식 섹션 생성 또는 갱신
  - root `AGENTS.md`에 1-2차 카테고리 맵 갱신
  - 작업 전 관련 메모리 읽기
  - 작업 중 장기 기억 후보 선별과 문서별 분류
  - 작업 중 확인한 실수, 실패 원인, 권한 요구, 도구 동작, 웹검색 지식, 코드 기반 지식, 사용자 지시의 저장 여부 판단
  - 확실한 지식은 사용자 저장 지시가 없어도 작은 단위로 갱신
  - 모호한 기억 후보는 사용자에게 질문하거나 `open-questions.md`에 보류
- 제외:
  - 특정 프로젝트 전용 지식 저장소로 스킬 경계 고정
  - 대상 폴더 밖 파일 변경
  - 기존 vault 문서 삭제 또는 임의 재작성
  - 대상 폴더 아래 별도 `memory-vault/` 하위 폴더 생성
  - 2 depth를 초과하는 지식 문서 경로 생성
  - 번호 없는 지식 문서 또는 대문자/공백 slug 파일 생성
  - 표식 없는 기존 `AGENTS.md` 본문 재작성
  - 대화 전문, 임시 작업 로그, 추측, 민감 정보의 자동 저장
  - 검증되지 않은 웹검색 결과나 일시적인 장애를 장기 지식으로 확정

## 처리하려는 작업 형태

- 사용자가 장기 기억으로 저장하라고 직접 요청하는 작업
- 에이전트가 작업 중 재사용 가능한 기억 후보를 발견한 경우
- 명령 실패, 권한 부족, 테스트 실패, 도구 제약처럼 다음 작업에서 같은 판단을 줄일 수 있는 실수를 확인한 경우
- 웹검색, 공식 문서, 실제 코드, 로컬 명령 결과에서 반복 적용할 지식을 얻은 경우
- 개인 vault root를 초기화하거나 기본 문서 누락 여부를 확인하는 작업
- 기존 memory vault의 기본 문서를 읽고 필요한 기억을 현재 작업에 적용하는 작업
- 기존 vault 문서에 선호, 결정, 환경, workflow, 용어, 질문을 정리하는 작업
- `Agents/Prompting`처럼 1-2 depth 카테고리를 만들고 각 폴더의 `INDEX.md`로 내용을 관리하는 작업
- `Programming/some-knowledge`, `Programming/React/hook-rules`처럼 지식 문서를 만들고 폴더별 `INDEX.md`에 연결하는 작업

## 엔트리포인트 / 대표 표면

- 대표 표면: `skills/memory-vault/SKILL.md`
- 호출 방식: 자연어 passive trigger 또는 `$memory-vault:memory-vault`
- helper script: `scripts/memv.py`
- 기본 vault root: 사용자가 지정하지 않은 경우 `~/Workspace/Memory-vault`

## 핵심 처리 계약

- 사용자가 지정한 대상 폴더가 있으면 해당 폴더를 vault root로 사용합니다.
- 대상 폴더가 없으면 기본 vault root `~/Workspace/Memory-vault`를 사용합니다.
- 대상 폴더만 변경 대상으로 잠급니다.
- 기본 변경은 대상 폴더의 기본 문서, 1-2 depth 카테고리 `INDEX.md`, `AGENTS.md` 표식 섹션으로 제한합니다.
- 지식 문서를 만들 때는 `<category>/<index>-<slug>.md` 또는 `<category>/<subcategory>/<index>-<slug>.md`만 허용합니다.
- slug는 lowercase hyphen-case로 정규화하고, index는 같은 폴더의 다음 3자리 번호를 사용합니다.
- 카테고리 `INDEX.md`는 본문 지식 요약이 아니라 해당 폴더의 지식 문서와 하위 카테고리 링크를 나열합니다.
- 일반 메모리 문서와 지식 문서는 덮어쓰지 않습니다.
- 인덱스 파일은 현재 카테고리와 지식 문서 목록을 반영하도록 갱신할 수 있습니다.
- `AGENTS.md`는 표식 섹션만 갱신합니다.
- 스크립트를 사용할 수 있으면 `--dry-run`으로 예정 변경을 확인한 뒤 실제 실행합니다.
- 실행 뒤에는 생성/갱신/보존된 파일과 검증 결과를 보고합니다.

## 메모리 판별 규칙

- 저장 허용:
  - 반복 적용되는 사용자 선호와 답변 방식
  - 오래 유지할 운영 결정
  - 로컬 환경, 경로, 도구, 패키지 매니저 정보
  - 반복 workflow와 검증 방식
  - 사용자가 정의한 용어, 약어, 명명 규칙
  - 에이전트가 직접 확인한 명령 실패 원인과 다음 실행 규칙
  - 권한 상승, 네트워크, sandbox, 패키지 매니저처럼 반복될 실행 환경 제약
  - 웹검색이나 공식 문서로 확인한 재사용 가능한 지식
  - 실제 코드나 테스트로 확인한 프로젝트 밖에서도 유효한 패턴
  - 앞으로 확인해야 할 미해결 질문
- 저장 보류:
  - 출처가 불명확하거나 사용자가 확정하지 않은 사실
  - 한 번 더 질문하면 더 정확해지는 선호
  - 현재 작업에는 유용하지만 장기 적용 여부가 불확실한 패턴
  - 웹검색 결과가 최신성이나 출처 신뢰성 면에서 불충분한 지식
  - 한 번의 실패만으로 일반화하기 어려운 오류
- 저장 금지:
  - 일회성 진행 로그
  - 임시 오류 상태와 그대로의 실패 로그
  - 추측이나 대화 중 취소된 방향
  - 비밀값, 인증 정보, 개인식별 민감 정보
  - 사용자가 저장하지 말라고 한 내용

## 문서 분류 규칙

- `preferences.md`: 말투, 설명 깊이, 질문 방식, 도구 사용 선호 같은 사용자 선호
- `decisions.md`: 장기 운영 결정과 명시적으로 확정된 정책
- `environment.md`: 로컬 경로, 런타임, 패키지 매니저, 자주 쓰는 시스템 정보
- `workflows.md`: 반복 작업 절차, 검증 루틴, 권한 상승이 필요한 명령, 선호하는 문제 해결 방식
- `glossary.md`: 사용자 또는 작업 전반에서 반복되는 용어와 약어
- `open-questions.md`: 아직 확정되지 않은 기억 후보와 확인 질문
- `INDEX.md`: vault root의 기본 문서와 1-2 depth 카테고리 맵
- `<category>/INDEX.md`: 해당 폴더의 지식 문서 목록과 하위 카테고리 링크
- `<category>/<index>-<slug>.md`: 1차 카테고리 지식 문서
- `<category>/<subcategory>/<index>-<slug>.md`: 2차 카테고리 지식 문서

## Passive Trigger 계약

- description은 skill 이름 없이도 선택될 수 있도록 한국어와 영어 트리거 표현을 포함합니다.
- passive token은 넓은 일반 문서 작업 전체가 아니라 personal agent memory, user preferences, durable notes, remember/save for future에 맞춥니다.
- 사용자가 "항상 사용"을 원한 의미는 모든 작업 내용을 저장하는 것이 아니라, 작업 중 실수, 웹검색 지식, 사용자 지시, 환경 제약 같은 기억 후보가 생길 때 자동 선택되도록 description trigger를 강화하는 것입니다.

## AGENTS.md 규칙 계약

- `AGENTS.md`에는 `<!-- memory-vault:start -->`와 `<!-- memory-vault:end -->` 표식으로 감싼 섹션을 둡니다.
- 표식 섹션은 agent가 관련 작업 전 `INDEX.md`와 필요한 문서를 확인하도록 지시합니다.
- 표식 섹션은 장기 기억 후보를 문서 분류 규칙에 따라 기록하도록 지시합니다.
- 표식 섹션은 추측, 임시 로그, 민감 정보, 취소된 방향을 저장하지 않도록 지시합니다.
- 표식 섹션은 root `AGENTS.md` 안에 1-2차 카테고리 맵을 둡니다.
- 표식 없는 기존 지침은 보존합니다.
- 기존 표식 섹션이 있으면 현재 템플릿으로 갱신할 수 있습니다.

## 검토 질문

- 이번 내용이 다음 작업에서도 재사용될 장기 기억인가?
- 사용자가 직접 확정했거나 코드/환경으로 검증된 사실인가?
- 에이전트가 작업 중 직접 겪은 실수나 실패라면 원인과 다음 행동이 충분히 확인됐는가?
- 웹검색 지식이라면 출처와 최신성이 충분히 신뢰 가능한가?
- 어느 문서에 들어가야 하는지 명확한가?
- 모호하면 질문할지, `open-questions.md`에 보류할지 판단했는가?
- 민감 정보나 일회성 로그를 저장하지 않는가?
- 변경 대상이 대상 vault root 내부 allowlist에 머무르는가?
- 카테고리 경로가 상대 경로이며 1-2 depth를 넘지 않는가?
- 지식 문서 파일명이 `<index>-<lowercase-hyphen-slug>.md` 형식인가?
- 관련 `INDEX.md`가 지식 문서 링크를 나열하는가?

## 독립성 원칙

- 이 skill이 독립 실행 가능성을 spec으로 강제해야 하는가: 예.
- 이유: 설치 후 자연어 passive trigger만으로도 단독 실행되어야 하며, sibling skill 없이 대상 vault root와 helper script만으로 작업을 완료해야 합니다.

## 확장 원칙

- 새 문서 종류를 추가할 때는 plugin spec의 bundle 경계와 `AGENTS.md` 규칙 계약을 함께 점검합니다.
- 외부 동기화나 데이터베이스 기능은 별도 plugin 또는 명시적 확장 spec 없이는 추가하지 않습니다.
- 기본 문서 템플릿은 장기 메모리 선별, 낮은 유지 비용, 빠른 읽기 가능성을 우선합니다.
