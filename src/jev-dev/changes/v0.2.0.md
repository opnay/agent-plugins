# jev v0.2.0 Change Spec

## 변경사항 요약

- `jev noul`, `jev choice`, `jev score` primitive 명령.
- 타입별 기본·JSON 출력과 결과 기준 필터.
- 기존 Choice 호출 호환성과 `snake_case` 소유 key 규칙.
- 평가·설정·유지보수와 타입별 옵션·출력·종료 코드를 구분한 usage.

## 변경 목적

서로 다른 의미의 Noul·Choice·Score를 하나의 Choice 계약으로 취급하지 않고, 질문 형태와 결과 해석을 CLI에서 분명히 구분한다.

## 변경 상세

### Primitive 명령

- Noul은 참일 확률, Choice는 선택된 조건, Score는 순서형 단계의 확률 가중 점수를 반환한다.
- Score 단계는 쉼표를 포함할 수 있는 반복 `--level`로 받는다.
- 기존 `jev --if ... --conditions ...`는 Choice 호환 형식으로 유지한다.
- 관련 표면: [CLI spec](../specs/cli.md), `jev/scripts/`, README.

### 출력과 설정

- 기본 출력은 타입별 주 결과 하나다. JSON의 공통 결과 key는 `answer`, `model`이다.
- Choice·Score는 `probabilities`, `confidence`를 제공하고 Score는 `legend`를 추가한다.
- `threshold`는 Choice 선택 확률과 Noul 참일 확률에 적용한다. Score는 `min_score`를 사용한다.
- CLI·설정·JSON의 소유 key는 `snake_case`다. Choice 라벨은 자유 문자열이며 자동화에 쓰는 경우 `snake_case`를 권장한다.
- 관련 표면: CLI·skill spec, runtime skill, README, manifest.

### Usage

- 단일 help 안에서 Evaluation, Configuration, Maintenance, 공통·primitive 옵션, config key, 출력, 종료 코드를 구분한다.
- 각 subcommand help는 자기 형식·옵션·출력·동작만 설명한다. 모든 help는 설정파일이나 토큰을 읽지 않는다.
- 관련 표면: [CLI spec](../specs/cli.md), `jev/scripts/flags.go`, `jev/scripts/usage*.go`.

## 비목표

한 요청의 복수 질문, 구조화 criteria, confidence 필터, 업무별 정책, 자동 재시도.

## 호환성 및 마이그레이션

- 기존 Choice 명령과 설정파일을 유지한다.
- `min_score`는 선택 설정이며 기존 파일에 없으면 Score 필터를 적용하지 않는다.
- 저장된 `pick`은 실행 primitive에서 제공하지 않는 필드를 선택하면 API 호출 전에 실패한다.

## 검증 기준

- 세 primitive의 요청 형식, 응답 검증, 기본·JSON·pick 출력, 결과 기준 경계를 자동 테스트한다.
- 기존 Choice 호출과 설정 우선순위 회귀 테스트를 유지한다.
- Go 테스트·vet·빌드, plugin·skill validator, spec/runtime 독립 검증을 통과한다.
- 실제 API smoke test는 사용 가능한 토큰과 호출 권한이 있을 때 별도로 수행한다.

## 정식 규칙 승격 여부

지속 계약은 plugin·CLI·skill spec이 소유한다. 이 문서는 v0.2.0 변경 범위와 검증 결과를 기록한다.
