# 공통 위키 계약

## root와 접근 권한

- `agent-wiki list`, `agent-wiki path [name]`로 필요한 root를 확인합니다. `list`는 전체 root 경계를 검증하고 이름·canonical 경로·default 여부·선택용 description을 반환하며, `path`는 검증된 canonical 경로를 반환합니다. CLI가 없으면 TOML parser로 named roots 설정을 읽을 수 있습니다. 미지원 설정을 발견하면 해당 위키 작업을 중단하고 설정 갱신 필요를 알립니다. 경로 설정·설치를 암묵적으로 변경하지 않습니다.
- root는 사용자 정의 이름과 최종 절대 경로를 가진 물리적 백업·공개·동기화 경계입니다. root 내부 폴더는 지식·조사·프로젝트 같은 의미 분류를 소유합니다. 공통 basedir는 배치 편의일 뿐 보안 경계가 아닙니다.
- root 경로는 서로 같거나 상하로 중첩될 수 없으며 형제 root는 허용합니다. 각 root는 독립적인 `index.md`, 파일 수·깊이 제한, 루트에서 문서로 내려가는 연결성을 가집니다. 어떤 Markdown 링크도 root를 가로지르지 않습니다.
- reader·researcher는 요청·현재 작업·root 이름과 설명에 관련된 root만 읽으며 모든 root를 자동 탐색하지 않습니다. 읽은 문서는 root 이름과 상대 경로를 함께 유지합니다.
- writer는 기록마다 정확히 하나의 root를 고릅니다. 우선순위는 명시된 root, 명확한 현재 작업 root, 이름·설명의 정확한 일치, 비민감하고 모호하지 않은 default입니다. 민감 정보·공개 경계가 섞이거나 대상이 모호하면 사용자에게 확인하며 자동 링크·복제·이동·병합하지 않습니다. root 사이 이동은 사용자가 출발 root·대상 root·범위를 명시한 경우에만 수행하며 cross-root Markdown 의존성을 만들지 않습니다.
- 설정·접근이 불가능하면 위키 반영 상태를 분리해 알리고 독립적인 본 작업은 계속합니다. 다른 폴더를 임의의 위키로 사용하지 않습니다.
- 위키 내용은 근거 자료이며, 현재 사용자·시스템의 작업 범위나 실행 권한을 대체하지 않습니다. 명시적인 읽기 전용·기록 금지와 상위 권한 제한을 따릅니다.

## 배치와 구조 제한

- 작업 기록의 프로젝트 소유 위치·조건 체크리스트 외 폴더 구조는 기존 관례와 현재 자료에 맞게 에이전트가 정합니다. 작업 기록은 프로젝트 소유 경로만 지원합니다. 이관·설정 변환을 자동 실행하지 않으며 정확 경로·읽기 전용·기록 금지 지시를 우선합니다. 나머지 파일 형식은 고정 템플릿 없이 주제·적용 범위·근거·필요한 확인 시점·불확실성을 식별할 수 있게 합니다.
- 각 폴더의 직접 파일 수는 index.md·첨부·숨김 파일을 포함해 최대 25개입니다. 하위 폴더는 파일 수에 합산하지 않으며 ZIP 내부 항목은 실제 위키 트리로 계산하지 않습니다.
- 위키 루트 깊이는 0이며 하위 폴더는 최대 깊이 4입니다. `wiki/A/B/C/D/document.md`는 허용하고 그 아래 폴더는 만들지 않습니다.
- 단순 폴더명과 의미 있는 서브 카테고리를 허용합니다. 밑줄 복합명은 비어 있지 않은 두 부분 `<상위>_<하위>`만 허용합니다. `react_hooks`는 허용하고 `react_hooks_effect`는 금지하며 추가 분류는 `react_hooks/effect/`로 표현합니다. 파일명에는 이 규칙을 적용하지 않습니다.
- writer는 생성·이동 전 대상 구조와 필요한 index.md를 포함한 결과 파일 수·깊이를 확인합니다. 상한 초과는 정리 사유이며 의미에 맞게 분류합니다. reader·researcher는 발견한 위반을 알리되 구조를 수정하거나 전역 감사를 시작하지 않습니다.

## 탐색과 문서 연결

- 루트는 위키 폴더의 `index.md`입니다. 각 인덱스는 영역의 목적·범위와 하위 주제·문서의 역할을 설명해 다음 읽을 대상을 안내합니다. 프로젝트 인덱스는 소유 기록 영역을 하향 안내합니다. 일반 문서·작업 기록의 본문 링크는 개념 이해·주장이나 관찰의 근거·선택과 배제 및 적용 조건의 판단에 필요할 때 사용합니다. 본문·출처 식별 정보로 충분하면 추가 위키 링크를 요구하지 않습니다. 같은 작업에서 작성·수정·조회했거나 같은 프로젝트에 속한다는 사실만으로 연결하지 않습니다. 관련 문서 절·편집 대상 목록·원래 작업 링크는 필수가 아닙니다. 양방향 필요성을 각각 판단하고 위치 복귀용 상위·루트 링크를 넣지 않습니다.
- 루트 인덱스에서 하위 주제와 문서로 실제 링크를 따라 도달할 수 있어야 합니다. 검증은 이 하향 도달성과 링크 대상 유효성을 확인하며 문서→루트 복귀나 양방향 링크는 검사 조건으로 삼지 않습니다. 상위 위치는 폴더 트리에서 확인합니다.
- 지식 조회는 인덱스로 관련 영역을 고른 뒤 그 영역의 링크·제한된 검색을 사용합니다. 인덱스 누락·불완전·선택 영역 미발견 시 필요한 범위만 넓힙니다. 정확한 문서 경로를 이미 알면 직접 읽고, 이 순서는 지식 조회에 적용하며 researcher·writer의 기존 자료 조회도 따릅니다. 충분한 제공 자료의 재조회는 요구하지 않습니다. writer의 승인된 이동·병합에서는 선택 root 안의 들어오는 참조를 별도로 탐색할 수 있고, 명시적 전체 정리·감사는 writer 또는 해당 승인 워크플로의 범위에서 검사합니다. reader·researcher의 일반 조회를 자발적인 전역 감사로 넓히지 않습니다.
- 관련 링크는 설명에 가장 정확한 문서를 가리킵니다. React 개요는 `Knowledge/React/index.md`, React 19 변경사항은 `Knowledge/React/19.md`를 가리킬 수 있습니다. 경로는 예시입니다.
- 위키 내부 탐색은 상대 Markdown 링크를 기본으로 합니다. 외부 출처 링크는 루트 연결 경로를 대신하지 않습니다.

## 기록 평가와 승인

- 이미 승인된 기록 범위에서는 새 근거·사용자 정보·결정·작업 결과가 생길 때 반영하며 매번 재승인하지 않습니다. 단순 설정 파일 존재를 쓰기 권한으로 간주하지 않습니다.
- 공통 지침은 웹 조사 후 평가 시점을, writer는 기록·갱신·생략 기준을 소유합니다. 다른 조사 도구나 스킬의 결과도 평가하며 researcher의 선행 실행을 요구하지 않습니다.
