# Agent Wiki Dev

작업에서 얻은 지식과 경험을 연결된 위키로 축적하고 다음 작업에 재사용합니다.
Rust CLI는 저장 위치·설치를, 세 스킬은 탐색·조사·문서 반영을 담당합니다.

개발 계약은 `specs/plugin.md`가 소유합니다. 배포본에는 개발 스펙과 테스트가 포함되지 않습니다.

## 스킬 선택

| 스킬 | 시작 조건 | 결과 |
| --- | --- | --- |
| `$agent-wiki-dev:reader` | 기존 지식·규칙·프로젝트 이력이 필요합니다 | 관련 문서, 적용 조건, 지식 공백 |
| `$agent-wiki-dev:researcher` | 현재 질문에 근거가 부족하거나 상충·최신성 확인이 필요합니다 | 출처·범위·불확실성을 포함한 조사 결과 |
| `$agent-wiki-dev:writer` | 조사 결과·사용자 정보·결정·작업 결과가 생깁니다 | 갱신된 문서와 연결, 영향 범위 정리 |

각 스킬은 단독 실행할 수 있습니다. 기존 문서로 충분하면 reader에서 끝내고, 제공된 근거가 충분하면 writer로 바로 반영합니다. 별도 서브에이전트나 세 스킬의 순차 호출은 필수가 아닙니다.

대표 요청:

- `$agent-wiki-dev:reader 프로젝트 A의 이전 결정과 현재 작업에 적용할 조건을 찾아주세요.`
- `$agent-wiki-dev:researcher 프로젝트 A 기록과 제공한 최신 자료의 차이를 확인해주세요.`
- `$agent-wiki-dev:writer 이 조사 결과와 작업 결정을 위키에 반영하고 관련 문서와 연결해주세요.`

## 과거 작업과 판단 복원

탐색 관계는 **작업 기록 > 판단별 근거 목록 > 자료 출처·요약**입니다. 근거 목록은 작업 문서 안에 두고 자료 요약은 여러 작업에서 공유할 수 있습니다. 고정 폴더나 세 개의 문서를 요구하지 않습니다.

- 작업 기록: 문제·목표·제약, 활용 지식, 검토한 대안과 선택·배제 이유, 주요 시도·실패·전환, 결과·검증·한계를 남깁니다.
- 판단별 근거: 무엇을 확인하려 했고 어떤 자료가 실제 판단에 어떻게 쓰였는지, 무엇이 미확인인지 연결합니다.
- 자료 요약: 질문에 필요한 내용, 원문 URL 또는 코드·실험 위치, 확인 날짜·버전·적용 조건·불확실성을 보존합니다.

원인 확인, 대안 선택·배제, 가설 기각, 유의미한 실패·방향 전환, 검증 결과가 나올 때 같은 작업 기록을 갱신합니다. 종료 시 누락된 사건과 출처를 확인합니다. 당시 사실과 후속 정정을 구분하고, 기록되지 않은 판단을 추측하지 않습니다.

`$agent-wiki-dev:reader 과거 로그인 세션 문제를 해결했던 내용을 블로그로 쓰려 합니다. 당시 제약, 참고 지식, 선택 이유, 시행착오와 검증을 관련 출처와 함께 정리해주세요.`

이 요청을 기록과 연결된 근거만으로 설명할 수 있는지가 완료 기준입니다. 없는 근거는 공백으로 알립니다.

## URL 조사 위임과 재사용

먼저 기존 위키의 관련 범위·출처·확인 날짜를 확인합니다. 충분하면 재사용하고 버전 변화·상충·근거 공백이 현재 판단에 영향을 줄 때 해당 부분만 재조회합니다.

독립적으로 분리 가능한 자료 확인은 위임이 허용된 경우 서브에이전트에 맡길 수 있습니다. 다음처럼 조사 목적과 기록 권한을 함께 전달합니다.

> 질문: 토큰 회전 환경에서 동시 갱신 요청이 실패하는 조건을 확인해주세요. 자료: 지정 URL 목록과 기존 위키 문서 경로. 필요한 정보: 적용 버전·동시 요청 조건·실패 동작. `$agent-wiki-dev:researcher`로 근거를 확인하고 `$agent-wiki-dev:writer`로 승인된 위키 루트와 문서 범위 안에 정리해주세요. 저장 문서 경로·핵심 발견·미해결 항목·저장 상태만 반환해주세요.

실제 위임 시 URL·경로·허용 쓰기 범위와 접근 가능한 스킬 경로 또는 식별자를 구체적으로 전달합니다. researcher는 읽기 전용이며, 저장은 writer 역할로 전환한 뒤 수행합니다. 같은 문서는 담당을 하나로 정하거나 쓰기를 직렬화합니다. 저장 실패와 조사 성공은 구분합니다.

메인은 반환된 문서의 필요한 부분과 판단 관련 출처를 확인하고, 실제 채택·배제와 이유를 작업 기록에 남깁니다. 자료 담당자는 메인의 판단을 추측하지 않습니다. 위임은 필수가 아니며, 반복 조회와 메인 문맥을 줄일 수 있지만 서브에이전트까지 포함한 총 토큰 절감을 보장하지 않습니다.

## 기록·연결·정리

위키 기록이 허용된 작업에서는 새 근거·사용자 정보·확정된 중간 결과를 자주 반영합니다. 이미 승인된 기록을 매번 다시 묻지는 않지만, 위치 설정만으로 쓰기 권한이 생기는 것은 아닙니다. 읽기 전용·기록 금지 요청과 상위 권한 제한을 따릅니다.

폴더·문서 템플릿은 고정하지 않습니다. 기존 관례를 따르고 빈 위키는 writer가 첫 작성 시 최소 `index.md`부터 만듭니다. CLI의 `set`은 문서를 만들지 않습니다.

`index.md`는 상위·하위 인덱스와 영역 진입 문서를 연결합니다. 일반 문서는 인덱스나 더 상세한 일반 문서에 자유롭게 연결합니다. React 개요는 `Knowledge/React/index.md`, React 19 변경사항은 `Knowledge/React/19.md`처럼 정확한 내용을 가진 대상을 가리킵니다. 경로는 예시입니다.

루트에서 모든 문서로, 각 문서에서 루트로 링크를 따라 도달해야 합니다. 일반 문서끼리의 중간 연결도 허용하며 각 문서에 직접 상위 인덱스 링크를 강제하지 않습니다. 작성할 때 주변을 정리하고 작업 종료 시 변경 범위를 점검합니다. 이동·병합은 기존 내용과 참조를 보존합니다.

설정·접근이 불가능하면 다른 폴더에 임의 기록하지 않고 본 작업과 위키 미반영 상태를 구분합니다. reader·researcher는 위키를 수정하지 않습니다.

## 웹 조사 결과 반영

웹 조사 후에는 기록 필요성을 항상 판단하며, 실제 기록은 다음 기준을 따릅니다.

- 새 사실·방법·제약, 비교·선택·배제의 근거, 기존 위키의 오류·누락·오래된 정보 정정은 기록합니다.
- 페이지 찾기·실패한 검색·내용 없는 탐색이나 추가 근거·조건이 없는 중복은 생략합니다.
- 날씨·가격·일정 같은 일시적 정보는 작업 결정의 근거일 때만 날짜와 함께 남깁니다.
- 기존 내용 재확인은 도움이 될 때 확인 시점·근거만 갱신합니다.
- 검색어나 방문 페이지별로 파일을 만들지 않고, 해결한 질문과 결과별로 출처·범위·확인 시점을 묶습니다.

writer는 다른 도구·스킬의 조사 결과도 받아 판단합니다. researcher 재실행은 필요하지 않으며 기존 기록 권한·읽기 전용·기록 금지 조건은 유지됩니다.

## 폴더 제한

- 폴더당 직접 파일은 `index.md`·첨부·숨김 파일을 포함해 최대 25개입니다. 하위 폴더와 ZIP 내부 항목은 합산하지 않습니다.
- 위키 루트는 깊이 0이며 최대 깊이는 4입니다. `wiki/A/B/C/D/document.md`까지 허용합니다.
- 단순 폴더명과 서브 카테고리는 자유롭게 정합니다. 밑줄 복합명은 `<상위>_<하위>` 두 부분까지만 사용합니다. `react_hooks`는 허용하고 `react_hooks_effect`는 사용하지 않습니다. 더 세분화하려면 `react_hooks/effect/`처럼 실제 폴더를 나눕니다. 파일명에는 적용하지 않습니다.
- writer는 생성·이동 전에 상한을 확인합니다. 초과하면 의미 있는 주제로 분류하되 무관한 내용을 합치거나 삭제하지 않습니다. reader·researcher는 발견한 위반만 알립니다.

## 설치

macOS·Linux용 Rust 단일 실행 파일입니다. 설치와 실행에는 Python이나 Rust 런타임이 필요하지 않습니다.
이 README가 있는 플러그인 폴더에서 실행합니다.

```sh
./scripts/agent-wiki install
```

`~/.local/bin/agent-wiki`에 현재 실행 파일 하나를 복사합니다. 원본 플러그인 폴더나 별도 라이브러리 파일에 의존하지 않습니다. 바이너리는 빌드한 OS·아키텍처에 맞춰 사용합니다.
동일한 파일은 그대로 유지하며, 다른 기존 파일을 교체하려면 내용을 확인한 뒤 `install --force`를 사용합니다. 심볼릭 링크와 디렉터리는 교체하지 않습니다.

소스 체크아웃에는 바이너리를 저장하지 않습니다. 바이너리가 없다면 Rust/Cargo를 준비하고 먼저 빌드합니다.

```sh
sh scripts/build.sh
./scripts/agent-wiki install
```

빌드 시 Cargo.lock에 고정된 의존성을 가져옵니다. 완성된 `scripts/agent-wiki` 파일만 복사해 다른 동일 플랫폼 환경에서도 설치할 수 있습니다.

`~/.local/bin`이 PATH에 없다면 셸 설정에 다음 내용을 추가합니다.

```sh
export PATH="$HOME/.local/bin:$PATH"
```

## 저장 위치 설정·조회

기존 위키 폴더를 지정합니다. 상대 경로와 `~`를 지원하며 절대 경로로 저장합니다.

```sh
agent-wiki set ~/Documents/Wiki
agent-wiki path
agent-wiki --help
```

설치는 아직 저장 위치를 정하지 않습니다. `set`을 실행할 때 `~/.agents/config.wiki.toml`을 생성하거나 갱신합니다.

```toml
root = "/Users/example/Documents/Wiki"
```

- `set`은 폴더가 없거나 파일이면 실패하며 기존 설정을 보존합니다.
- `path`는 설정되지 않았거나 저장 폴더가 사라졌다면 실패합니다.
- 설정은 최상위 `root` 문자열만 지원합니다. 잘못된 TOML이나 미지원 키가 있으면 덮어쓰지 않습니다. 주석과 서식은 설정 갱신 시 정규화합니다.
- 도움말과 조회는 파일을 생성하지 않습니다. 셸 설정과 위키 내용도 변경하지 않습니다.
