# Problem Decomposition

이 문서는 `pro-planner`의 넓은 제품/기능 요청 분해 판단을 소유합니다.

## 넓은 요청 처리

- "가계부 만들자", "예약 기능 추가하자"처럼 넓은 요청은 바로 화면, DB, 구현 순서로 고정하지 않습니다.
- 먼저 사용자가 원하는 결과, 제품 방식 후보, 주요 기능 영역, 정책/상태, 비목표를 분리합니다.
- 기능 목록은 사용자 목표와 제품 방식이 정해진 뒤에 작성합니다.

## 제품 방식 후보

- 같은 제품명이라도 운영 방식이 다르면 다른 제품입니다.
- 방식 후보는 사용자 행동, 기본 정책, 성공 기준, 필요한 기능, 주요 리스크가 달라지는 기준으로 나눕니다.
- 예: 가계부는 월간 한도 안에서 쓰는 방식과 모든 지출 기록을 모으는 방식이 다른 제품 판단을 요구합니다.

## 기능 영역 map

- 기능 영역은 사용자가 반복해서 인식하는 업무 단위나 화면 단위로 묶습니다.
- 각 영역에는 사용자 목표, 핵심 행동, 필요한 상태, 데이터, 예외, 다음 역할의 판단 포인트를 붙입니다.
- 기능 영역 map은 구현 작업 분해가 아니라 제품 구조와 handoff 기준을 잡기 위한 분해입니다.

## 분해 산출물

- `Product mode`: 선택지, 차이, 추천 또는 확인 질문
- `Feature map`: 영역, 사용자 목표, 핵심 행동, 필요한 상태
- `Requirement groups`: 기능, 정책, 상태, 데이터, 예외, 비목표
- `Supplemental planning surfaces`: 디자인 시스템 브리프, 정보 구조, 화면 inventory, 설정/운영/분석 표면
- `Handoff needs`: designer가 판단할 정보 구조와 tone, engineer가 판단할 데이터/상태/정책
