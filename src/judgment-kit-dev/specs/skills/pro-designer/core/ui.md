# UI Criteria

## 정의

UI는 사용자가 정보를 읽고, 구조를 이해하고, 가능한 행동을 판단하는 인터페이스 표면의 기준입니다.

## 기준

- 정보 구조: 중요한 정보, 자주 쓰는 행동, 위험한 행동, 상세 탐색 경로의 우선순위와 그룹이 분명해야 합니다.
- 레이아웃: 배치, 정렬, 밀도, 스캔 경로, 구분 방식, 관계 표현이 화면 목적과 정보 관계를 드러내야 합니다.
- 시각 위계: 표현을 정하기 전에 정보의 의미, 역할, 상태를 기준으로 위계 그룹을 정하고, 폰트 크기, 간격, 색, 타이포그래피 무게, 아이콘 크기, 이미지, 선, 표면 처리의 강도로 중요도와 행동 우선순위를 드러내야 합니다.
- 상태 표현: 기본, 선택, 비활성, 로딩, 오류, 성공, 빈 상태의 의미가 구분되어야 합니다.
- 컴포넌트 역할: 버튼, 링크, 입력, placeholder, 토글, 메뉴, 아이콘 버튼, 보조 라벨은 행동 성격과 정보 역할에 맞는 크기, 강조, 위치를 가져야 합니다.
- 일관성: 같은 위계, 역할, 상태의 요소는 같은 컴포넌트와 타이포그래피, 간격, 색, 아이콘, 표면 규칙을 사용해야 합니다. 차이는 실제 의미, 상호작용, 맥락의 차이를 전달하고 반복 가능한 규칙으로 설명될 때만 사용해야 합니다.
- 콘텐츠 적응: 긴 문구, 지역화, viewport 변화는 일부 요소만 다른 크기나 강조를 쓰는 일회성 보정보다 콘텐츠, 레이아웃, 공통 반응형 규칙으로 해결해야 합니다.
- 접근성: 대비, 가독성, 포커스, 터치 목표, 키보드 탐색 가능성이 유지되어야 합니다.
- Affordance: 아이콘, 라벨, 위치, 상태, 피드백은 행동 가능성, 행동 결과, 위험도를 예측할 수 있게 보여야 합니다.
- 데이터 표현: 차트, 표, 로그, 지표, 관계도는 축, 눈금, 라벨, 행, 열, 범례, 노드, 연결, 방향, 그룹이 먼저 읽혀야 합니다.
- 즉시 피드백: 버튼 클릭, 입력, 전환 같은 사용자 행동은 즉각적인 시각 반응을 줘야 합니다.
- 처리 상태: 지연되는 작업은 진행 중임을 드러내고 사용자가 기다릴 이유를 알 수 있어야 합니다.
- 결과 상태: 완료, 실패, 취소, 부분 성공은 다음 행동과 함께 구분되어야 합니다.
