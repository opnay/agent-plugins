# judgment-kit-dev v0.1.0 Change Spec

## 변경사항 요약

- `pro-planner`, `pro-engineering`, `pro-designer`를 `advance-codex-dev`에서 `judgment-kit-dev`로 이동한다.
- `judgment-kit-dev` manifest, README, plugin spec을 role-based judgment plugin 경계로 작성한다.
- `judgment-kit`의 공통 기준을 분야별 professional judgment flow로 정리한다.
- `pro-researcher`를 추가해 판단 전 research question, 근거, source quality, 불확실성, decision input을 정리한다.
- `pro-planner`를 넓은 제품/기능 요청의 문제 분해, 제품 방식 후보, 기능 영역 map 판단까지 다루도록 보강한다.
- `pro-planner`가 디자인 시스템 브리프, 정보 구조, 화면 inventory, 설정/운영/분석 같은 부가 기획 표면을 handoff 입력으로 다루도록 보강한다.
- `pro-quality-manager`를 추가해 테스트보다 넓은 품질 관리 관점의 quality target, coverage, release confidence, residual risk를 관리한다.
- `pro-code-keeper`를 추가해 가장 작고 안전한 코드 변경, 삭제, 재사용, standard library/native feature, dependency reduction, lean debt 기준을 제공한다.
- `pro-code-keeper` runtime을 router, references, examples 구조로 정리해 구현·리뷰·audit·root-cause fix·dependency check·refactor shrink·debt ledger 분기를 제공한다.
- `pro-designer`의 위계 일관성, 중첩 표면, 경계와 강조 기준을 보강한다.
- marketplace 등록과 release surface 생성을 통해 `judgment-kit`을 별도 플러그인으로 설치 가능하게 한다.

## 변경 목적

`v0.1.0`은 `pro-*` 시리즈를 Codex 운영/제작 도구 묶음인 `advance-codex`에서 분리해, 리서치·제품 기획·엔지니어링·코드 단순화·디자인·품질 관리 판단 기준만 소유하는 독립 플러그인으로 만드는 첫 버전입니다.

## 릴리즈 노트 기준

- 독자에게 보이는 변화: `judgment-kit` 플러그인이 새로 생기고 `pro-*` skill은 이 플러그인에서 제공된다.
- 호환성 영향: 기존 `$advance-codex:pro-*` 호출자는 `$judgment-kit:pro-*`로 옮겨야 한다.
- migration 필요 여부: pro 계열 skill 호출 prefix 변경이 필요하다.
- 운영자/사용자가 알아야 할 검증 결과: release surface에는 `specs/`가 없어야 하며, marketplace는 root `./judgment-kit`을 가리켜야 한다.

## 변경 상세

### Plugin Boundary

- 목적: 역할 기반 판단 skill을 독립적인 coherent bundle로 제공한다.
- 범위: research judgment, product planning judgment, engineering judgment, product design judgment, quality management judgment.
- 관련 표면: `README.md`, `specs/plugin.md`, `.codex-plugin/plugin.json`.
- 검증: manifest prompt와 README가 여섯 skill을 설명해야 한다.

### Skill Migration

- 목적: pro 계열 skill의 소유 플러그인을 `judgment-kit`으로 이동한다.
- 범위: `pro-researcher`, `pro-planner`, `pro-engineering`, `pro-designer`, `pro-quality-manager` runtime skill과 folder-based spec.
- 관련 표면: `skills/`, `specs/skills/`.
- 검증: `judgment-kit` dev/release surface에 다섯 skill이 존재하고, `advance-codex` dev/release surface에는 존재하지 않아야 한다.

### Pro Researcher

- 목적: 기획, 디자인, 엔지니어링, 품질 관리 판단 전에 불확실성을 줄이고 결정 가능한 근거를 만든다.
- 범위: research question, evidence, source quality, facts/assumptions, uncertainty, decision input.
- 관련 표면: `specs/skills/pro-researcher/`, `skills/pro-researcher/SKILL.md`, README, manifest prompt.
- 검증: runtime skill은 다음 역할의 결정을 직접 소유하지 않고 evidence와 uncertainty를 handoff 입력으로 정리해야 한다.

### Pro Planner Decomposition

- 목적: "가계부 만들자"처럼 넓은 요청을 바로 화면이나 구현으로 고정하지 않고 PO/PM 판단으로 분해한다.
- 범위: 문제, 제품 방식 후보, 기능 영역 map, 요구사항 그룹, designer/engineer handoff.
- 관련 표면: `specs/skills/pro-planner/`, `skills/pro-planner/SKILL.md`, README, manifest prompt.
- 검증: runtime skill은 실행 루프를 소유하지 않고 design/development 판단은 handoff로 넘겨야 한다.

### Pro Planner Supplemental Surfaces

- 목적: 넓은 제품 요청에서 core feature 외에 다음 역할이 필요로 하는 부가 기획 표면을 빠뜨리지 않는다.
- 범위: 디자인 시스템 브리프, 정보 구조, 화면 inventory, 설정, 온보딩, 알림, 데이터 관리, 분석, 운영 표면.
- 관련 표면: `specs/skills/pro-planner/`, `skills/pro-planner/SKILL.md`, README, manifest prompt.
- 검증: runtime skill은 디자인 시스템 결과물을 직접 결정하지 않고 designer handoff 입력으로만 정리해야 한다.

### Pro Quality Manager

- 목적: tester보다 넓은 quality manager 관점으로 산출물의 품질 관리와 release confidence를 판단한다.
- 범위: quality target, coverage gap, acceptance evidence, state coverage, severity, release confidence, residual risk.
- 관련 표면: `specs/skills/pro-quality-manager/`, `skills/pro-quality-manager/SKILL.md`, README, manifest prompt.
- 검증: runtime skill은 테스트 실행에만 좁아지지 않고 product, design, engineering 품질을 함께 점검해야 한다.

### Pro Code Keeper

- 목적: lean senior developer 관점으로 가장 작고 안전한 코드 변경과 불필요한 구조 축소를 판단한다.
- 범위: smallest safe change, root-cause fix, deletion, reuse, standard library/native feature, dependency reduction, overengineering review, refactor shrink, lean debt ledger.
- 관련 표면: `specs/skills/pro-code-keeper/`, `skills/pro-code-keeper/SKILL.md`, README, manifest prompt.
- 검증: runtime skill은 `SKILL.md`, `references/`, `examples/` 구조를 갖고, 문제 이해와 code-flow inspection을 줄이지 않으며, 보안·접근성·validation·명시 기능을 축소 대상으로 삼지 않아야 한다.

### Pro Designer Hierarchy and Surface

- 목적: 같은 위계의 요소가 불필요한 시각 차이로 경쟁하거나, 중첩 표면과 부분 border가 해석 비용을 높이는 문제를 줄인다.
- 범위: 의미·역할·상태 기반 위계 그룹, 반복 가능한 시각 규칙, 중첩 표면의 허용 조건, 외곽 경계와 부분 강조 indicator의 역할 분리.
- 관련 표면: `specs/skills/pro-designer/`, `skills/pro-designer/SKILL.md`.
- 검증: runtime skill은 같은 위계·역할·상태의 시각 규칙을 통일하고, 독립 역할 없는 중첩 표면과 의미 없는 한쪽 선 강조를 우선 선택하지 않아야 한다.

### Marketplace Registration

- 목적: `judgment-kit`을 별도 플러그인으로 설치 가능하게 한다.
- 범위: `.agents/plugins/marketplace.json`에 `judgment-kit` 항목을 추가한다.
- 관련 표면: marketplace entry.
- 검증: `source.path`가 `./judgment-kit`이고 `policy.installation`, `policy.authentication`, `category`를 포함해야 한다.

## 비목표

- `pro-*` skill을 일반 업무 workflow나 구현 대행 절차로 확장하지 않는다.
- `advance-codex`의 creator, scenario testing, commit, optimize-token 책임을 옮기지 않는다.
- commit, push, PR, publish는 이 change scope에 포함하지 않는다.

## 호환성 및 마이그레이션

- `$advance-codex:pro-planner` 대신 `$judgment-kit:pro-planner`를 사용한다.
- `$advance-codex:pro-engineering` 대신 `$judgment-kit:pro-engineering`을 사용한다.
- `$advance-codex:pro-designer` 대신 `$judgment-kit:pro-designer`를 사용한다.
- 새 research 판단에는 `$judgment-kit:pro-researcher`를 사용한다.
- 새 품질 관리 판단에는 `$judgment-kit:pro-quality-manager`를 사용한다.
- 작은 안전 변경, overengineering review, dependency reduction, lean debt tracking에는 `$judgment-kit:pro-code-keeper`를 사용한다.
