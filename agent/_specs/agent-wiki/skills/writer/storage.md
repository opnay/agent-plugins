# 저장·연결·검증

## 쓰기 계약

1. `agent-wiki list`·`agent-wiki path [name]`으로 root를 확인하고, CLI가 불가하면 TOML parser로 named roots 설정을 읽습니다. 미지원 설정은 변환하거나 대체 경로로 우회하지 않고 설정 갱신 필요와 미저장 상태를 알립니다. 경로·쓰기 범위를 확인하고 정확히 하나의 root를 고릅니다. 우선순위는 사용자 지정 root, 명확한 현재 작업 root, 이름·설명의 정확한 일치, 비민감하고 모호하지 않은 default입니다. 위치 지정은 권한 부여가 아닙니다.
2. 개인정보·서로 다른 공개 경계가 섞였거나 root가 모호하면 사용자에게 확인합니다. 더 엄격한 root에 둘지 문서를 나눌지는 추측하지 않으며, 자동 링크·복제·이동·병합하지 않습니다. root 사이 이동은 사용자가 출발 root·대상 root·범위를 명시한 경우에만 수행하고 cross-root Markdown 의존성을 만들지 않습니다.
3. 기존 인덱스·대상 문서·주변 연결을 선택 root 안에서 읽습니다. 충분한 제공 자료는 재조회하지 않고 정확한 문서 경로를 알면 직접 읽습니다. 기존 자료를 찾아야 하면 root·하위 인덱스로 영역을 고른 뒤 관련 링크·영역 내 검색을 사용합니다. 인덱스 누락·불완전·선택 영역 미발견 때만 필요한 범위로 넓힙니다. 입력이 충분하면 reader나 researcher를 재호출하지 않습니다. 명시적 전역 정리·감사는 승인된 범위에서 검사합니다.
4. [기억 분류 계약](memory.md#주제-소속과-문서-역할)으로 소유 위치·갱신·새 문서·분리를 판단합니다. 주제 폴더가 필요한 현재 내용은 허용된 작성 범위에서 즉시 구성하며 구체적인 문서명과 하위 인덱스를 맞춥니다. 지식에 작업 기록의 고정 경로나 전역 분야 목록·문서 템플릿을 강제하지 않습니다.
5. 첫 작성 시 선택 root의 index.md가 없으면 기존 파일을 살핀 뒤 최소 인덱스를 생성합니다. 빈 위키에는 불필요한 하위 폴더를 미리 만들지 않습니다.
6. 제목·적용 범위·출처 또는 사용자 제공 맥락·필요한 확인 시점·불확실성을 식별 가능하게 기록합니다. 일반 문서·작업 기록의 `type`·`tags`는 [메타데이터 계약](metadata.md)을 적용하며 본문 형식은 내용에 맞춥니다.
7. 현재 지식은 근거에 맞게 정정하며, 과거 결정·작업 기록은 당시의 의미를 보존합니다. 중요한 상충은 해소 근거 또는 미해결 상태를 남깁니다.
8. 선택 root 안의 연결 계약을 적용하고 저장 후 실제 내용과 링크를 확인합니다. 다른 root로 향하는 상대 Markdown 링크는 만들지 않습니다.

## Obsidian CLI로 어휘·저장 확인

- [Obsidian 조회 계약](../../obsidian.md)에 따라 선택 root와 확인된 vault를 연결하고 관련 문서의 properties에서 유형·태그 어휘를 확인합니다. 기존 메타데이터 병합·본문 보존 계약을 적용합니다.
- 승인된 파일 저장 후 properties·read 결과를 실제 파일의 type·tags·본문과 대조합니다. YAML 키 중복·자료형·의미 검증도 유지합니다. 인덱스 캐시 차이·CLI 오류가 있으면 저장 완료와 CLI 확인 상태를 분리하고 독립 파일 검증을 계속합니다.
- CLI 조회가 불가해도 같은 승인 root에서 raw 파일·YAML 검증을 수행합니다. 이 조회 연계로 CLI 쓰기·설정 변경 권한을 늘리지 않습니다.

## 본문 PR 참조

- 새로 작성하거나 수정하는 설명문에서 PR 참조는 종류와 번호를 붙인 `PR#150` 형식으로 쓰고 식별자 전체를 인라인 코드로 감쌉니다. 조사는 코드 밖에 둡니다. 예: `` `PR#150`은 참고로 남깁니다. ``
- 실제 URL을 알고 있으면 같은 식별자를 인라인 코드로 감싼 링크 표시명으로 사용하고 URL을 보존합니다. 예: `` [`PR#150`](https://github.com/opnay/blog-server/pull/150) ``. URL·번호·참조 종류를 추측하지 않습니다.
- 여러 저장소의 번호가 섞이면 `blog-server PR#150`처럼 저장소 식별을 포함한 전체 참조를 인라인 코드로 감싸 구분합니다.
- 원문 인용·코드 블록·URL·frontmatter·의도한 태그는 각각의 데이터 의미와 보존 지시를 따릅니다. 편집 권한 밖의 문서를 일괄 치환하지 않습니다. 저장 후 대상 설명문에서 종류·번호·코드 범위·조사 위치와 실제 링크 대상을 확인합니다.

## 연결·정리

- 생성·이동 전에 결과 구조를 확인합니다.
- 루트 깊이는 0이며 폴더 깊이는 최대 4입니다. 단순 이름·서브 카테고리는 자유롭게 정하되 밑줄 복합명은 비어 있지 않은 두 부분 `<상위>_<하위>`까지만 허용합니다. 세 부분 이상은 실제 하위 폴더로 표현하며 파일명은 이 규칙의 대상이 아닙니다.
- 깊이 5가 필요하면 먼저 기존 문서 갱신, 깊이 4 안의 의미 있는 분류, 기존 형제 영역 활용·해당 영역 재편을 검토합니다. 무관한 문서 병합·내용 삭제·번호만 다른 폴더로 제한을 맞추지 않습니다.
- 허용 범위 안에서 의미와 근거를 보존하며 재구성할 수 없으면 깊이 상한을 넘겨 쓰지 않고 미반영 내용과 필요한 결정을 알립니다. 기존 위반의 최초 정리는 명시된 정리 범위로 수행하고, 이후 일반 작업은 영향받는 영역만 점검합니다.
- index.md는 영역의 목적·범위와 하위 주제·문서의 역할을 설명하고 다음 읽을 대상을 top-down으로 안내합니다. 파일 목록을 계속 덧붙이는 문서로 만들지 않습니다. 일반 문서와 작업 기록의 본문 링크는 개념 이해, 주장·관찰의 근거 확인, 선택·배제·적용 조건의 판단에 필요할 때 사용합니다. 링크가 전달할 관계를 본문 문맥에서 알 수 있어야 하며 모든 링크에 별도 설명 필드를 강제하지 않습니다. 본문·출처 식별 정보로 충분하면 추가 위키 링크를 만들지 않습니다. 같은 작업의 작성·수정·조회 대상, 같은 프로젝트 소속, 원래 작업이라는 사실만으로 연결하지 않습니다. 링크는 해당 설명에 필요한 문서·절에 직접 연결하며 필요한 방향을 각각 판단합니다. 수정·조회했다는 사실만으로 편집 대상 목록이나 관련 문서 절을 만들지 않습니다. 인덱스의 하향 탐색 목록과 실제 출처·근거 목록은 유지합니다. 작업 기록 자체에 필요한 근거가 있으면 해당 문서나 절을 직접 참조할 수 있습니다.
- 전체 변경 목록은 사용자가 명시적으로 요청하거나 파일별 대응이 검증에 필수인 경우에만 제공합니다. 기존 diff·manifest 등으로 충분하면 재사용하고, 별도 자료가 필요한 경우에만 허용된 범위에 둡니다. 본문 목록을 피하려고 감사 파일을 자동 생성하지 않습니다.
- 루트 인덱스에서 하위 주제와 각 문서로 실제 링크를 따라 도달할 수 있어야 합니다. 검증은 하향 도달성과 링크 대상 유효성을 확인하며 문서→루트 복귀는 요구하지 않습니다. 일반 문서끼리만 순환하며 루트에서 찾을 수 없는 집합은 충분하지 않습니다.
- 상위 위치는 폴더 트리로 확인합니다. 인덱스·일반 문서에 위치 복귀만을 위한 상위·root 링크나 기계적인 상호 링크를 넣지 않습니다. 기존 링크 삭제는 사용자가 탐색 정리를 승인한 범위에서만 수행하며 일반 내용 수정에 덧붙이지 않습니다. 대상이 상위 index라는 이유만으로 삭제하지 않고 문맥상 위치 복귀용인지 판단해 관련 개념·근거·개요 참조를 보존합니다. 기존 위키 전체를 일괄 수정하지 않습니다.
- 작성할 때 주변 중복·참조를 정리하고 작업 종료 시 변경한 문서와 그 연결 범위를 점검합니다. 깊이 초과·중복·탐색 곤란·상이한 적용 범위가 드러나면 해당 영역만 병합·분리·인덱싱합니다.
- 분리·이름 변경·이동·병합은 선택 root 안에서 내용·출처·날짜·적용 조건·후속 정정·불확실성을 보존한 목적지를 먼저 준비하고 인덱스·들어오는 링크·상대 링크를 갱신합니다. 이름 변경·이동·병합의 이전 문서는 목적지와 영향 링크 확인 뒤에만 제거합니다. 분리 시 원본을 남길지 개요로 바꿀지는 역할에 맞춰 판단하고 중복 본문을 남기지 않습니다. root 사이 이동은 명시적 사용자 지시가 있을 때만 수행하며 cross-root Markdown 의존성을 만들지 않습니다. 참조 탐색은 선택 root 전체에서 할 수 있지만 수정은 영향 범위로 한정합니다.
- 여러 작업이 같은 파일을 갱신할 수 있으면 쓰기 직전 다시 확인하고 충돌 시 병합합니다. 진행 중인 변경을 덮어쓰지 않습니다.
- 기존의 무관한 고립 문서는 위치·문제를 알리고 현재 작업을 전체 재정리로 확대하지 않습니다. 전체 연결 검증을 하지 않았다면 전체 정상이라고 보고하지 않습니다.

## 완료·실패

- 작업 기록 저장이 막히면 작업 관찰을 같은 root의 지식 문서에 대신 쓰지 않고 미저장 내용·이유를 반환합니다. 독립적으로 승인된 새 지식은 기존 자료 기준을 충족할 때 별도 갱신할 수 있습니다. manager 또는 작업 담당자가 임시 초안과 작업/저장 상태를 관리합니다.
- writer는 내용의 충실성·근거·분류·링크·실제 저장을 검증합니다. 작업 담당자의 요청 충족·실행 완료 판정과 저장 완료를 구분하고 전달된 미충족·실패·보류·제외·검증 공백을 보존합니다.
- 위임 시 제공 질문·자료·쓰기 권한만 사용하고 채택 이유를 만들지 않습니다. 반환은 root·저장 경로·핵심 발견·미반영/미검증·상태 불일치·저장/검증 상태로 간결히 하며 상세 내용은 기록에 둡니다.
- 완료 기준: 새 독자가 제공된 문제·조건·판단·근거·결과·한계를 이해하고 기록된 상태와 writer가 실제 확인한 저장 범위를 구분할 수 있어야 합니다.
- 새 독립 문서·기존 본문 갱신·중복 생략을 구분하고 반영 내용·확인 범위·남은 문제를 전달합니다. 기존 내용이 충분해 변경이 없으면 그대로 알리며 신규 주제 조사·전체 완전성을 확인 범위 이상으로 주장하지 않습니다.
- 쓰기·검증이 실패하면 확인된 부분만 반영 완료로 구분합니다. 연결이 깨진 상태에서 이전 문서를 삭제하거나 정리 완료로 보고하지 않습니다.
- 설정·권한이 없으면 다른 폴더에 임의로 저장하지 않습니다. 가능한 본 작업은 계속하며 위키 미반영을 알립니다.

## 검증 범위

- 검증: 작성·정리 시 주제 소속과 문서 역할 판단, 현재 내용의 독립 본문 2개 이상이면 폴더 구성·분리, 단일 질문의 구체명 유지·혼합 주제의 소유별 분리, 신규 주제와 보충 구분, 이름·출처·날짜·정정·조건과 영향 참조 보존, 단독 메모의 기존 배치·정확 경로 권한 보존, 빈 구조·중복 방지, 의미상 배치 검증, 제공 상태·계층형 결과/근거 보존·조건 도출/재판정 불요·불일치/공백 반환·후속 정정·중단/실패 보존·프로젝트 소유 기록 저장·general 분류·프로젝트 기록만 갱신·미지원 배치/설정 보고·저장 불가 고지, 빈 위키 초기화, 기존 관례 보존, 상세 문서 직접 연결, top-down 도달성·링크 유효성·복귀 링크 불요·index 우선 조회, 필요한 의미 참조·수정 목록 기본 생성 불요·명시 요청/필수 파일별 검증 예외·감사 파일 자동 생성 불요·인덱스/근거 목록 보존·이력성 상호 참조 불요, 이동 참조 보존, 읽기 전용·경로 경계, 부분 실패 보고, 본문만으로 판단 맥락 이해, 선택적 재현, 임시 경로 비의존과 단기 복구 위치 구분.
