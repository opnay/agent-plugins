# advance-codex-dev v0.1.1 Change Spec

## 변경사항 요약

- session artifact guidance를 date-scoped `.agents/sessions/{YYYYMMDD}/` convention으로 정리한다.
- `session-manager`, `agents-sessions`, subagent runtime skill, `tool-use-guide`처럼 중복되거나 선택성이 낮은 runtime surface를 제거한다.
- `skill-scenario-testing`, `skill-creator`, `git-committer`, `plugin-creator`, `optimize-token`의 역할과 사용 표면을 정리한다.
- `notion-memory`를 Notion-backed agent work memory setup/capture skill로 추가한다.
- `notion-memory`의 page property 계약은 고정하고, body format은 기록 목적에 맞춰 작성 전 선택하는 자유 형식 계약으로 둔다.
- `optimize-token`은 과도한 압축으로 판단 맥락이 사라지지 않도록 `의미 맥락 보존` 축을 둔다.
- `pro-*` role judgment skill은 `judgment-kit`으로 분리하고 `advance-codex`에서는 제공하지 않는다.

## 변경 목적

`v0.1.1`은 `advance-codex`를 Codex surface 제작, 평가, agent work memory, 커밋, 토큰 최적화 중심 플러그인으로 좁히는 변경입니다.
role-based judgment는 `judgment-kit`이 소유합니다.

## 릴리즈 노트 기준

- 독자에게 보이는 변화: `advance-codex`는 creator, scenario testing, notion-memory, commit, optimize-token 중심으로 노출된다.
- 호환성 영향: 기존 `$advance-codex:pro-*` 호출자는 `$judgment-kit:pro-*`로 옮겨야 한다.
- migration 필요 여부: pro 계열 skill 호출 prefix 변경이 필요하다.
- 운영자/사용자가 알아야 할 검증 결과: release surface에는 `specs/`가 없어야 하며, manifest prompt는 실제 제공 skill만 언급해야 한다. `notion-memory`는 개인 Notion DB URL/ID를 plugin에 포함하지 않아야 한다.

## 변경 상세

### Session Surface 정리

- 목적: `advance-codex`에는 session artifact 위치에 대한 문서 수준 convention만 남긴다.
- 범위: README, plugin spec, manifest prompt.
- 관련 표면: `.agents/sessions/{YYYYMMDD}/` 설명.
- 검증: runtime skill source와 release surface에 `session-manager`와 `agents-sessions` runtime skill이 없어야 한다.

### Runtime Skill 제거

- 목적: `advance-codex`의 범위를 Codex surface 제작과 운영 품질 도구로 좁힌다.
- 범위: `session-manager`, `agents-sessions`, subagent runtime skill, `tool-use-guide` 제거.
- 관련 표면: `skills/`, `specs/skills/`, README, plugin spec, manifest prompt.
- 검증: dev/release surface와 manifest prompt에 제거된 skill 노출이 없어야 한다.

### Creator/Testing/Commit/Token Surface 정리

- 목적: 남는 skill의 시작 기준과 책임을 manifest, README, plugin spec에 맞춘다.
- 범위: `skill-creator`, `plugin-creator`, `skill-scenario-testing`, `git-committer`, `optimize-token`.
- 관련 표면: runtime skill, skill spec, plugin usage surface.
- 검증: 각 skill이 자기 spec과 runtime surface에 존재하고, dev-only spec 경로를 runtime 실행 지시로 남기지 않아야 한다.

### Notion Memory 통합

- 목적: Notion DB를 Codex 작업 메모리로 설정하고 작업 히스토리, 결정, 후속 작업, 검증, 재사용 가능한 작업 지식을 남기는 skill을 제공한다.
- 범위: `notion-memory` spec, runtime skill, setup command reference, memory contract reference, setup config script, README, plugin spec, manifest prompt.
- 관련 표면: `src/advance-codex-dev/specs/skills/notion-memory.md`, `src/advance-codex-dev/skills/notion-memory/`.
- 검증: setup command family, setup config script, allow-list/block-list, sectioned config path, memory document writing rules, schema/body/relation contract가 runtime에 포함되어야 하며, 개인 Notion DB URL/ID는 dev/release plugin 파일에 없어야 한다.
- body format: page property 이름, 타입, 허용 값, 의미는 고정 계약으로 유지하고, 본문 형식은 기본 템플릿 강제가 아니라 기록 작성 전 목적에 맞게 선택한다.

### Optimize Token 의미 맥락 보존

- 목적: `optimize-token`이 토큰을 줄이면서 원인/증거, 순서/의존성, 범위/비목표, 확인/미확인, source/evidence 구분 같은 판단 맥락을 지우지 않게 한다.
- 범위: `optimize-token` spec, runtime skill, `levels` reference, `writing` reference, README, manifest prompt.
- 관련 표면: `src/advance-codex-dev/specs/skills/optimize-token/`, `src/advance-codex-dev/skills/optimize-token/`.
- 검증: scenario testing에서 나온 context-loss 위험 축이 하나의 `의미 맥락 보존` 계약으로 반영되어야 한다.

### Role Judgment 분리

- 목적: product planning, engineering, design judgment를 `judgment-kit`의 coherent bundle로 분리한다.
- 범위: `pro-planner`, `pro-engineering`, `pro-designer` runtime skill과 folder-based spec을 `judgment-kit-dev`로 이동한다.
- 관련 표면: `src/judgment-kit-dev`, root `judgment-kit`, marketplace entry.
- 검증: `advance-codex` dev/release surface에 `pro-*` skill과 spec이 없어야 한다.

## 비목표

- flow record 생성/갱신 규칙을 복제하거나 재정의하지 않는다.
- 제거된 runtime skill 책임을 다른 sibling skill에 그대로 흡수하지 않는다.
- `advance-codex`를 일반 제품 구현 workflow나 역할 기반 판단 플러그인으로 넓히지 않는다.
- `notion-memory`를 일반 Notion workspace 자동화나 개인 DB config 배포 수단으로 넓히지 않는다.
- `judgment-kit`의 `pro-*` runtime 판단 계약을 이번 change spec에서 새로 설계하지 않는다.

## 호환성 및 마이그레이션

- `$advance-codex:pro-planner` 대신 `$judgment-kit:pro-planner`를 사용한다.
- `$advance-codex:pro-engineering` 대신 `$judgment-kit:pro-engineering`을 사용한다.
- `$advance-codex:pro-designer` 대신 `$judgment-kit:pro-designer`를 사용한다.
- `$advance-codex:notion-memory`는 새 skill이므로 기존 호출 migration은 없다.

- `src/advance-codex-dev/skills/` 아래에 `pro-*` skill이 없어야 한다.
- `src/advance-codex-dev/specs/skills/` 아래에 `pro-*` spec이 없어야 한다.

## 정식 규칙 승격 여부

- normative spec으로 승격할 지속 규칙: `advance-codex-dev/specs/plugin.md`가 Codex surface 제작/평가/agent work memory/커밋/토큰 최적화 중심 경계를 소유한다. `notion-memory` skill spec은 fixed page property contract와 free body format selection contract를 소유한다.
- change spec에만 남길 release/migration 이력: `pro-*` skill을 `judgment-kit`으로 분리한 호출 prefix 변경.
