# 기억 선택·분류·근거

## 기록 시점

- 조사 질문의 답·근거를 확보했을 때, 사용자가 사실·선호·규칙을 알려줬을 때, 실패 원인·해결 조건을 확인했을 때, 결정·작업 결과가 확정됐을 때 기록합니다. 웹 조사 결과는 아래 기록 기준을 적용합니다.
- 먼 미래의 재사용 가능성이 높아야만 기록하는 필터를 두지 않습니다. 긴 작업에서는 확정된 중간 결과마다 반영합니다.
- 동일 정보는 중복 기록하지 않고 기존 문서로 연결합니다. 검색·도구 호출별 원시 로그, 비공개 추론 과정, 불필요한 비밀값은 기록하지 않습니다.
- 가설·계획은 사실이나 완료 결과로 쓰지 않습니다. 사용자가 기록 금지·읽기 전용을 지정하면 반영하지 않습니다.

## 웹 조사 기록 기준

- 웹 조사 후 항상 기존 위키와 비교해 기록·갱신·생략을 판단합니다. 웹검색 외의 사용자 정보·작업 기록 조건은 유지합니다.
- 새 사실·방법·제약, 비교·선택·배제의 결정 근거, 기존 위키의 오류·누락·오래된 정보 정정이면 기록합니다. 실제 근거를 확인한 결과만 사실로 쓰고 나머지는 미확인으로 구분합니다.
- 페이지 위치 찾기·실패한 검색·내용 없는 탐색만 했거나, 기존 위키와 같은 정보에 추가할 근거·조건도 없으면 생략합니다.
- 검색 과정에서 불확실성이 생겼다는 사실만으로 기록하지 않습니다. 알려진 제약이나 실패 원인이 작업에 영향을 준다는 근거를 확보했다면 새 지식으로 평가합니다.
- 날씨·가격·일정 등 일시적 정보는 작업 결정의 근거일 때만 날짜·적용 범위와 함께 기록합니다.
- 기존 설명을 재확인한 경우 확인 시점·근거의 갱신이 현재 판단에 도움이 될 때만 해당 부분을 갱신하고 중복 문서를 만들지 않습니다.
- 검색어·방문 페이지가 아닌 해결한 질문과 결과를 단위로 묶고 출처·범위·확인 시점을 보존합니다. 같은 질문을 위한 여러 조회를 개별 기록으로 늘리지 않습니다.
- 충분한 기존 조사 결과를 받아 바로 판단할 수 있으며 researcher 선행 실행이나 재검색은 요구하지 않습니다. 기록 판정은 쓰기 권한을 확대하지 않습니다.

## 주제 소속과 문서 역할

- 승인된 작성·정리마다 소유 주제·적용 범위와 개요·버전 전환·재사용 패턴·개별 사례·작업 기록 역할을 판단합니다. 관련 기존 내용에서 지식의 분산·주제 혼합을 확인하며 깊이 상한 준수만으로 배치 적합성을 인정하지 않습니다.
- 재사용할 개념·방법·사례는 Knowledge의 소유 주제에, 특정 프로젝트에만 적용되는 설계·정책·현재 상태는 해당 Projects 영역에 둡니다. 프로젝트에서 얻었다는 이유만으로 재사용 지식을 프로젝트에 가두지 않으며 사례의 조건을 다른 프로젝트의 규칙으로 확대하지 않습니다. 작업 기록의 위치는 [기록 계약](records.md)이 소유합니다.
- 분야에서 하위 주제로 내려가되 계층 수·분야 목록을 고정하지 않습니다. `Knowledge/agents/skills/`, `Knowledge/software/database/`, `Knowledge/design/tools/`는 예시입니다. 개요·버전·패턴·사례는 문서 역할이며 모든 주제에 같은 폴더 세트를 강제하지 않습니다. 본문은 주 소유 위치 하나에 두고 다른 영역에서는 필요한 인덱스·본문 링크로 안내합니다.

### 갱신·신규 문서·분리

| 내용 판단 | 처리 |
| --- | --- |
| 기존 문서와 같은 질문·적용 범위 | 기존 문서를 갱신합니다. |
| 별도로 찾을 질문·버전·사례·적용 범위 | 중복을 확인한 뒤 구체적인 이름의 독립 문서를 만듭니다. |
| 같은 주제의 현재 내용이 독립 본문 2개 이상으로 분리 가능 | 즉시 주제 폴더를 구성하고 내용을 분리합니다. |
| 서로 다른 소유 주제가 섞임 | 각 소유 주제로 나눕니다. 한 도구에서 다뤘다는 이유로 같은 주제에 묶지 않습니다. |

- 2개는 실제 내용으로 설명할 독립 본문 수이며 index.md는 제외합니다. 현재 파일 하나와 새 자료에서도 판단하며 기존 파일 2개가 쌓일 때까지 기다리지 않습니다. 미래 가능성만으로 빈 폴더·문서를 만들거나 수를 맞추려고 API·절별로 기계적으로 나누지 않습니다.
- 독립 질문 하나면 적절한 기존 영역의 구체명 문서로 유지합니다. 새 폴더 생성 기준만으로 기존 단일 자식 폴더를 자동 해체하거나 정확 경로 지시를 변경하지 않습니다. 깊이 상한과 허용된 재편 범위는 [저장 계약](storage.md)을 따릅니다.
- 신규 지식 발굴·누락 정리 요청에서는 제공 자료와 승인된 조회 범위를 기존 지식과 대조해 독립 주제 후보를 확인합니다. 기존 본문 보충만 수행하고 신규 주제까지 점검했다고 보고하지 않습니다. 새 문서·기존 갱신·중복 생략과 미확인 범위를 실제 결과로 구분하며 불필요한 문서를 만들지 않습니다.

### 이름과 소유 범위

- 폴더는 주제, 일반 파일명·제목은 설명하는 질문과 범위를 드러냅니다. index.md는 해당 주제의 개요·실제 하위 문서 안내를 소유합니다. 도구 전체 개요가 아닌 특정 사용법에 `figma.md`처럼 포괄적인 이름을 붙이지 않습니다.
- 예: 좌표·레이아웃 해석 하나만 다루면 `design/tools/figma-coordinates-and-layout.md`, 같은 Figma 주제의 독립 본문 둘 이상이면 `design/tools/figma/coordinates-and-layout.md`와 구체 이름의 sibling 문서로 둡니다. 경로·철자는 기존 관례에 맞추며 실제 내용이 없는 예시 문서를 만들지 않습니다.
- Figma 좌표 해석과 일반 목록·상세 split view 설계는 다른 소유 주제입니다. 후자를 Figma 두 번째 문서로 세지 않고 디자인 패턴의 실제 소유 영역으로 분리합니다.
- 기존 관례·내용을 보존하되 평면 배치라는 이유만으로 소유 판단을 생략하지 않습니다. 로컬 분류·참조 갱신은 승인 범위에서 수행합니다. 정확한 파일만 수정하라는 요청은 다른 문서 이동 권한이 아닙니다. 범위 밖 재편·root 경계 변경은 허용된 부분을 완료하고 남은 문제를 알리며 전역 재편으로 넓히지 않습니다.
- 저장 후 주제 소속·역할·적용 범위, 이름의 정확성, 분리 가능한 내용의 누적·혼합, 불필요한 분산·빈 구조·중복과 index의 실제 하위 안내를 확인합니다. 링크·상한 검사는 의미상 분류 검증을 대신하지 않습니다. 범위 밖 배치 문제와 미확인 범위를 알리고 부분 검사로 위키 전체 정상이라고 보고하지 않습니다.

## 기억과 근거 연결

- 작업 기록은 해결한 질문·발견·판단·결과·검증 한계를 본문에 설명합니다. 수정·조회한 파일 목록으로 내용을 대신하지 않습니다. 참조 선택과 전체 목록의 예외는 [본문 연결 계약](storage.md#연결정리)을 따릅니다.
- 작업 기록은 판단 질문·근거·출처를 설명합니다. 전달된 체크리스트와 근거를 보존하며 근거 목록·자료 요약은 본문에 둘 수 있습니다. 필요한 외부 자료만 연결하고 고정 링크 사슬이나 세 파일을 요구하지 않습니다.
- 제목·범위·확인 시점·출처와 불확실성을 식별하고 목표·배경·제약·제외·활용 지식·선택과 배제 이유·주요 시도·실패·전환·결과·검증·미해결 한계를 제공 근거 범위에서 연결합니다. 해당하지 않는 항목은 억지로 채우지 않습니다.
- 판단 근거에는 질문, 실제 확인한 자료의 출처 식별 정보와 필요한 링크, 선택에 어떻게 쓰였는지, 미확인 항목을 남깁니다. 요약은 질문 관련 발견·원문 URL 또는 저장소/실행 출처·확인 날짜·버전·적용 조건·불확실성을 보존합니다.
- 당시 사실·제공된 상태와 후속 정정·writer의 확인 범위를 구분합니다. 채택 이유·비공개 추론·원시 도구 로그·불필요한 비밀을 만들거나 저장하지 않습니다.
- 일반화한 지식·사용자 정보는 기존 소유 주제에서 갱신하고 적용 조건·출처를 보존합니다. 원래 작업 링크는 [저장·연결 계약](storage.md)의 본문 연결 기준을 충족할 때만 사용합니다. 공유 요약을 복제하지 않으며 새 지식이 없어도 전달된 승인 작업 기록은 보존할 수 있습니다. 자료 생략 판단과 제공 작업 기록 저장 여부는 별개입니다.

## 근거의 지속성과 재현 범위

- 기록 자체에 확인한 사실·관찰 결과, 판단 이유, 중요한 조건·시점·버전, 한계가 있어야 합니다. 링크나 실행 경로만으로 내용을 대신하지 않습니다.
- 위키의 기본 완료 기준은 지식과 판단 맥락의 이해입니다. 모든 실험의 재실행·원시 로그·재현 스크립트·전체 산출물 보존을 요구하지 않습니다. 사용자가 재현을 요청했거나 결과를 활용하려면 재실행이 필요한 경우에만 필요한 자료의 범위와 보존 권한을 확인합니다.
- `/tmp`, `/private/tmp`, 임시 worktree·scratchpad 같은 소멸 가능한 작업 위치는 지속적인 근거 출처로 사용하지 않습니다. 필요한 관찰과 결론은 본문에 요약하고, 원본 추적이 필요하면 실제로 확인한 원문 URL·저장소 커밋과 파일 위치·같은 root의 보존 자료를 사용합니다. 안정적인 원본이 없으면 관찰 당시 결과와 독립 재확인 한계를 명시합니다.
- 임시 경로는 단기 복구·인계에 필요한 경우에만 작업 위치로 구분하고 임시성·용도를 밝힙니다. 영구 보존·현재 접근 가능·원시 자료 독립 검증을 암시하지 않습니다. 근거 경로로 남기기 위해 원시 로그·산출물을 자동 복제하거나 다른 root로 옮기지 않습니다.
- 기존 기록의 임시 경로를 고칠 때 확인된 요약·조건·한계는 보존합니다. 확인하지 않은 영구 경로를 만들거나 자료를 읽지 않고 근거를 검증했다고 쓰지 않습니다.
