# Thinking Intent Scenarios

작업 전 판단 문장과 진행 보고에 `light`, `standard`, `extreme` 차이를 적용하는 예시입니다.
사용자 의도, 다음 행동, 검증 필요성, 승인 경계, 실제 불확실성은 어떤 단계에서도 유지합니다.
내부 추론 공개를 요구하지 않습니다.

| 시나리오 | Before | light | standard | extreme |
| --- | --- | --- | --- | --- |
| 설명 후 확인 | `사용자가 설명을 원하는 것 같습니다. 자세한 답변을 제공한 후 구현해 볼 의향이 있는지 물어볼 수 있습니다.` | `사용자가 설명을 원하므로, 답변 후 구현 의향을 확인합니다.` | `설명 후 구현 의향을 확인합니다.` | `다음: 설명 후 구현 여부 확인.` |
| 파일 확인 | `이 작업은 파일을 수정해야 할 가능성이 있어 보이므로 먼저 관련 파일을 확인하는 것이 좋겠습니다.` | `파일 수정 가능성이 있으므로 관련 파일을 먼저 확인합니다.` | `관련 파일을 먼저 확인합니다.` | `다음: 파일 확인.` |
| 검증 필요 | `변경이 끝나면 문제가 해결됐는지 확인하기 위해 테스트를 실행하는 방향이 적절해 보입니다.` | `변경 후 테스트로 해결 여부를 확인합니다.` | `테스트로 해결 여부를 확인합니다.` | `검증: 테스트.` |
| 불확실성 | `이 실패가 sandbox 때문인지 코드 문제인지는 아직 확실하지 않으므로, 로그와 재현 조건을 먼저 확인해야 할 것 같습니다.` | `sandbox 문제인지 코드 문제인지 불확실하므로, 로그와 재현 조건을 먼저 확인합니다.` | `원인이 불확실해 로그와 재현 조건을 확인합니다.` | `불확실: sandbox/code. 다음: 로그, 재현 조건 확인.` |
| 승인 경계 | `이 명령은 외부 네트워크 접근이 필요할 수 있으므로, 실패하면 승인을 요청해서 다시 실행해야 할 수 있습니다.` | `외부 네트워크 접근이 필요할 수 있으므로, 실패하면 승인 후 재실행합니다.` | `네트워크 문제로 실패하면 승인 후 재실행합니다.` | `승인 경계: 네트워크 실패 시 재실행 승인 필요.` |
| 과압축 실패 | `검증은 아직 실행하지 않았고, 변경 범위가 넓어 회귀 위험이 남아 있습니다.` | `검증은 아직 실행하지 않았고, 넓은 변경 범위로 회귀 위험이 남아 있습니다.` | `미검증이며 회귀 위험이 남아 있습니다.` | `상태: 미검증. 위험: 회귀 가능.` |
| 사용자 정정 | `제가 사용자의 의도를 잘못 이해한 것 같습니다. 이전 답변의 방향을 수정해서 다시 설명해야 할 것 같습니다.` | `이전 해석을 수정하고, 사용자의 의도에 맞춰 다시 설명합니다.` | `해석을 수정해 다시 설명합니다.` | `다음: 해석 수정 후 재설명.` |
| 범위 제한 | `이 변경과 직접 관련 없는 파일은 건드리지 않는 편이 좋겠습니다. 현재 요청 범위에 포함된 파일만 확인하고 수정해야 할 것 같습니다.` | `관련 없는 파일은 제외하고, 요청 범위의 파일만 확인하고 수정합니다.` | `요청 범위 파일만 확인하고 수정합니다.` | `범위: 요청 파일만.` |
| 질문 라우팅 | `이 경우에는 사용자의 선택에 따라 구현 방향이 달라질 수 있으므로, 먼저 어떤 방향을 원하는지 물어보는 것이 좋을 수 있습니다.` | `구현 방향이 사용자 선택에 따라 달라지므로, 먼저 방향을 확인합니다.` | `사용자 선택이 필요해 방향을 확인합니다.` | `질문: 구현 방향 확인.` |
