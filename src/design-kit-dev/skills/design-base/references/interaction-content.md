# Interaction, Content, and Time

## Goal and Flow

Connect entry, understanding, choice, action, feedback, completion, return, and recovery. Account for user skill, task frequency, environment, risk, and existing policy.

- Make location, available content, detail entry, and return paths discoverable.
- Keep the information needed for decisions visible at the point of choice. Reduce unnecessary recall and guessing without hiding useful comparisons.
- Make labels, icons, placement, surface, and state suggest available actions and their consequences.
- Support a learnable first use and efficient repeat use. More confirmation is not always better; fit friction to actual consequence and reversibility.

## States and Feedback

Give actions an immediate response, delayed work a truthful processing state, and outcomes a clear next step.

Cover relevant default, loading, empty, error, disabled, permission, success, partial success, cancellation, interruption, and saving states. Show what happened, what remains, and what the user can do.

- Make input, save, submit, select, cancel, undo, and retry behave consistently.
- Preserve context and entered work through recoverable failures when the product supports it. Identify missing policy rather than inventing persistence or undo guarantees.
- Expose cost, permissions, saved state, impact, and irreversible effects when users need them to act confidently.
- Keep focus, keyboard operation, reading order, target size, and assistive technology support usable across state transitions.

## Interface Language

Use page and section titles, group names, labels, and terminology to make meaning and differences clear. Explain internal or domain language when the audience needs it.

- CTA copy should reveal intent and expected result.
- Guidance should arrive where it helps. Omit redundant visible copy only while the necessary context remains available.
- Error copy should state the known problem and recovery path. Do not invent a cause that the system does not establish.
- Status copy should reflect real progress, results, and limits. Differentiate completed, failed, cancelled, and partially completed work.
- Empty states should explain the absence and available next action.
- Risk copy should communicate consequences and actual reversibility.
- Use one term for one concept within its scope; exposure frequency is a separate decision. Restore labels or units when scrolling, standalone presentation, or assistive use removes context.
- Fit voice to the user's situation and emotional state while preserving brand recognition and inclusive, unambiguous language.

## Motion and Perceived Time

Use timing, sequence, easing, and spatial continuity to explain change, direction, hierarchy, feedback, or a deliberate expressive rhythm.

- Keep animation from delaying frequent work or obscuring results.
- Avoid suggesting progress, saving, or completion that the system has not established.
- Provide an understandable reduced-motion presentation and preserve focus and state meaning without animation.
- Inspect transitions with realistic latency, interruption, and content changes when relevant. Static screenshots cannot verify these behaviors.

## Verification

Test the affected task path and states when an interactive artifact is available. A proposal, prototype, and functioning implementation provide different evidence. State what was observed and what remains a design assumption.
