## 사용자 스펙 의도

- 문서 작성도 범위에 포함하고, 응답·문서·생각에서 나오는 말투와 스타일 전반에 token-efficient style을 적용하고 싶다.
- 답변을 사후 압축하는 도구가 아니라 agent가 자연어를 생성할 때부터 토큰 최적화된 문체를 사용하게 하고 싶다.
- reasoning의 표현은 간결하게 만들되 reasoning logic, 판단 깊이, workflow 자체를 줄이는 기능으로 넓히고 싶지 않다.
- 관계를 자연어로 반복하지 않고 제한된 symbol grammar로 표현하고 싶다.
- `:`는 항목과 값·상태, `>`는 계층·절차·상태 전이·우선순위처럼 방향이 있는 순서 관계, `·`는 같은 상태를 공유하는 병렬 항목에 사용하고 싶다.
- `>`는 뎁스와 순서를 나누지 않고 하나의 ordered relation으로 사용하고 싶다.
- 숫자 비교와 Markdown 문법은 문맥으로 구분되므로 `>`에 별도 금지 조건을 두지 않고, 요소 사이의 관계가 문맥상 명확한지만 판단하고 싶다.
- 기존 optimize-token 본문을 이어 쓰거나 부분 수정하지 않고, 이 사용자 의도만 기준으로 새 skill을 작성하고 싶다.
