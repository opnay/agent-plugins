# 작업 기록·상태 보존

## 전달된 작업 기록과 상태 보존

- 입력은 manager에 한정하지 않습니다. 사용자·작업 담당자·다른 도구가 제공한 지식·사실·결정·자료·작업 초안에서 시작하며 manager 실행이나 체크리스트를 모든 기억 작성의 선행 조건으로 요구하지 않습니다.
- 작업 기록은 제공된 하나의 의도·식별 정보와 기존 기록을 대조합니다. 기존·신규 기록 모두 아래 프로젝트 소유 계약으로 저장합니다. 같은 의도의 기록은 지원되는 위치에서 갱신합니다. 월별 경로·순번은 아래 기록 명명 계약을 따릅니다. 기존 이력 일괄 이동·변환은 별도 범위이며 정확 경로·읽기 전용·기록 금지를 우선합니다.
- manager 또는 작업 담당자가 도출·판정한 조건, 체크 상태, 하위 결과·근거·검증·선행·한계, 후속 변경·제외 이유를 의미 손실 없이 보존합니다. writer가 새 작업 조건을 만들거나 기존 조건·제외·충족 상태를 재판정하지 않습니다.
- 체크 상태와 근거가 맞지 않거나 정보가 부족하면 주장·관찰·불일치·공백을 구분해 기록하고 작업 담당자에게 반환합니다. 제공된 상태를 조용히 바꾸거나 근거 없는 충족을 writer의 확인 사실처럼 서술하지 않습니다. 기록 금지·원문 보존 경계를 지킵니다.
- 조건별 6줄 이내 결과·근거·한계 요약과 계층형 일반 목록, 독립 하위 조건의 체크 구조를 보존합니다. 긴 판단·자료는 별도 절·같은 root의 문서로 연결하되 상태·근거 관계를 잃지 않습니다. 근거가 부족하다고 당시 판단·준비·체크 상태를 추측하지 않습니다.
- 체크리스트가 없는 과거·사후 기록은 제공된 서술·상태·결과와 공백을 남깁니다. 이를 위해 조건을 역으로 만들거나 완료를 추론하지 않습니다. 조사·사용자 정보만 기록하는 작업에도 체크리스트 작성을 강제하지 않습니다.
- 지원되는 위치의 기존 기록은 조건·과거 근거·정정 이력을 보존하며 갱신합니다. 저장 직전에 재확인하고 파일별 쓰기 담당·직렬화를 유지합니다. 실패를 삭제·재생성으로 우회하지 않습니다.
- manager의 확정 중간 결과·실패·전환·중단·완료 초안 또는 직접 제공된 새 기억을 기록 시점으로 사용합니다. writer는 저장할 내용을 기존 문서와 대조하며 매 도구 호출을 복제하거나 작업 완료를 기다리지 않습니다.

## 프로젝트 소유와 기록 위치

- 선택 root 안의 모든 작업 기록은 하나의 프로젝트가 소유합니다. 사용자 지정 프로젝트·기존 프로젝트와 작업 맥락을 대조하고 `Projects/<project>/records/`에 저장합니다. 기존 프로젝트가 없으면 승인된 기록에 필요한 프로젝트와 최소 인덱스만 구성합니다.
- 특정 프로젝트에 속하지 않는 일반 작업은 같은 root의 `Projects/general/records/`에 둡니다. 소유가 불분명하면 관련 맥락을 먼저 확인하고 해결되지 않는 분류만 질문합니다. general은 불확실한 작업을 버리는 기본 분류가 아닙니다.
- 여러 프로젝트가 관련돼도 작업의 주된 책임 프로젝트 하나를 선택하고 복제하지 않습니다. 선택 근거가 없으면 분류를 확인합니다. root 공개·백업 경계와 정확 경로 지시는 프로젝트 분류보다 우선합니다.
- 후속 요청·재개는 프로젝트 소유 위치에서 같은 기록의 의도·조건·상태·정정 이력을 보존하며 갱신합니다. `Records/` 등 프로젝트 기록 영역 밖의 배치는 지원하지 않습니다. 미지원 위치를 발견하면 이관 필요와 미반영 내용을 알립니다. 이관 권한 없이 이전 위치 갱신·이동·복제·우회 저장을 하지 않습니다. 정확 경로 지시가 현재 계약과 충돌하면 충돌을 알리고 저장하지 않습니다.
- 기록 경로는 `Projects/<project>/records/YYYY-MM/000-<slug>.md`입니다. `YYYY-MM`은 최초 기록일의 연·월이며 `000`은 같은 프로젝트·월 안에서 000부터 증가하는 세 자리 순번입니다. 기존 최댓값 다음 번호를 사용합니다. slug는 내용을 구분하는 짧은 이름입니다. 예: `Projects/agent-plugins/records/2026-11/000-record-naming.md`.
- 같은 의도의 후속 요청·재개는 월이 바뀌어도 기존 월·순번·경로를 유지합니다. 저장 직전에 같은 월의 번호·대상을 다시 확인하고 충돌하면 다음 번호를 선택하며 기존 파일을 덮어쓰지 않습니다. 새 규칙과 다른 기존 기록의 일괄 이름 변경·이동은 별도 승인 범위입니다. 승인된 이관은 내용·들어오는 참조·상대 링크를 보존합니다.
- 프로젝트 인덱스 > records/index.md > YYYY-MM/index.md > 기록으로 하향 안내합니다. 인덱스는 실제 자식 역할을 설명하며 소유 계층 안내는 본문 관련 참조와 구분합니다. 프로젝트 인덱스에 기록별 목록을 중복하거나 추가 관련 프로젝트 링크를 둘 필요는 없습니다. 월 폴더는 root 0 기준 깊이 4이며 추가 하위 폴더를 만들지 않습니다.
