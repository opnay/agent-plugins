# Quality 0.1.0 검증 결과

2026-11-13에 현재 runtime의 구조·계약·Codex native 로딩과 대표 행동을 검증했습니다. 아래 결과는 관찰 기록이며 plugin의 실행 규칙은 [plugin 계약](plugin.md)과 [verify 계약](skills/verify/spec.md)이 소유합니다. 사례의 목적과 기준은 [검증 계획](validation-plan.md)을 따릅니다.

## 대상과 조건

- runtime: `agent/quality/skills/verify/SKILL.md`, SHA-256 `17096ecb68b3115f39fc12bad6ca49c13aeb0018dd9245f68d2712aaac5bed96`. 실험 중 변경하지 않았습니다.
- 호스트: codex-cli 0.167.2. 요청 모델은 `gpt-6-luna`, reasoning effort는 `max`입니다. 실제 응답과 도구 실행을 관찰했지만 이벤트에 모델 식별자가 없어 서버의 실행 모델은 독립 확인하지 못했습니다.
- 각 사용·미사용 실행은 새 HOME·CODEX_HOME·작업 폴더, 읽기 전용 sandbox, approval `never`, 사용자 설정 무시, ephemeral 세션으로 분리했습니다. 호스트 기본 system skill은 양쪽에 동일하게 노출됐습니다.
- 사용 조건만 고정된 verify 폴더를 임시 native skill 경로에 연결했습니다. 본문을 프롬프트에 삽입하지 않았습니다. 각 쌍의 요청·초기 fixture·제공 이미지는 동일하며 평가 기준은 실행 작업 폴더 밖에 뒀습니다.
- 기본 인증 파일은 임시 심링크로 연결했고 실행 후 제거했습니다. 인증 내용·사용자 설치·설정은 변경하지 않았습니다. Q07-live의 소유자 변경 외에는 fixture 변경이 없었습니다.

## 구조와 독립 검토

canonical skill validator, manifest JSON·공통 metadata, 단일 skill 경로, 호출 예시, 문서 링크, marketplace 이름·순서·실제 경로, diff 공백 검사를 통과했습니다. 두 marketplace는 기존 9개 항목을 보존하고 quality를 마지막에 추가했습니다. 읽기 전용 독립 검토 2건에서 spec/runtime 정합성과 패키징·등록 정합성을 확인했습니다. 기존 `pro-quality-manager`와 다른 plugin runtime은 변경하지 않았습니다.

## 실제 plugin 설치 경로

새 격리 HOME에서 실제 quality 폴더와 해당 marketplace 항목을 복사한 단일 항목 fixture로 marketplace 등록·plugin 설치를 실행했습니다. 설치 cache의 version 0.1.0과 runtime hash가 원본과 일치했고, marketplace 필터 목록에서 installed/enabled를 확인했습니다. 설치된 상태의 `$quality:verify` 호출이 Q09를 범위 내 통과로 판단했습니다. 추가 명시적 본문 읽기 smoke에서는 실제 설치 cache의 SKILL.md 읽기와 독립 Decimal 계산을 관찰했습니다. 이 추가 smoke는 자동 선택 효과를 측정한 비교가 아닙니다.

무필터 `plugin list --json`은 45초 timeout이 발생했습니다. 재설치 없이 marketplace 필터 조회로 확인했습니다. 이 환경 오류를 산출물 결함이나 조회 성공으로 처리하지 않았습니다.
