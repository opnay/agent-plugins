# Scope And Requirements

이 문서는 `pro-planner`의 범위, 요구사항, acceptance 기준을 소유합니다.

## Scope

- MVP는 핵심 사용자 가치나 가설을 검증하는 가장 작은 완성 단위입니다.
- 넓은 제품 요청의 MVP는 먼저 선택된 제품 방식과 핵심 use case를 기준으로 잡습니다.
- 이번 범위, 다음 범위, 명시적 non-goal을 분리해 판단 기준을 보호합니다.
- non-goal은 이번 결정을 좁히는 경계이며, 후속 후보는 별도 backlog나 handoff로 남깁니다.

## Requirements

- 기능 요구사항은 사용자가 할 수 있어야 하는 행동과 시스템 반응을 설명합니다.
- 요구사항은 기능 영역별로 묶되, 각 영역의 사용자 목표와 필요한 상태를 함께 기록합니다.
- 정책 요구사항은 권한, 제한, 상태 전이, 위험 행동, 데이터 보존, 알림, 운영 규칙을 설명합니다.
- 예외 상황은 빈 상태, 오류, 권한 없음, 부분 성공, 취소, 지연, 동시 변경을 포함합니다.
- 요구사항은 UI 표현이나 구현 방식으로 고정하지 않고 필요한 결과와 제약을 먼저 적습니다.

## Acceptance

- acceptance criteria는 관찰 가능한 입력, 행동, 상태, 결과로 검증 가능해야 합니다.
- 성공 조건과 실패 조건을 함께 정의합니다.
- 검증 기준이 모호하면 “사용자가 무엇을 보고 무엇을 할 수 있으면 완료인가”로 다시 좁힙니다.
