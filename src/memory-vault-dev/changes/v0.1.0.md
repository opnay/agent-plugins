# memory-vault-dev v0.1.0 Change Spec

## 변경사항 요약

- `memory-vault-dev` 신규 dev 플러그인을 추가합니다.
- `manage-memory-vault` passive skill을 추가합니다.
- `memv.py` helper script로 지정 폴더 자체를 vault root로 삼아 기본 문서, 카테고리 `INDEX.md`, `AGENTS.md` 표식 섹션을 만듭니다.

## 변경 목적

사용자가 직접 관리할 폴더 위치를 지정하면 그 폴더 자체를 지식 저장소로 관리하고, 에이전트가 이를 계속 관리하도록 `AGENTS.md` 규칙을 추가할 수 있어야 합니다.

## 릴리즈 노트 기준

- 독자에게 보이는 변화: 새 `memory-vault` 플러그인과 `manage-memory-vault` skill을 사용할 수 있습니다.
- 호환성 영향: 신규 플러그인이므로 기존 호출자 migration은 없습니다.
- migration 필요 여부: 없음.
- 운영자/사용자가 알아야 할 검증 결과: manifest JSON, release build, helper script dry-run, script unit test를 검증합니다.

## 기록 근거

- 관련 커밋: `pending`
- 관련 세션 기록: `.agents/sessions/20260605/002-create-knowledge-repository-plugin.md`

## 변경 상세

### 신규 플러그인 표면

- 목적: folder-local 지식 저장소 생성과 관리 규칙을 하나의 bundle로 제공합니다.
- 범위: manifest, README, plugin spec, change spec.
- 관련 표면: `src/memory-vault-dev/.codex-plugin/plugin.json`, `README.md`, `specs/plugin.md`.
- 검증: JSON 파싱과 build output 확인.

### 신규 passive skill

- 목적: skill 이름 없이도 관련 요청에서 자동 선택되는 지식 저장소 관리 workflow를 제공합니다.
- 범위: skill spec, runtime `SKILL.md`, helper script.
- 관련 표면: `specs/skills/manage-memory-vault.md`, `skills/manage-memory-vault/SKILL.md`, `scripts/memv.py`.
- 검증: skill validation과 helper script dry-run.

## 비목표

- 외부 저장소 동기화.
- 프로젝트 지식 내용 자동 작성.
- 기존 문서 삭제 또는 `AGENTS.md` 전체 재작성.

## 호환성 및 마이그레이션

- 신규 플러그인이므로 migration은 없습니다.
- 대상 폴더에 기존 `AGENTS.md`가 있으면 표식 섹션만 추가 또는 갱신합니다.
- 대상 폴더 아래 별도 `memory-vault/` 하위 폴더는 만들지 않습니다.
- 카테고리는 1-2 depth 상대 경로로 제한합니다.

## 검증 기준

- `python3 -m json.tool src/memory-vault-dev/.codex-plugin/plugin.json`
- `python3 src/memory-vault-dev/scripts/memv.py <tmpdir> --category Programming/React --dry-run`
- `python3 -m unittest src/memory-vault-dev/scripts/tests/test_memv.py`
- `pnpm build:plugin memory-vault --force`
- release surface에 `specs/`와 `changes/`가 없어야 합니다.

## 정식 규칙 승격 여부

- normative spec 또는 runtime 문서로 승격할 지속 규칙: plugin boundary, passive trigger 계약, allowlist 파일 변경, 1-2 depth category indexing, `AGENTS.md` 표식 섹션.
- change spec에만 남길 release/migration 이력: 신규 플러그인 추가 이력과 검증 기준.
