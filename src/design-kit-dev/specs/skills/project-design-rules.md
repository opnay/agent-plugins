## 사용자 스펙 의도

- 디자인 기본 베이스 구조와 프로젝트 특성에 맞춘 전용 디자인 패턴 규칙을 쌓고 싶다.
- 패턴은 동일 문구의 맥락별 생략과 강조를 위한 반복, 동일 용어·색상·패턴의 반복을 포함해야 한다.

# project-design-rules 스킬 스펙

## 목적과 경계

- 프로젝트의 디자인 방향, 베이스, 전용 패턴을 탐색·기록·채택·재사용·갱신한다.
- 전문 역할의 결정을 지속 가능한 규칙으로 정리한다. 일반 이론과 프로젝트 결정값을 구분한다.
- 실제 프로젝트 규칙은 대상 프로젝트에 둔다. 플러그인·타 프로젝트·위키를 임의로 갱신하지 않는다.
- 대표 표면: `skills/project-design-rules/SKILL.md`, `references/project-context.md`, `templates/project-design.md`.

## 맥락 탐색 계약

- 대상 프로젝트와 요청의 읽기/쓰기 범위를 먼저 정한다.
- 프로젝트 지침, 기존 디자인 문서·브랜드 기준·토큰·컴포넌트·대표 화면을 좁게 확인한다. 여러 기록이 있으면 소유 문서와 상호 링크를 찾는다.
- 명시된 사용자 결정·채택 규칙과 관찰한 구현·가정을 구분한다. 구현의 우연한 반복을 채택 규칙으로 간주하지 않는다.
- 현재 적용 범위에 맞는 채택 규칙을 우선 사용한다. 문서·구현이 다르면 차이·영향을 보고하고, 근거 없이 한쪽을 덮어쓰지 않는다.
- 필요한 정보가 없으면 가정을 밝히고 작업을 진행한다. 범위를 크게 바꾸는 미정 결정만 확인한다.
- 모든 역할은 이 탐색 계약을 공유 reference로 읽는다. 규칙 관리 skill을 매번 선행 호출할 필요는 없다.

## 저장과 기록

- 기존 디자인 문서 위치와 형식을 우선한다. 새 기록 위치가 필요하고 기록이 요청 범위면 대상 프로젝트의 `docs/design.md`를 기본값으로 삼는다.
- 기존 동일 경로 파일을 통째로 대체하지 않는다. 큰 분할은 내용·검색 필요가 실제로 생겼을 때 수행한다.
- 방향: 사용자·목표·톤·브랜드·표현 우선순위와 근거.
- 베이스: 색 역할·타이포·간격·그리드·공간·표면·상태·모션 규칙. 기존 토큰과 연결하고 값을 임의 발명하지 않는다.
- 패턴: 상황·규칙·이유·예외·대표 사례·근거·상태. 필요한 경우 적용 맥락·반복 요소·유지할 의미/역할·생략/재제공/강조/변주 조건을 포함한다.
- 기록 상태는 candidate, adopted, deprecated로 구분한다. 사용자 확정 또는 기존에 채택된 근거가 있으면 adopted, 미확정 제안은 candidate다. 확인된 적용 결과는 evidence로 기록한다.
- 단일 화면의 실험·실수·일회성 보정을 전역 규칙으로 승격하지 않는다. 규칙은 프로젝트·화면군·컴포넌트·상태 등 실제 적용 범위를 갖는다.

## 재사용·갱신 계약

- 작업 시작 시 적용 규칙을 찾고 결과가 기존 규칙의 적용·확장·변경인지 판단한다.
- 후보는 채택 규칙과 구분해 제안·기록한다. 일반 UI 요청만으로 지속 문서 쓰기를 추론하지 않는다.
- 기록·수정이 요청 범위면 관련 항목만 갱신하고 이유·영향·대체 관계를 남긴다. 미정한 충돌은 병기하고 유효 규칙을 조용히 바꾸지 않는다.
- 폐기 규칙은 대체 규칙이나 폐기 이유를 연결한다. 무관한 과거 결정과 다른 프로젝트 규칙은 보존한다.
- 명시적 사용자 변경은 해당 범위의 규칙에 반영한다. 접근성·기능 의미와 충돌하면 문제를 드러내고 가능한 대안을 제시한다.

## 출력과 검토 질문

- 읽거나 쓴 정확한 위치, 적용·후보·변경 규칙, 근거·영향·미해결 충돌을 보고한다.
- 실제 저장하지 않았다면 제안이라고 표시한다. 다음 세션의 재발견은 소유 문서와 프로젝트의 기존 문서 탐색 경로로 지원한다.
- 규칙은 언제 적용되는가? 동일한 의미를 유지하면서 언제 생략·재제공·변주하는가? 채택 근거가 있는가?

## 독립성·확장

- 이 skill은 기록 관리에 독립 실행 가능하다. 디자인 판단 결과는 입력으로 받고 필요한 경우 `$design-kit-dev:design-base/references/repetition.md`를 읽는다.
- shared context reference와 template는 이 skill이 소유하며 다른 역할은 `$design-kit-dev:project-design-rules/<resource-path>`로 참조한다.
- 새 상태·저장소·자동화는 실제 관리 요구가 확인될 때 추가한다.
