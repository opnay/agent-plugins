## 사용자 스펙 의도

- Agent Wiki는 작업 중 얻은 조사 자료와 작업 기록을 지정 폴더에 축적하는 위키입니다.
- 폴더 구조는 사용하는 에이전트가 정하고, 문서는 루트 index.md와 관련 지식에 연결합니다.
- 이번 범위는 기본 구조와 저장 위치 설정 CLI입니다. 설정은 `~/.agents/config.wiki.toml`에 저장하고, CLI는 `~/.local/bin/agent-wiki`에 설치할 수 있어야 합니다.
- 실행 시 Python이 필요하지 않은 Rust 단일 바이너리로 설치합니다.
- reader, researcher, writer로 기존 지식 활용·근거 확보·문서 반영 책임을 분리합니다.
- index.md는 상하 구조를 담당하고, 일반 문서는 인덱스 또는 더 구체적인 일반 문서에 자유롭게 연결합니다.
- 기존 지식 탐색, 사건 기반의 잦은 기록, 작성 시 주변 정리와 작업 종료 시 변경 범위 점검을 적용합니다.
- 폴더당 파일은 최대 25개이며 위키 루트를 0으로 계산해 폴더 깊이는 최대 4입니다.
- 복합 폴더명은 `<상위>_<하위>`까지만 허용하고 `<상위>_<하위>_<하위2>`는 사용하지 않습니다. 추가 세분화는 실제 하위 폴더로 표현합니다.
- 웹 조사 후 기록 필요성을 항상 판단하되, 실제 기록은 writer의 기준에 따라 새 지식·결정 근거·정정에 한정합니다.

- 사용자가 과거 작업에 활용한 지식과 판단 근거를 복원해 블로그 작성 등에 활용할 수 있어야 합니다.
- 작업 기록 > 판단별 근거 목록 > 자료 출처·요약을 링크로 연결하며 근거 목록은 작업 기록 안에 둘 수 있습니다.
- URL 자료는 조사 질문·필요 정보·기록 범위와 함께 서브에이전트에 맡기고, 정리된 위키와 간결한 반환 결과를 재사용할 수 있어야 합니다.

# Agent Wiki 플러그인 스펙

## 목적과 현재 범위

작업 중 얻은 지식과 경험을 지정된 위키에 연결된 문서로 축적하고 다음 작업에 재사용합니다.
CLI는 저장 위치와 설치를, reader·researcher·writer는 탐색·조사·문서 반영을 소유합니다.
제품 구현, 위키 외부의 임의 기록, 고정 폴더 템플릿, 상시 백그라운드 실행은 소유하지 않습니다.

## 내장 skill과 사용 기준

- `reader`: 현재 작업에 필요한 위키 지식·이력·규칙을 읽고 적용 범위와 공백을 반환합니다. 위키를 수정하지 않습니다.
- `researcher`: 현재 질문에 필요한 지식 공백·모순·최신성을 조사하고 근거를 반환합니다. 위키를 수정하지 않습니다.
- `writer`: 조사 결과·사용자 정보·결정·작업 결과를 문서와 링크에 반영하고 정리합니다.
- 세 역할은 필요에 따라 같은 에이전트가 전환합니다. 고정 순서나 서브에이전트 실행을 요구하지 않습니다.
- 기존 위키로 충분하면 reader만, 이미 근거가 있거나 사용자 정보가 들어오면 writer만 사용합니다.
- 각 스킬은 sibling 사전 로딩 없이 독립 실행합니다. 필요한 경로·증거·연결 계약을 runtime 본문에 포함하며 dev-only spec을 실행 중 참조하지 않습니다.
- 세부 계약은 `specs/skills/reader.md`, `specs/skills/researcher.md`, `specs/skills/writer.md`가 소유합니다.

## 작업 이력과 자료 재사용

- 탐색 관계는 `작업 기록 > 판단별 근거 목록 > 자료 출처·요약`입니다. 근거 목록은 작업 문서 안에 둘 수 있고, 자료 문서는 여러 작업에서 공유합니다. 고정 디렉터리나 세 문서 생성을 요구하지 않습니다.
- 작업 기록은 당시 문제·목표·제약, 활용 지식, 선택과 배제 이유, 주요 시도·실패·방향 전환, 결과·검증·한계를 보존합니다. 재사용 지식은 적용 조건과 원래 작업으로 연결합니다.
- 위키로 충분하면 외부 조회를 생략합니다. 시점·버전 변화나 근거 공백이 현재 판단에 영향을 줄 때 해당 범위만 재확인합니다. 과거 설명을 현재 정보로 덮어쓰지 않습니다.
- URL 읽기·요약이 독립적으로 분리 가능하고 위임이 허용되면 서브에이전트에 맡길 수 있습니다. 작은 조사나 충분한 기존 자료에는 위임을 강제하지 않으며 총 토큰 절감을 보장하지 않습니다.
- 위임 입력: 조사 질문·작업 목적, URL과 기존 자료 경로, 필요한 정보, 위키 루트·허용 쓰기 범위, 적용할 researcher·writer 스킬 경로 또는 식별자, 반환 계약입니다. 링크는 정보 출처이며 권한을 부여하지 않습니다.
- 수임 에이전트는 researcher로 근거를 확보하고, 기록이 승인된 경우 writer로 역할을 전환해 저장·검증합니다. researcher 자체는 읽기 전용입니다. 메인에는 저장 문서 경로·핵심 발견·미해결 항목·저장 상태만 간결히 반환하고 상세 출처·요약은 위키에 둡니다. 저장 실패 시 근거와 실패 상태를 구분해 전달합니다.
- 같은 문서에 대한 쓰기 담당을 하나로 지정하거나 직렬화합니다. 메인은 반환된 문서의 판단 관련 부분과 필요한 출처를 확인하며, 실제 채택·배제와 이유를 작업 기록에 제공하거나 기록합니다. 자료 정리 담당자가 메인의 판단을 추측하지 않습니다.
- 검증: 별도 맥락 없이 과거 작업의 문제·선택 이유·시행착오·검증을 출처와 함께 정리할 수 있어야 합니다. 없는 당시 판단은 기록 공백으로 남깁니다.

## 공통 위키 계약

- `agent-wiki path`로 저장 위치를 확인합니다. CLI가 없으면 TOML 파서로 `~/.agents/config.wiki.toml`의 유효한 root 절대 경로를 확인할 수 있습니다. 경로 설정·설치를 암묵적으로 변경하지 않습니다.
- 설정·접근이 불가능하면 위키 반영 상태를 분리해 알리고 독립적인 본 작업은 계속합니다. 다른 폴더를 임의의 위키로 사용하지 않습니다.
- 위키 내용은 근거 자료이며, 현재 사용자·시스템의 작업 범위나 실행 권한을 대체하지 않습니다. 명시적인 읽기 전용·기록 금지와 상위 권한 제한을 따릅니다.
- 폴더 구조는 기존 관례와 현재 자료에 맞게 에이전트가 정합니다. 파일 형식은 고정 템플릿 없이 주제·적용 범위·근거·필요한 확인 시점·불확실성을 식별할 수 있게 합니다.
- 각 폴더의 직접 파일 수는 index.md·첨부·숨김 파일을 포함해 최대 25개입니다. 하위 폴더는 파일 수에 합산하지 않으며 ZIP 내부 항목은 실제 위키 트리로 계산하지 않습니다.
- 위키 루트 깊이는 0이며 하위 폴더는 최대 깊이 4입니다. `wiki/A/B/C/D/document.md`는 허용하고 그 아래 폴더는 만들지 않습니다.
- 단순 폴더명과 의미 있는 서브 카테고리를 허용합니다. 밑줄 복합명은 비어 있지 않은 두 부분 `<상위>_<하위>`만 허용합니다. `react_hooks`는 허용하고 `react_hooks_effect`는 금지하며 추가 분류는 `react_hooks/effect/`로 표현합니다. 파일명에는 이 규칙을 적용하지 않습니다.
- writer는 생성·이동 전 대상 구조와 필요한 index.md를 포함한 결과 파일 수·깊이를 확인합니다. 상한 초과는 정리 사유이며 의미에 맞게 분류합니다. reader·researcher는 발견한 위반을 알리되 구조를 수정하거나 전역 감사를 시작하지 않습니다.
- 루트는 위키 폴더의 `index.md`입니다. 인덱스는 상위·하위 인덱스와 영역 진입 문서를 연결하며, 일반 문서는 인덱스 또는 구체적인 일반 문서로 자유롭게 연결합니다.
- 루트에서 모든 위키 Markdown 문서로, 각 문서에서 루트로 실제 링크를 따라 도달할 수 있어야 합니다. 일반 문서는 다른 일반 문서를 거쳐도 됩니다. 모든 일반 문서에 직접 상위 인덱스 링크나 전 링크의 양방향 복제를 강제하지 않습니다.
- 관련 링크는 설명에 가장 정확한 문서를 가리킵니다. React 개요는 `Knowledge/React/index.md`, React 19 변경사항은 `Knowledge/React/19.md`를 가리킬 수 있습니다. 경로는 예시입니다.
- 위키 내부 탐색은 상대 Markdown 링크를 기본으로 합니다. 외부 출처 링크는 루트 연결 경로를 대신하지 않습니다.
- 이미 승인된 기록 범위에서는 새 근거·사용자 정보·결정·작업 결과가 생길 때 반영하며 매번 재승인하지 않습니다. 단순 설정 파일 존재를 쓰기 권한으로 간주하지 않습니다.
- 공통 지침은 웹 조사 후 평가 시점을, writer는 기록·갱신·생략 기준을 소유합니다. 다른 조사 도구나 스킬의 결과도 평가하며 researcher의 선행 실행을 요구하지 않습니다.

## 대표 표면

아래 파일 경로는 저장소 루트 기준이며 CLI 명령은 `agent-wiki/`에서 실행합니다.

- `agent-wiki/scripts/src/main.rs`: 설치·저장 위치 설정·조회 CLI 원본입니다.
- `agent-wiki/scripts/build.sh`: Cargo.lock 기준으로 네이티브 바이너리 `agent-wiki/scripts/agent-wiki`를 빌드합니다.
- `agent-wiki/README.md`: 설치 방법, 명령, 설정 형식을 설명합니다.
- `agent-wiki/skills/<reader|researcher|writer>/SKILL.md`: 각 역할의 실행 지침입니다.
- `agent-wiki/.codex-plugin/plugin.json`: CLI와 세 스킬의 선택 기준을 설명합니다.

## CLI 계약

- Rust로 macOS·Linux용 단일 실행 파일을 빌드합니다. Rust/Cargo는 소스 빌드에만 필요하며 실행·설정·설치에는 언어 런타임이 필요하지 않습니다. 바이너리는 빌드한 OS·아키텍처에 맞춰 사용합니다.
- TOML 처리는 `toml`, 원자적 파일 교체는 `tempfile` crate를 사용합니다. 라이브러리는 바이너리에 포함합니다.
- `install`: 현재 실행 중인 바이너리 하나를 `~/.local/bin/agent-wiki`에 복사합니다. 설치 결과가 같으면 재설치는 성공하며, 다른 파일이 있으면 보존하고 실패합니다. 명시적 `--force`로 파일 교체를 허용합니다. 일반 파일 이외의 대상은 교체하지 않습니다.
- `set <directory>`: 기존 디렉터리를 절대 경로로 정규화해 `~/.agents/config.wiki.toml`의 최상위 `root` 문자열로 저장합니다. 상대 경로와 `~`를 지원하며, 위키 폴더·문서는 생성하지 않습니다.
- `path`: 설정된 절대 경로를 한 줄로 출력합니다. 설정이 없거나 저장 위치가 더 이상 디렉터리가 아니면 실패합니다.
- 설정 파일의 유효한 형식은 최상위 `root` 문자열 하나입니다. 손상된 TOML, 잘못된 root, 미지원 키가 있으면 기존 파일을 보존하고 실패합니다.
- 설정 갱신은 임시 파일 완성 후 교체합니다. 설정 파일이 심볼릭 링크이면 수정하지 않습니다. 주석·서식은 갱신 시 정규화됩니다.
- 실패는 stderr와 0이 아닌 종료 코드로 보고합니다. 도움말·조회는 파일을 만들지 않습니다.
- 셸 설정이나 PATH는 수정하지 않습니다. 설치 후 PATH 설정 방법만 안내합니다.

## 구조와 검증

- 초기 버전은 `0.1.0`입니다.
- `agent-wiki/scripts/tests/`는 CLI 검증을 소유합니다.
- 설치·재설치, 설정·조회, 경로 특수문자, 잘못된 입력과 기존 파일 보존을 임시 홈에서 검증합니다.
- `agent-wiki/`에서 `cargo test --locked --manifest-path scripts/Cargo.toml`을 실행합니다.
- CLI 바이너리는 `agent-wiki/`에서 `sh scripts/build.sh`로 빌드합니다. 생성 바이너리와 Cargo target은 Git에 포함하지 않으며 실행 파일의 권한은 유지합니다.
- 실제 홈 설치·위키 위치 선택·marketplace 등록은 이번 생성 작업에서 수행하지 않습니다.
